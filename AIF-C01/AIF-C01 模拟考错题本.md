## 模拟考分数追踪

> **目标**：真实考试通过线是**缩放分数 700/1000**（约等于原始正确率 70%，但缩放算法并非严格线性）。65 题中有 **15 题不计分**且无法分辨是哪些，模拟题通常也比真实考试更刁钻，考场还有额外的时间压力和紧张情绪损耗——因此**模拟考正确率的目标应显著高于 70% 这条真实及格线**，建议稳定在 **80%~85% 以上**再考虑预约，不要以单次压线通过为准。

> **⚠️ 重要发现：Security, Compliance and Governance 这一栏具有误导性，不代表真实的安全/合规知识水平。** 平台按 Domain 汇总分数用的是**它自己的原始标注**，而本笔记在整理错题时发现这个 Domain 的标注经常出错。核对 4 次模拟考里所有被标为该 Domain 的**错题**（共 7 道：批次一 Q38/Q62、批次二 Q5/Q63、批次三 Q15/Q18、批次四 Q53），只有 **批次三 Q18（AWS Artifact/ISV 合规报告）1 道**是真正的安全合规内容——其余 6 道实际是翻译评估指标、提示工程语气调整、通用云计算基础、BI 工具选型、EC2 硬件选型等**被平台错误归类**的题目（详见各批次错题详解中的"原标注"标注）。也就是说，**这个 Domain 报告的 74% 几乎完全是标签噪音**，真实的安全/合规知识水平大概率接近满分（4 次仅 1 道真实失分）——**不需要针对"Security, Compliance"专门加练**，时间应优先花在下面这条真正暴露出来的弱项上。
>
> **真正的弱项：Fundamentals of AI and ML，汇总正确率 79%，是五个 Domain 里唯一持续低于其他领域的一个**（70% → 73% → 87% → 100%，虽然逐次提升，但批次四的 100% 只基于 6 道题的小样本，不宜过度解读为"已经掌握"）。这与错题详解中反复出现的偏差-方差、监督/无监督/半监督边界等**基础概念题**吻合——建议接下来的 Udemy 模拟考重点关注这类基础概念题，而不是分散精力去"补" Security 这个假弱项。
>
> **次要观察**：Fundamentals of Generative AI 在批次二骤降到 73%（对应嵌入模型/提示工程集中失分），此后回升到 100%/93%，是补救见效的量化证据。批次四的 Domain 题量分布（Applications 占 35/65 ≈ 54%，远高于官方约 28% 的权重；Fundamentals of AI and ML 仅 6/65）明显偏离真实考试的 Domain 配比，该批次的单 Domain 百分比参考价值有限。

### 真实考试通过概率预测（基于当前 4 次数据，随新分数更新）

> **结论：通过概率较高，主观估计约 80%~90%**——但这不是严格的统计模型，样本只有 4 次，且 AWS 缩放分数的换算公式未公开，请把下面的推理过程当作**依据充分的估计**，而不是精确概率。

| 指标 | 数值 | 相对约 70% 及格线的余量 |
|------|------|------------------------|
| 最差一次（批次二） | 76% | +6 分 |
| 4 次平均 | 82.5% | +12.5 分 |
| 最近两次平均 | 86.5% | +16.5 分 |

**支持"通过概率较高"的理由**：
- 即使是**最差一次**模拟考也高出及格线 6 分，最近两次更是高出 16 分以上——按备考经验的粗略经验法则，模拟考稳定高出及格线 15 分以上通常意味着通过概率较高（这不是正式统计结论，只是社群经验）
- Domain 数据显示**真正的弱项**（Fundamentals of AI and ML，汇总 79%）本身也仍然**高于** 70% 及格线，说明没有任何一个真实领域是"扯后腿"到不及格的程度
- 模拟题（尤其 Tutorials Dojo 风格）普遍比真实考试更刁钻，不少考生反馈真实考试比高质量模拟题更容易

**拉低这个估计的不确定因素**：
- 65 题中 15 题不计分且无法分辨，缩放分数换算并非严格线性，AWS 未公开具体公式
- 真实考场的时间压力和紧张情绪，经验上通常会比放松状态下的模拟考再扣 5~10 个百分点
- **目前只有 4 次数据**——周三、周四计划中的模拟考分数还未纳入，这两次的结果会显著影响这个预测（见下方"如何更新此预测"）

**如何更新此预测**：
- 新增的模拟考分数 ≥ 80% → 预测上调，趋向 85%~90%+ 区间
- 新增分数落在 75%~84% → 预测维持在当前 80%~90% 区间，需关注失分集中在哪个 Domain
- 新增分数 < 75%，尤其若集中在 Fundamentals of AI and ML → 预测下调，建议重新评估是否如期应考

### 备考与预约计划（当前）

> 背景：原打算把批次四当作"最后一次模拟考"，后来发现了 **Udemy 上的新题库**，且计划**本周末预约真实考试**。以下是基于这个最新情况的计划。

- **模拟考总数已从 2 次调整为 4 次**——周二当天已完成 2 次（用户称为"mock exam 3、4"，与本笔记已记录的批次三/四是否为同一批还待确认，暂用日期+顺序追踪，不强行套用批次编号），另计划再做 2 次。**模拟考的价值主要在考后复习，而不是刷分本身**——4 次全部堆在一起做、不做中间复习，效果会明显打折扣，容易在多次模拟考里重复同样的错误却没发现规律，因此下方把剩余 2 次分开安排在不同天，每次都留出当天复习时间
- **本次新增的重点**：官方 Domain 数据显示 **Fundamentals of AI and ML 汇总仅 79%，是唯一持续偏低的领域**（详见上方"各 Domain 表现趋势"），而"Security, Compliance and Governance"看起来分数低（74%）但基本是标签噪音，**不必专门加练**——把有限的复习时间优先投入 Domain 1 的基础概念（监督/无监督/半监督边界、偏差-方差等）

## 重复出现的错题（高危薄弱点，优先复习）

> 以下题目/主题在**不同时间被问到两次以上、每次都答错**，说明是真正没有内化的薄弱区，考前应重点二次确认，优先级高于只错过一次的题目。

#### 批次一 · Q2 - 监督学习 vs 无监督学习 vs 半监督学习识别（多选，选二）

- **题干**：以下哪些属于监督学习？（Document classification / Clustering / Linear regression / Neural network / Association rule learning）
- **我的选择（错）**：Document classification（错）+ Linear regression（对）
- **正确答案**：Linear regression + **Neural network**
- **核心原因**：
  - **Linear regression**、**Neural network** 都是用**带标签数据**训练、预测已知目标的监督学习算法
  - **Document classification（文档分类）** 属于**半监督学习**——文档数量过大无法全部人工标注时，先用少量标注数据 + 大量无标注数据训练，本质是监督+无监督的结合
  - **Clustering**、**Association rule learning** 都是**无监督学习**——前者按相似性分组，后者挖掘"经常同时出现"的规律（如 Apriori 购物篮分析），二者都不依赖标签
- **易错点**：与批次三 Q22 是"同一知识框架的镜像题"（该题反过来考"哪些属于无监督学习"）——判断依据应该是"有标签→监督；无标签→无监督；部分标签→半监督"这套底层框架，而不是死记硬背单个答案
- **关联笔记**：[[Machine Learning#监督学习算法]] | [[Machine Learning#无监督学习算法]] | [[Machine Learning#半监督学习 (Semi-Supervised Learning)（考试重点：勿与自监督混淆）]]

#### 批次一 · Q18 - 提升模型准确率：应该调整哪个超参数

- **题干**：模型部署后预测准确率不理想，应该怎么做来提升准确率？
- **我的选择（错）**：增加正则化
- **正确答案**：**增加 Epoch 数量**
- **核心原因**：
  - **Epoch 增多** → 模型有更多机会学习训练数据中的复杂模式，直到准确率/误差率达到可接受水平——这是最直接针对"准确率不够"的调整方向
  - **正则化（我的错误选择）** 用于**解决过拟合**；但题目只说"准确率不理想"，未说明是过拟合还是欠拟合——若模型本身**欠拟合**，继续加正则化反而会进一步压低准确率
  - **降低批大小**：训练更"嘈杂"，不保证提升准确率，甚至可能让训练更不稳定
  - **降低学习率**：本质是**微调阶段**的精细调整，而非直接的"准确率提升手段"
- **考试关键词识别**：题目只说"准确率不够"、未提"训练集好测试集差"（过拟合特征）→ 默认先考虑"训练不充分"（增加 Epoch），而不是想当然地上正则化
- **关联笔记**：[[Machine Learning#模型参数与超参数]] | [[Machine Learning#过拟合与欠拟合（考试重点）]]（含偏差-方差方向速查表）

#### 批次一 · Q26 - Shapley 值 vs PDP（局部 vs 全局解释）📘

- **题干**：Shapley 值和 PDP 在模型可解释性上的区别，以及如何使用两者？
- **我的选择（错）**：认为 Shapley 值是全局、PDP 是局部（两者搞反了）
- **正确答案**：**Shapley 值 = 局部解释**（单个实例的特征贡献）；**PDP = 全局解释**（某特征在整个数据集范围内的边际影响）
- **核心原因**：Shapley 值基于博弈论，逐实例计算每个特征的边际贡献，回答"为什么这一条预测是这个结果"；PDP 固定其他特征、扫描某个特征的取值范围，回答"这个特征整体上如何影响模型输出"
- **关联笔记**：[[负责任的AI与安全#Shapley 值 vs PDP（局部解释 vs 全局解释）]]

#### 批次一 · Q30 - 推理参数：限制候选词数量该调哪个参数

  - **Temperature**：调节整体概率分布的"随机性"，不是筛选候选词范围的机制；**Stop sequences**：生成到特定字符串就停止，与候选词数量无关
- **关联笔记**：[[提示工程 - Prompt Engineering#核心参数对比]]

#### 批次二 · Q7 - 偏差-方差权衡：方向与定义不能搞反 📘

- **题干**：什么是机器学习中的偏差-方差权衡？

- **考试关键词识别**："审核模型的预测结果" → A2I；"标注训练数据" → Ground Truth
- **关联笔记**：[[Amazon SageMaker#SageMaker Ground Truth（数据标注，考试高频）]]

#### 批次四 · Q21 - 法律文档关键信息提取（多选，选三）📘

- **题干**：律所需要从合同、协议、案卷中自动提取关键条款、日期、实体信息，该用哪些工具？（Textract / Comprehend / Personalize / CNN / 生成式 AI 摘要聊天机器人 / WaveNet）
- **我的选择**：Textract（对）+ Comprehend（对）+ 漏选"生成式 AI 摘要聊天机器人"
- **正确答案**：Textract + Comprehend + **生成式 AI 摘要聊天机器人**
- **核心原因**：Textract 从扫描件/PDF 提取结构化文字；Comprehend 识别实体和关键短语；生成式 AI 摘要聊天机器人用提示工程生成定制化摘要，弥补前两者无法做语义级归纳总结的短板；CNN/Personalize/WaveNet 分别专注图像识别、推荐、语音合成，与文档提取无关
- **易错点**：三选题容易只选出最直觉的两个工具就停下，忽略题目还希望覆盖"归纳/总结"这一层
- **关联笔记**：[[AWS AI托管服务#三件套组合：Textract + Comprehend + 生成式 AI（考试重点：合同/法律文档处理）]]

#### 批次四 · Q49 - SageMaker 治理工具组合 📘

- **题干**：金融公司需要 SageMaker 治理工具确保模型合规、透明、负责任使用，该推荐哪组工具？
- **我的选择（错）**：Model Dashboard + Role Manager + Model Monitor
- **正确答案**：Role Manager + **Model Cards** + Model Dashboard

- **易错点**：纯记忆题，四个工具单独看都"沾边"治理，但官方明确只打包前三者，逻辑推理反而会选错

#### 批次四 · Q53 - 最节能的 EC2 实例类型 📘

- **题干**：医疗公司希望训练 ML 模型的同时选择能效最高、环境影响最小的 EC2 实例类型，该选哪个？
- **我的选择（错）**：Compute Optimized C 型实例
- **正确答案**：**AWS Trainium 实例**
- **核心原因**：Trainium 明确以"每瓦性能最优"为卖点，Trn1 实例训练场景能效比同类加速计算实例最高高出约 25%；C 系列追求计算性能而非能效；P 型 GPU 追求最大吞吐量、功耗显著；G 型面向图形渲染，同样非能效优化型
- **考试关键词识别**："能效最高/降低碳足迹" → Trainium；"训练性能最强" → 才考虑 P 型 GPU，不要把"性能强"和"能效高"混为一谈
- **关联笔记**：[[Amazon Bedrock#专用 AI 加速器（降低成本）]]

#### 批次四 · Q55 - SageMaker 自动调参（AMT）的必填配置项 📘

- **题干**：使用 SageMaker Automatic Model Tuning（AMT）时，以下哪项是必须手动指定的配置？（超参数范围 / 调优策略 / 训练任务数量）
- **我的选择（错）**：超参数范围
- **正确答案**：**都不是（None）**
- **核心原因**：SageMaker 的 Autotune 功能可自动决定超参数范围、搜索策略、任务数量、提前停止方式等，只需提供目标指标——没有一项是强制手动配置的
- **易错点**：这些参数确实**可以**手动设置、传统上通常也需要手动设置，容易被误判为"必需"，但题目问的是"mandatory"，Autotune 恰恰消除了这种必须性
- **关联笔记**：[[Machine Learning#Autotune：连"配置调参本身"都可以自动化（考试重点）]]

### Guidelines for Responsible AI

#### 批次四 · Q24 - 控制聊天机器人内容风险的最有效方法 📘

- **题干**：公司担心 Bedrock 聊天机器人生成不当/敏感/恶意内容，应采取什么措施控制风险？
- **我的选择（错）**：开发自定义 API 对模型输出做事后扫描过滤
- **正确答案**：**在提示词中加入明确指令，要求模型忽略无关或潜在恶意内容**
- **核心原因**：提示词层面的明确指令成本几乎为零，直接在生成阶段约束行为边界，属于"防患于未然"；自建输出过滤 API 增加复杂度和延迟，且不能阻止模型一开始就生成问题内容，只能事后补救；调超参数与内容安全是不同维度；从零重新训练不现实，且 Bedrock 本身不支持从零训练基础模型
- **考试关键词识别**：控制 LLM 安全风险的优先级排序 → 提示工程（最简单）→ Guardrails → 微调/RAG → 重新训练（几乎不会是正确答案）
- **关联笔记**：[[Amazon Bedrock#控制模型安全风险：按成本/复杂度排序的选择逻辑（考试重点）]]
