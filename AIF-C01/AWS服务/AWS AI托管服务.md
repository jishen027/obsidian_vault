# AWS AI 托管服务

> AWS 提供一系列开箱即用的 AI 服务，覆盖计算机视觉、NLP、对话 AI、推荐系统等领域。这些服务通过 API 调用即可使用，无需 ML 专业知识。是 AIF-C01 考试 Domain 1 和 Domain 3 的重要考点。
>
> 相关文档：[[Amazon Bedrock]] | [[Amazon SageMaker]] | [[AI与ML概念]] | [[AIF-C01 考试概览]]

## 服务分类速览（考试重点）

> 对于许多常见使用案例，无需构建自定义模型——AWS 提供可通过 **API** 访问的预先训练 AI 服务。在投入成本构建自定义模型之前，应先调查是否有现成服务适用。

## Amazon Rekognition（计算机视觉）

> **Amazon Rekognition** 是深度学习驱动的图像和视频分析服务，无需 ML 背景即可使用。

### 核心功能

| 功能 | 描述 |
|------|------|
| **对象/场景检测与标注** | 识别图像中的物体、场景、活动，使图像库变得可搜索 |
| **人脸检测/分析** | 检测人脸，分析年龄、情感、眼镜等属性 |
| **人脸比对（身份验证）** | 将人脸与员工证或驾驶执照等参考图像比较以验证身份 |
| **人脸搜索（已知人脸库）** | 从一系列已标注的人脸图像中自动识别并找到匹配人脸 |
| **名人识别** | 识别图像中的公众人物 |
| **文字识别 (OCR)** | 提取图像中的文字内容，例如路牌 |
| **内容审核** | 检测露骨、不当和暴力内容；标记应由人工审查的内容 |
| **自定义对象识别** | 提供已标注图像供其学习，用于识别自定义或专有对象 |
| **实时视频分析** | 分析流媒体视频中的对象，在安全系统中实时检测并发出提醒 |

> **置信度分数**：Rekognition 返回每个检测结果的置信度分数。示例：人脸匹配置信度 99.8%，不匹配人脸也会显示结果并标注不匹配。

### 适用场景

```
场景分析 → 使用 Rekognition
├── "验证用户身份（人脸与证件比对）" → 人脸比对
├── "从已知人员库中找到目标人物" → 人脸搜索
├── "审查用户上传图片是否合规（内容审核）" → 内容审核
├── "从图片中提取文字/路牌识别" → 文字识别
├── "识别并标注图库中的对象使其可搜索" → 对象检测与标注
└── "安全系统实时视频监控" → 实时视频分析
```

## Amazon Comprehend（NLP 文本分析）

> **Amazon Comprehend** 使用 NLP 分析文本，提取关键信息，支持自定义模型。

### 核心功能

| 功能 | 描述 |
|------|------|
| **情感分析 (Sentiment Analysis)** | 判断文本的情感倾向：正面、负面、中性、混合 |
| **实体识别 (Entity Recognition)** | 提取人名、地名、日期、组织、数量等实体 |
| **关键短语提取** | 识别文本中的关键词组 |
| **语言检测** | 自动检测文本使用的语言 |
| **PII 检测** | 识别个人身份信息（姓名、电话、邮件、信用卡等） |
| **目标情感 (Targeted Sentiment)** | 针对特定实体的情感分析 |
| **自定义实体/分类** | 训练自定义 NLP 模型识别领域专有实体或分类 |

### Comprehend Flywheel

- **Flywheel** 是 Comprehend 的子服务，自动化自定义模型版本的持续训练（类似持续学习）

### PII 检测与置信度阈值

> Comprehend 检测 PII 时会返回每项结果的**置信度分数**，可设置最低置信阈值自动处理。

示例：从电子邮件中找到姓名、地址、电话、信用卡号，并返回置信度分数。超过阈值的 PII 实体可自动移除。

### 自定义分类器

> 通过向 Comprehend 提供训练数据，可创建使用您自己类别的**自定义分类器**（无需从头构建 ML 模型）。

### 常见组合工作流：Textract + Comprehend

```
扫描文档/图像 → Amazon Textract（提取文字） → Amazon Comprehend（情感分析/PII检测）→ 结果
```
- 实际案例：AWS 使用 Amazon Comprehend 分析认证考试评论的情感

### 适用场景

```
场景分析 → 使用 Comprehend
├── "分析客户评论的正负面情绪" → 情感分析
├── "从合同中提取公司名称和日期" → 实体识别
├── "检查文档中是否包含个人信息" → PII 检测（含置信度阈值）
├── "将客户支持工单自动分类（自定义类别）" → 自定义分类
└── "从扫描文档中提取文字后进行情感分析" → Textract + Comprehend 组合
```

## Amazon Textract（文档 OCR）

> **Amazon Textract** 超越传统 OCR，不仅提取文字，还理解文档结构（表单、表格、签名）。

### 核心功能

| 功能 | 描述 |
|------|------|
| **OCR** | 从图像/PDF 中提取文字，保留布局坐标 |
| **表格提取** | 识别并结构化提取表格数据 |
| **表单提取 (Key-Value)** | 提取表单字段和对应值 |
| **签名检测** | 检测文档中的签名位置 |
| **费用单识别** | 专门识别收据/发票的预定义模型 |
| **文档查询** | 对 OCR 后的内容进行自然语言查询 |

### 支持格式

- JPEG、PNG、PDF、TIFF

### 适用场景

```
场景分析 → 使用 Textract
├── "数字化纸质申请表" → 表单提取
├── "自动录入发票数据" → 费用单识别
├── "验证合同是否有签名" → 签名检测
└── "在大量文档中查找特定信息" → OCR + 文档查询
```

## Amazon Lex（对话 AI / 聊天机器人）

> **Amazon Lex** 是构建对话式语音和文字聊天机器人的服务，是 Alexa 的商业/企业版本。

### 核心特性

| 特性 | 描述 |
|------|------|
| **自动语音识别 (ASR)** | 将语音转换为文字 |
| **自然语言理解 (NLU)** | 理解用户意图 |
| **意图 (Intent)** | 用户想要完成的操作 |
| **槽位 (Slot)** | 完成意图所需的参数信息 |
| **多轮对话** | 支持上下文感知的多轮会话 |

### 典型架构

```
用户语音/文字 → Amazon Lex（意图识别）→ Lambda 函数（业务逻辑）→ 后端系统
```

### 核心使用案例

- **客户服务聊天机器人**：处理常见问题，无需人工座席
- **交互式语音应答 (IVR) 系统**：支持客户直接对话而无需按键（取代旧式按键 IVR）→ 将呼叫转给合适座席
- **实际案例**：DoorDash 用 Amazon Lex 替换旧式 IVR 系统，客户可直接对话，极大改善体验、缩短等待时间、提高自助服务采用率

## Amazon Kendra（企业搜索）

> **Amazon Kendra** 是企业级机器学习搜索引擎，使用语义和上下文理解（而非简单关键词匹配）进行搜索。

### 核心特性

| 特性 | 描述 |
|------|------|
| **语义搜索** | 理解问题含义，而非关键词匹配 |
| **自然语言问答** | 直接回答问题，而非返回文档列表 |
| **多数据源连接** | 支持 S3、SharePoint、Salesforce、数据库等 |
| **访问控制** | 基于用户权限过滤搜索结果 |

### 核心特性

- 使用 NLP 理解自然语言问题，例如："How do I connect my Echo Plus to my network?"
- 根据对问题的智能理解返回相关结果（而非简单关键词匹配）
- 支持多数据源：S3、SharePoint、Salesforce、数据库等
- 基于用户权限过滤搜索结果

### 与 RAG（Bedrock Knowledge Bases）对比

| 特性 | Amazon Kendra | Bedrock Knowledge Bases |
|------|--------------|------------------------|
| **技术** | 传统搜索 + ML 语义 | 向量嵌入 + LLM |
| **输出** | 相关文档/段落 | LLM 生成的自然语言答案 |
| **适合场景** | 企业文档搜索 | 生成式 AI 应用 RAG |

## Amazon Personalize（推荐系统）

> **Amazon Personalize** 是全托管的个性化推荐服务，使用与 Amazon.com 相同的技术。

### 核心数据集

| 数据集 | 必填 | 说明 |
|--------|------|------|
| **用户-物品交互数据** | ✅ 必填 | 用户 ID、物品 ID、时间戳（核心） |
| **物品元数据** | 可选 | 物品的属性（类别、价格等） |
| **用户元数据** | 可选 | 用户属性（年龄、地区等） |

### 推荐场景

| 推荐类型 | 描述 |
|---------|------|
| **用户个性化** | 为特定用户推荐内容（"您可能还会喜欢"） |
| **相关物品** | 与某物品相关的其他物品 |
| **热门商品** | 最受欢迎的物品 |
| **最近浏览** | 基于用户最近行为 |

### 使用案例

- **电子商务**："您可能还会喜欢"个性化产品推荐区
- **营销活动**：根据客户喜好对客户进行细分，开展更有效的定向营销活动
- **媒体娱乐**：个性化内容推荐（视频流、音乐等）

## Amazon Polly（文字转语音）

> **Amazon Polly** 使用**深度学习技术**合成人类语音，支持数十种语言，生成听起来自然的语音。AI 生成自然声音的能力使公司能够提高客户参与度，并为视障客户提供更多便利。

### 核心使用案例

- **将文章转换为音频**：媒体公司根据突发新闻和头条新闻制作音频
  - 实际案例：《华盛顿邮报》、《今日美国》等使用 Amazon Polly 制作新闻音频
- **IVR 系统提示语音**：在交互式语音应答系统中提示来电者
- **无障碍访问**：为视障客户提供内容朗读功能

### SSML 支持

| 标签 | 功能 |
|------|------|
| `<speak>` | 根元素 |
| `<break>` | 插入停顿 |
| `<emphasis>` | 强调语气 |
| `<prosody>` | 控制音量、语速、音调 |
| `<whisper>` | 低声说话效果（仅特定声音） |
| `<lang>` | 切换语言 |

## Amazon Transcribe（语音转文字）

> **Amazon Transcribe** 是自动语音识别 (ASR) 服务，将音频转换为文字，支持 **100 多种语言**，适用于实时和录制的音频/视频输入。

| 功能 | 描述 |
|------|------|
| **实时转录** | 实时流式转录（适合直播字幕） |
| **批量转录** | 异步处理录制的音频/视频文件 |
| **说话人识别** | 区分多个说话人 |
| **自定义词汇** | 添加专业术语提高识别准确率 |
| **PII 编辑** | 自动从转录文字中移除个人信息 |

**常见使用案例**：实时为流式音频添加字幕、会议转录、呼叫中心录音分析

## Amazon Translate（机器翻译）

> **Amazon Translate** 可在 **75 种**不同语言之间流畅翻译文本。以**神经网络**为基础，考虑源语言句子的**整个上下文**以及已生成的翻译，生成更准确、更流畅的翻译。

| 特性 | 描述 |
|------|------|
| **语言数量** | 支持 75 种语言之间的互译 |
| **翻译方式** | 神经网络上下文感知（非逐字翻译） |
| **实时翻译** | 支持流式输入实时翻译 |

**常见使用案例**：
- 在线聊天应用中的实时翻译（客户和客服使用不同语言实时沟通）
- 内容本地化和多语言文档翻译

## Amazon Forecast（时间序列预测）

> **Amazon Forecast** 是一项 AI 时间序列预测服务。通过提供历史时间序列数据，可预测序列中未来的时间点值。

| 特性 | 描述 |
|------|------|
| **内置算法** | 支持神经网络算法和传统统计算法 |
| **适用领域** | 零售、财务规划、供应链、医疗保健等 |

**常见使用案例**：
- 预测销售额和库存水平
- 预测呼叫中心呼叫量（按时间段配置坐席数量）
- 实际案例：AffordableTours.com 使用 Amazon Forecast 预测呼叫量，未接电话率下降 20%

## Amazon Fraud Detector（欺诈检测）

> **Amazon Fraud Detector** 是全托管的实时欺诈检测服务，具有**预训练的数据模型**，可检测多种欺诈场景。

| 检测场景 | 说明 |
|---------|------|
| **线上支付欺诈** | 检测欺诈性在线交易 |
| **虚假账户** | 检测虚假账户创建行为 |
| **产品评论欺诈** | 识别虚假评论 |
| **账户接管** | 检测账户被他人接管的情况 |

- 无需 ML 专业知识，上传历史数据即可训练模型
- 实际案例：MasterCard 使用 SageMaker 训练欺诈检测模型，检测到的欺诈交易数量增加两倍，误报减少 10 倍；后又采用生成式 AI 将欺诈检测效率提升 20%
