# Amazon SageMaker

> **Amazon SageMaker** 是 AWS 的全托管机器学习平台，覆盖 ML 的完整生命周期：数据准备、模型训练、调参、评估、部署和监控。与 Bedrock 不同，SageMaker 面向需要**自建和训练模型**的 ML 工程师和数据科学家。
>
> 相关文档：[[Amazon Bedrock]] | [[AI与ML概念]] | [[机器学习算法]] | [[数据与分析服务]]

---

## ML 开发生命周期（ML 管道）

> **机器学习管道**是从业务目标到运行已部署模型的一系列相互关联的步骤，是一个**迭代过程**——部分或全部步骤在模型部署后可能会重复进行。

```
1. 确定业务目标
       ↓
2. 收集和准备训练数据
       ↓
3. 训练、优化和评估模型（迭代）
       ↓
4. 部署模型
       ↓
5. 监控模型
       ↓（发现问题时返回步骤 2 或 3）
```

### 第一步：确定业务目标

- 确定要解决的问题和要获得的商业价值
- 确定可量化的成功标准（没有成功标准就无法评估模型）
- 协调利益相关方，就目标达成共识
- 评估组织能力，设定可实现的目标
- 进行**成本效益分析**，确认 ML 是否是最佳方法

### 服务选择框架（从简到复杂）

```
第一步：AWS 预训练 AI 服务能否满足需求？
├── 能 → 直接使用（Rekognition / Comprehend / Lex 等）
│         支持自定义输出（如 Comprehend 自定义分类器）
│
第二步：现有预训练模型 + 微调？
├── 生成式 AI 场景 → Amazon Bedrock（基础模型 + 迁移学习/Fine-tuning）
├── 其他 ML 场景 → SageMaker JumpStart（预训练模型 + 增量训练）
│
第三步：从头开始训练自定义模型（难度极大，成本极高）
└── 技术上极具挑战性，安全与合规责任极高 → 最后手段
```

### SageMaker JumpStart 与迁移学习

> **SageMaker JumpStart** 为计算机视觉和 NLP 任务提供经过预训练的 AI 基础模型和特定任务模型（基于大型公用数据集预训练）。

- **迁移学习 (Transfer Learning)**：使用自己的数据集对预训练模型进行**增量训练/微调**，大幅降低成本和开发时间
- 包含 HuggingFace 模型（Whisper、BERT 等）
- 支持快速部署和实验，内置 Jupyter Notebook 示例

## SageMaker vs Bedrock（考试重点）

| 特性 | Amazon SageMaker | Amazon Bedrock |
|------|-----------------|----------------|
| **定位** | 构建/训练/部署自定义 ML 模型 | 访问预训练基础模型（LLM） |
| **用户群** | ML 工程师、数据科学家 | AI 工程师、应用开发者 |
| **技术深度** | 深（需要 ML 知识） | 浅（API 调用即可） |
| **模型来源** | 自建、HuggingFace、开源 | AWS 合作商提供的基础模型 |
| **典型场景** | 训练自定义分类器、推荐模型 | 调用 Claude 生成文本、RAG |

```
选择 SageMaker 还是 Bedrock
├── "需要完全控制训练过程" → SageMaker
├── "需要使用自己的数据集从零训练" → SageMaker
├── "快速使用 LLM 构建 AI 应用" → Bedrock
├── "不想管训练基础设施" → Bedrock（Fine-tuning）
└── "需要训练传统 ML 模型（分类、回归）" → SageMaker
```

## SageMaker 核心组件

### 开发环境

| 组件 | 描述 |
|------|------|
| **SageMaker Studio** | 集成 IDE，支持 Jupyter Notebooks、代码编辑、实验跟踪 |
| **SageMaker Notebooks** | 托管 Jupyter Notebooks，按使用计费 |
| **SageMaker JumpStart** | 预构建 ML 解决方案和基础模型的起点（含 HuggingFace 模型） |

> **注意**：SageMaker Studio Classic 已被新版 SageMaker Studio 取代，新版体验差异较大。

### 数据摄取与准备（ETL 阶段）

> 数据收集和准备阶段包括：识别所需数据、配置 ETL 流程、数据标注、探索性数据分析、预处理和特征工程。

#### AWS Glue（ETL 服务）

> **AWS Glue** 是完全托管式 ETL 服务，从多个来源收集数据并存储到集中式存储库（通常是 S3）。

| 组件 | 说明 |
|------|------|
| **AWS Glue 数据目录** | 存储元数据（表定义、架构、位置），而非数据本身 |
| **Glue 爬网程序** | 自动扫描数据来源，使用分类器确定数据架构，写入数据目录 |
| **Glue ETL 任务** | 生成代码执行数据转换，支持删除重复记录、填写缺失值、拆分数据集等内置转换 |
| **支持数据源** | 关系数据库、数据仓库、其他云、流服务（MSK、Kinesis）等 |

**注意**：数据目录只存储元数据（位置、架构），源数据本身不写入目录，ETL 任务负责实际转换和写入目标存储（通常是 S3）。

#### AWS Glue DataBrew（可视化数据准备）

> **DataBrew** 是可视化数据准备工具，无需编写代码即可清理和规范化数据。

- 250+ 内置转换（删除空值、替换缺失值、修复架构不一致、基于列的函数等）
- 交互式发现、可视化、清理和转换原始数据
- 将转换步骤保存为**配方 (Recipe)**，可重复用于其他数据集
- 支持定义规则集和运行分析任务评估数据质量
- DataBrew 提出智能建议，帮助识别难以发现的数据质量问题

#### 数据集划分（Train/Val/Test）

建议比例：**训练集 80% / 验证集 10% / 测试集 10%**

#### 特征工程注意事项

- 精简训练数据中的特征，仅保留推理所需的特征
- 可组合特征进一步减少特征数量
- 减少特征数量 → 减少训练所需的内存量和计算能力

### 数据准备

| 组件 | 描述 |
|------|------|
| **SageMaker Data Wrangler** | 可视化数据准备工具，300+ 内置转换，无需编写代码 |
| **SageMaker Ground Truth** | 数据标注服务，主动学习自动标注 + 人工处理难例 |
| **SageMaker Feature Store** | 集中存储、共享、发现 ML 特征的在线/离线存储 |
| **SageMaker Canvas** | 无代码 ML 工具，上传数据即可训练模型（**费用极高，空闲也计费**） |

### 训练

> 创建训练任务需指定：训练数据 S3 URL、计算资源、模型构件输出 S3 路径、算法（Docker 容器映像，来自 Amazon ECR）、超参数。

| 组件 | 描述 |
|------|------|
| **内置算法 (Built-in Algorithms)** | 预优化的常见 ML 算法（XGBoost、线性回归、KNN 等） |
| **自定义训练脚本** | 使用自己的 Python 脚本（TensorFlow、PyTorch、MXNet） |
| **自定义 Docker 容器** | 完全自定义训练环境（存储于 Amazon ECR） |

> 最佳实践：**并行运行多个训练任务**（不同算法 + 不同设置），即"运行实验"，找到性能最佳的解决方案。

### SageMaker Experiments（实验管理）

> **SageMaker Experiments** 允许创建、管理、分析和比较机器学习实验，应对大量模型版本（可能成千上万个）的管理需求。

- 可视化界面浏览当前和历史实验
- 比较关键性能指标的不同训练运行
- 确定性能最佳的模型

### 调参与优化

| 组件 | 描述 |
|------|------|
| **Automatic Model Tuning (AMT)** | 自动搜索最优超参数组合，可使用 Spot 实例降低成本 |
| **SageMaker Debugger** | 实时分析训练过程，检测梯度问题 |

> **AMT 工作原理**：配置优化任务，指定算法、超参数范围和目标指标（如最大化 AUC），在循环内运行多个训练任务，直到满足完成标准（如指标不再改善的任务数量）。

### 部署与推理（四种 SageMaker 推理选项）

> 选择推理方式时需根据 ML 推理工作负载的业务需求决定。所有 SageMaker 托管端点均为完全托管式，支持弹性伸缩。

| 推理选项 | 适用场景 | 计算资源 | 特点 |
|---------|---------|---------|------|
| **实时推理 (Real-time)** | 低延迟、交互式响应、持续流量 | 持续运行 | REST API 端点，实例类型可选 |
| **批量转换 (Batch Transform)** | 大型数据集离线推理，无需持久端点 | 按需启停 | 支持 GB 级大型数据集 |
| **异步推理 (Async)** | 大型负载、处理时间较长、需排队 | 无请求时缩减到 0 | 适合长时处理，无请求时不付费 |
| **无服务器推理 (Serverless)** | 间歇性流量，无需配置实例 | Lambda 按需 | 仅运行时付费，无流量不付费 |

> 推理代码和模型构件通常打包为 **Docker 容器**部署，可在任何安装了容器运行时的 AWS 资源上运行（Batch、ECS、EKS、Lambda、EC2）。

> **SageMaker 推理推荐器**：测试模型的不同配置选项，帮助选择最佳配置。

### 监控

| 组件 | 描述 |
|------|------|
| **SageMaker Model Monitor** | 监控生产模型的数据漂移和质量下降 |
| **CloudWatch 集成** | 追踪训练/推理指标和日志，配置警报 |

#### 模型监控细节

> 模型性能会随时间推移因数据质量、模型质量和模型偏差等原因下降。

| 偏移类型 | 定义 |
|---------|------|
| **数据偏移 (Data Drift)** | 与训练数据相比，输入数据分布发生显著变化 |
| **概念偏移 (Concept Drift)** | 目标变量的属性发生变化（任何偏移都会导致性能下降） |

**SageMaker Model Monitor 工作流**：
```
按定义时间表收集端点数据 → 与基准比较 → 根据规则分析 → 在 Studio 中查看结果
     → 发送结果到 CloudWatch → 配置警报 → 触发补救措施（如启动重新训练）
```

## MLOps（机器学习运营）

> **MLOps** 是将软件工程最佳实践应用于 ML 模型开发的方法，涉及自动执行手动任务、发布前测试评估代码、自动响应事件。

### MLOps 核心原则

- **版本控制**：对所有内容进行版本控制，包括训练数据、代码、模型构件
- **自动化**：自动执行 ML 生命周期中的所有步骤（可重复性）
- **持续监控**：监控部署以发现潜在问题
- **自动重新训练**：数据/代码更改或检测到问题时自动触发重训练

### MLOps 的好处

| 好处 | 说明 |
|------|------|
| **提高工作效率** | 自动化 + 自助服务环境，数据工程师和科学家进展更快 |
| **可重复性** | 自动化训练、评估、版本控制和部署流程确保一致性 |
| **更高可靠性** | 部署能力更快，质量和一致性更高 |
| **合规可审计性** | 对所有输入/输出（实验、源数据、训练模型）版本控制，可准确演示模型构建和部署方式 |
| **提高数据和模型质量** | 执行防偏差策略，追踪数据统计属性和模型质量变化 |

### MLOps 工具生态

| 工具 | 类型 | 用途 |
|------|------|------|
| **AWS CodeCommit** | 源代码存储库 | 存储推理代码（类似 GitHub） |
| **SageMaker Feature Store** | 特征存储库 | 训练数据特征定义的集中存储 |
| **SageMaker Model Registry** | 模型注册表 | 训练模型和历史记录的集中存储 |
| **SageMaker Pipelines** | ML 管道编排 | 编排 SageMaker 任务，创建可复制的 ML 管道 |
| **AWS Step Functions** | 工作流编排 | 可视化拖放界面定义无服务器工作流 |
| **Amazon MWAA** | Apache Airflow 托管服务 | 使用 Python 创建工作流，无需管理底层基础设施 |

### SageMaker Pipelines

> **SageMaker Pipelines** 编排 SageMaker 任务，创建可复制的 ML 管道，支持追踪构件的沿袭。

- 可使用 **SageMaker Python SDK** 或 **JSON** 定义管道
- 支持条件分支（基于上一步输出）
- 可在 **SageMaker Studio** 中查看管道
- 支持低延迟实时推理部署、批量转换离线推理、构件沿袭追踪

### 成本追踪（业务指标）

> **AWS 成本分配标签**：为管道使用的所有资源定义标签（如 ML 项目名称），然后在 **AWS Cost Explorer** 中筛选成本报告，确定项目实际产生的 AWS 费用，用于计算投资回报率 (ROI)。

## SageMaker ML 流程

### 完整流程

```
数据准备 (Data Wrangler / Ground Truth)
    ↓
特征工程 (Feature Store)
    ↓
模型训练 (Training Jobs)
    ↓
超参数调优 (Automatic Model Tuning)
    ↓
模型评估 (Model Evaluation)
    ↓
模型部署 (Endpoint / Batch Transform)
    ↓
模型监控 (Model Monitor)
```

## SageMaker Feature Store

> **Feature Store** 提供在线（低延迟）和离线（大批量）特征存储，支持多个 ML 模型共享特征。

| 模式 | 用途 | 特点 |
|------|------|------|
| **在线存储 (Online Store)** | 实时推理时快速读取特征 | 毫秒级延迟 |
| **离线存储 (Offline Store)** | 批量训练时读取历史特征 | 基于 S3，适合大数据量 |

### 流式摄取

- 使用 **Put Record API** 将实时数据推送到 Feature Store
- 支持 Kafka、Kinesis、Spark 等流式数据源
- 毫秒级延迟，高吞吐量

---

## SageMaker Ground Truth（数据标注）

> **Ground Truth** 提供数据标注工作流，支持图像分类、对象检测、文本分类等任务。

| 特性 | 描述 |
|------|------|
| **人工标注** | 通过标注人员界面完成标注任务 |
| **主动学习** | 自动标注置信度高的样本，人工处理难例 |
| **CORS 注意** | 标注图像时需要启用 S3 CORS（解决图像方向显示问题） |

---

## SageMaker JumpStart

> **JumpStart** 提供预构建的 ML 解决方案、基础模型（含 HuggingFace 模型），可直接部署或微调。

- 访问 HuggingFace 上的 Whisper、Bert 等模型
- 支持快速部署和实验
- 内置 Jupyter Notebook 示例

## 定价注意事项

> **重要警告**：SageMaker 部分服务在空闲时也持续计费，使用完必须及时停止实例。

| 容易忘关的资源 | 说明 |
|--------------|------|
| **SageMaker Studio 实例** | 内核停止后仍可能计费 |
| **SageMaker Canvas** | 费用极高（课程中曾有数百加元意外费用），不建议使用 |
| **实时端点** | 按运行时间计费，不用时应删除 |

## 推理管道 (Inference Pipeline)

> 将多个容器串联处理推理请求，支持在**同一 EC2 实例**上按顺序运行所有容器（低延迟）。

| 特性 | 描述 |
|------|------|
| **不可变性** | 部署后不可修改，更新需重新部署新版本 |
| **无额外成本** | 推理管道本身不额外收费 |
| **支持容器类型** | sklearn 容器、Spark ML 容器、自定义容器 |

## 考试重点总结

### AIF-C01 高频考点

1. **SageMaker vs Bedrock**：自建训练 vs 直接用预训练模型
2. **服务选择框架**：预训练 AI 服务 → JumpStart/Bedrock 微调 → 从头训练
3. **迁移学习**：用自己数据对预训练模型进行增量训练
4. **AWS Glue**：托管 ETL 服务，数据目录只存元数据
5. **DataBrew**：无代码可视化数据准备，配方可重复使用
6. **Data Wrangler**：SageMaker 内可视化数据准备（300+ 转换）
7. **Ground Truth**：数据标注，主动学习自动标注 + 人工处理难例
8. **SageMaker Experiments**：管理和比较大量训练实验
9. **Automatic Model Tuning (AMT)**：超参数自动调优
10. **四种推理选项**：实时（持续）/ 批量（按需）/ 异步（排队）/ 无服务器（Lambda）
11. **数据偏移 vs 概念偏移**：输入分布变化 vs 目标变量属性变化
12. **Model Monitor**：检测生产模型偏移，通过 CloudWatch 触发警报
13. **MLOps**：版本控制、自动化、持续监控、可重复性
14. **SageMaker Pipelines**：编排 ML 管道，支持沿袭追踪
15. **成本追踪**：成本分配标签 + AWS Cost Explorer 计算 ROI

### 场景题解题思路

```
场景分析 → 选择 SageMaker 功能
├── "需要给图像打标签" → Ground Truth
├── "需要找最优模型参数" → Automatic Model Tuning (AMT)
├── "需要低延迟实时推理" → 实时端点
├── "需要处理大批量数据，无需持久端点" → Batch Transform（批量转换）
├── "请求量大，处理时间长，需排队" → 异步推理
├── "间歇性流量，无请求时不想付费" → 无服务器推理
├── "需要检测模型质量下降" → Model Monitor
├── "发现数据偏移/概念偏移" → 重新训练模型
├── "需要可视化数据清洗（无代码）" → DataBrew 或 Data Wrangler
├── "需要 ETL 从多个来源收集数据" → AWS Glue
├── "需要快速使用预训练模型（HuggingFace 等）" → JumpStart
├── "需要管理大量训练实验" → SageMaker Experiments
└── "需要自动化整个 ML 管道" → SageMaker Pipelines
```
