## 模型构件与推理部署

### 模型构件 (Model Artifacts)

> 训练过程生成的**模型构件**是模型的核心产出物，通常存储在 **Amazon S3** 中。

| 组成部分 | 说明 |
|---------|------|
| **训练好的参数** | 训练过程中迭代优化的模型权重 |
| **模型定义** | 描述如何计算推理的结构信息 |
| **其他元数据** | 版本、训练配置等附加信息 |

> 模型构件 + **推理代码**（读取构件以实现模型的软件）打包在一起，形成**可部署的模型**。

### 推理部署方式（考试重点）

| 方式 | 说明 | 计算资源 | 适用场景 |
|------|------|---------|---------|
| **实时推理 (Real-time Inference)** | 持久性终端节点，随时接受请求 | **始终运行** | 低延迟、高吞吐量的线上请求 |
| **批处理推理 (Batch Inference)** | 离线批量处理，完成后资源关闭 | **仅处理时运行，之后关闭** | 大量数据一次性处理，可接受延迟 |

**关键区别**：实时推理的计算资源**持续运行**；批处理的计算资源**按需启停**，因此批处理通常更具**成本效益**。

#### 实时推理
```
客户端 → 发送输入数据 → 持久性终端节点（模型） → 快速返回推理结果
```
- 适合：欺诈检测、实时推荐、语音识别等需要即时响应的场景

#### 批处理推理
```
大量输入数据（预先准备）→ 批处理作业 → 等待处理完成 → 获取批量结果（用于报告等）
```
- 适合：不需要持久性终端节点，结果可以等待的离线分析场景
- 示例：拥有历史销售数据，每月预测目录中每种产品下个月所需库存，结果用于生成月度报告

## 数据集划分

> 将数据集划分为训练集、验证集和测试集，是保证模型评估客观性的关键。

### 三类数据集

| 数据集 | 用途 | 比例参考 |
|--------|------|---------|
| **训练集 (Training Set)** | 模型从中学习参数（权重） | 60–80% |
| **验证集 (Validation Set)** | 调整超参数，评估模型在训练过程中的表现 | 10–20% |
| **测试集 (Test Set)** | 最终评估模型在未见数据上的泛化能力 | 10–20% |

> **关键原则**：测试集只能在训练完成后使用一次，不能用于调参，否则会导致评估结果过于乐观。

### 交叉验证 (Cross-Validation)

> 数据量不足时，使用 K 折交叉验证充分利用数据。

```
K-Fold 交叉验证（K=5）
┌─────┬─────┬─────┬─────┬─────┐
│ 验证 │ 训练 │ 训练 │ 训练 │ 训练 │ 第1轮
│ 训练 │ 验证 │ 训练 │ 训练 │ 训练 │ 第2轮
│ 训练 │ 训练 │ 验证 │ 训练 │ 训练 │ 第3轮
│ 训练 │ 训练 │ 训练 │ 验证 │ 训练 │ 第4轮
│ 训练 │ 训练 │ 训练 │ 训练 │ 验证 │ 第5轮
└─────┴─────┴─────┴─────┴─────┘
最终得分 = 5 轮验证集准确率的平均值
```

## 训练核心概念

### 参数 vs 超参数（考试重点）

| 类型 | 定义 | 示例 | 谁来设置 |
|------|------|------|---------|
| **参数 (Parameters)** | 模型内部权重，训练中自动学习更新 | 神经网络权重、偏置项 | 算法自动优化 |
| **超参数 (Hyperparameters)** | 训练前手动配置的设置项 | 学习率、Epoch、批大小 | 工程师手动设定 |

### 关键超参数说明

| 超参数 | 描述 | 过大的影响 | 过小的影响 |
|--------|------|----------|----------|
| **学习率 (Learning Rate)** | 每次梯度更新的步长 | 不收敛，震荡 | 训练极慢，陷入局部最优 |
| **Epoch** | 训练数据被完整遍历的次数 | 过拟合 | 欠拟合 |
| **批大小 (Batch Size)** | 每次更新权重使用的样本数量 | 内存压力大，但梯度稳定 | 训练噪声大，但泛化性可能更好 |
| **层数/节点数** | 神经网络深度和宽度 | 过拟合、计算成本高 | 欠拟合，表达能力不足 |

### SageMaker 自动超参数调优

- **Automatic Model Tuning**（也称超参数调优 HPO）
- 自动搜索最优超参数组合
- 支持内置算法、自定义算法、预构建容器
- 可配合 **Spot 实例**节省成本

## 过拟合与欠拟合（考试重点）

| 状态 | 训练集表现 | 测试集表现 | 根本原因 |
|------|----------|----------|---------|
| **欠拟合 (Underfitting)** | 差 | 差 | 模型太简单或训练时间不足，无法捕捉数据规律 |
| **过拟合 (Overfitting)** | 好 | 差 | 模型记住了训练噪声，泛化能力弱 |
| **泛化良好** | 好 | 好 | 目标状态 |

### 具体原因与示例

**过拟合的典型原因**：
- 训练数据**多样性不足**：模型仅见过特定场景 → 遇到略有不同的输入时失败
  - 示例：鱼类识别模型只训练了"鱼在水中游"的图像，部署后遇到"鱼离开水"的图片则无法识别
- **训练时间过长**：模型开始过分强调不重要的特征（**噪声**）→ 另一种形式的过拟合

**欠拟合的典型原因**：
- 训练时间**不够长**
- 训练数据集**规模不足**
- 欠拟合的模型对训练数据集和新数据的预测结果**都不准确**

> **最佳训练时间**：数据科学家需要找到最佳训练时长——训练太短导致欠拟合，训练太长导致过拟合。

### 解决方案

| 问题 | 解决方案 |
|------|---------|
| **过拟合** | **使用更多样化的训练数据**（最佳方法）、正则化（L1/L2）、Dropout、早停（Early Stopping）、减少模型复杂度 |
| **欠拟合** | 增加训练时间、扩大训练数据集、增加模型复杂度（更多层/节点）、特征工程 |

```
场景分析 → 诊断并解决
├── "训练集 95%，测试集 60%" → 过拟合 → 正则化 / 更多数据
├── "训练集 60%，测试集 58%" → 欠拟合 → 增加模型复杂度
└── "训练集 90%，测试集 88%" → 泛化良好 ✅
```

## 偏差与方差（Bias and Variance）（考试重点）

> **过拟合/欠拟合**描述的是训练集与测试集之间的**表现差距**（现象）；**偏差（Bias）**与**方差（Variance）**则是造成这一现象的两种**根本成因**——理解两者能帮助更精准地判断"模型错在哪里、该怎么修"。

### 定义

| 概念                | 定义                                        | 对应现象                            |
| ----------------- | ----------------------------------------- | ------------------------------- |
| **偏差 (Bias)**     | 模型对问题做出的**简化假设**与真实规律之间的系统性偏差——假设越简单，偏差越大 | 高偏差 ≈ **欠拟合**：模型太简单，训练集和测试集误差都高 |
| **方差 (Variance)** | 模型对**训练数据微小变化**的敏感程度——对训练集中随机噪声的过度拟合      | 高方差 ≈ **过拟合**：训练集误差低，但测试集误差高    |

```
模型总误差 ≈ 偏差² (Bias²) + 方差 (Variance) + 不可约误差 (Irreducible Error)
```

- **不可约误差 (Irreducible Error)**：数据本身固有的噪声，无法通过改进模型消除，是误差的理论下限

### 偏差-方差权衡（Bias-Variance Tradeoff）

> 偏差和方差通常此消彼长：**降低偏差（增加模型复杂度）往往会提高方差**，反之亦然。模型训练的目标是找到两者之间的**最佳平衡点**，使总误差最小。

```
模型复杂度  低 ──────────────────────────────────▶ 高

偏差 (Bias)     高 ─────────────────────────▶ 低
方差 (Variance) 低 ─────────────────────────▶ 高

           欠拟合区                最佳平衡点              过拟合区
       （高偏差，低方差）      （偏差、方差都较低）      （低偏差，高方差）
```

| 场景 | 偏差 | 方差 | 诊断 |
|------|------|------|------|
| 训练集、测试集误差都高 | 高 | 低 | **高偏差 → 欠拟合** |
| 训练集误差低，测试集误差高 | 低 | 高 | **高方差 → 过拟合** |
| 训练集、测试集误差都低且接近 | 低 | 低 | **理想的平衡状态** ✅ |

### 如何分别应对高偏差 vs 高方差

| 问题 | 应对方法 |
|------|---------|
| **高偏差（欠拟合）** | 增加模型复杂度（更多特征、更深的模型）、减少正则化强度、延长训练时间 |
| **高方差（过拟合）** | 增加训练数据量、使用正则化（L1/L2）、Dropout、早停、降低模型复杂度、[[Machine Learning#集成学习（Ensemble Learning）：Bagging vs Boosting vs Stacking\|Bagging 集成方法（如随机森林）]] |

> **考试与工程的分界**：AIF-C01 只需理解"过拟合/欠拟合"这一层现象描述即可应对大部分场景题；"偏差/方差"是更严谨的工程诊断视角——知道两者对应关系（高偏差=欠拟合，高方差=过拟合）足以应对考试中出现的相关概念题。更深入的 Bagging（降方差）vs Boosting（降偏差）工程选型讨论见 [[Machine Learning#偏差-方差权衡（Bias-Variance Tradeoff）：比"过拟合/欠拟合"更严谨的视角\|Machine Learning]]。

## 分类任务评估指标（考试重点）

### 混淆矩阵

> **混淆矩阵（Confusion Matrix）**是一张表格，用于总结**分类模型**的预测结果与真实标签之间的对应关系——它把模型"预测对了多少、预测错了多少，以及具体错在哪个方向"一次性摆出来，是几乎所有分类评估指标（Accuracy、Precision、Recall、F1、AUC-ROC）计算的**基础**。

```
                预测：正 (Positive)   预测：负 (Negative)
实际：正 (P)   TP（真正例）           FN（假负例 / 漏报）
实际：负 (N)   FP（假正例 / 误报）    TN（真负例）
```

#### 四个格子的含义（以"鱼 vs 非鱼"二元分类为例）

| 格子 | 全称 | 含义 | 示例（预测是否为鱼） |
|------|------|------|---------------------|
| **TP（True Positive，真正例）** | 真正例 | 实际为正，模型也**正确**预测为正 | 图像确实是鱼，模型也预测为"鱼" |
| **TN（True Negative，真负例）** | 真负例 | 实际为负，模型也**正确**预测为负 | 图像确实不是鱼，模型也预测为"非鱼" |
| **FP（False Positive，假正例）** | 假正例 / **误报** | 实际为负，但模型**错误**预测为正（"狼来了"型错误） | 图像不是鱼，模型却预测为"鱼" |
| **FN（False Negative，假负例）** | 假负例 / **漏报** | 实际为正，但模型**错误**预测为负（"放过了"型错误） | 图像确实是鱼，模型却预测为"非鱼" |

> **记忆技巧**：第一个词（True/False）表示**模型预测得对不对**；第二个词（Positive/Negative）表示**模型预测的类别是什么**。例如 FN = 模型预测**错**了（False），且预测的是**负类**（Negative）→ 但实际是正类，被漏掉了。

#### 为什么混淆矩阵比单一准确率更有用

- **准确率会掩盖错误的分布**：两个模型可能有相同的 Accuracy，但一个的错误全是 FP（误报），另一个全是 FN（漏报）——业务代价可能天差地别（见下方 Precision vs Recall 选择逻辑）
- **是所有分类指标的来源**：Precision（关注 FP）、Recall（关注 FN）、F1（兼顾两者）、Specificity/FPR 等指标，全部由混淆矩阵中的四个数字计算得出
- **多元分类的扩展**：对于多元分类（超过 2 个类别），混淆矩阵扩展为 **N×N 矩阵**（N=类别数），对角线上的值为各类别预测正确的数量，非对角线的值揭示模型容易把哪两个类别**混淆**（这也是"混淆矩阵"名称的由来）

| 指标 | 公式 | 重点场景 |
|------|------|---------|
| **准确率 (Accuracy)** | (TP + TN) / 总数 | 类别均衡时使用 |
| **精确率 (Precision)** | TP / (TP + FP) | 降低误报成本（垃圾邮件过滤） |
| **召回率 (Recall)** | TP / (TP + FN) | 降低漏报成本（癌症筛查） |
| **F1 分数** | 2 × P × R / (P + R) | 类别不均衡时使用，兼顾精确率和召回率（训练阶段如何处理不均衡数据本身，如 SMOTE/类别加权，见 [[Machine Learning#类别不平衡数据的处理技术\|Machine Learning]] 独立笔记） |
| **AUC-ROC** | ROC 曲线下面积（0~1） | 综合评估二分类模型整体表现 |

### 扩展分类指标

| 指标 | 公式 | 描述 |
|------|------|------|
| **假阳性率 (FPR)** | FP / (FP + TN) | 在**非鱼**图像中，被错误预测为鱼的比例 |
| **真阴性率 (TNR)** | TN / (FP + TN) | 在**非鱼**图像中，被正确预测为非鱼的比例 |

> TNR 也称为**特异性 (Specificity)**，是 FPR 的补集（TNR + FPR = 1）。

### AUC-ROC（曲线下面积）

> **AUC-ROC** 用于比较和评估返回概率的二元分类算法（如逻辑回归）在**整个阈值范围内**的综合性能。

**核心概念**：
- **阈值 (Threshold)**：将概率映射为离散预测值（如 0 或 1）的边界值
  - 示例：阈值设为 0.6 → 模型对某图像是鱼的置信度 ≥ 60% → 归为鱼
  - 阈值增大 → 假阳性率降低，但假阴性率增加
- **ROC 曲线（受试者操作特征曲线）**：以不同阈值绘制真阳性率（纵轴）vs 假阳性率（横轴）的曲线
- **AUC（曲线下面积）**：0~1 之间；**1 = 完全准确**；**0.5 ≈ 随机分类器**

### Precision vs Recall 选择逻辑

```
业务场景 → 选择侧重指标
├── "误报代价高（把正常邮件标为垃圾）" → 提高 Precision（减少 FP）
├── "漏报代价高（漏诊癌症）" → 提高 Recall（减少 FN）
└── "两者都重要，数据不均衡" → 使用 F1 分数
```

## 回归任务评估指标

| 指标 | 全称 | 描述 | 单位 |
|------|------|------|------|
| **MSE** | 均方误差 | 预测值与真实值差的**平方**均值，对异常值惩罚更重 | 因变量单位的平方（如英寸²） |
| **RMSE** | 均方根误差 | MSE 的平方根，**单位与因变量一致**，更易诠释 | 与因变量相同（如英寸） |
| **MAE** | 平均绝对误差 | 差值的**绝对值**均值，不强调异常值影响 | 与因变量相同 |
| **R²** | 决定系数 | 模型解释目标变量方差的比例（0~1，越高越好） | 无单位 |

> **选择 MSE/RMSE vs MAE**：MSE/RMSE 会强调异常值（大误差的影响更大）；若不需要强调异常值影响，使用 MAE 更合适。RMSE 比 MSE 更易理解（单位与原始数据一致）。

## NLP 评估指标（考试重点）

| 指标 | 全称 | 评估对象 | 核心原理 |
|------|------|---------|---------|
| **BLEU** | Bilingual Evaluation Understudy | 机器翻译 | 基于 n-gram 精确率匹配 |
| **ROUGE** | Recall-Oriented Understudy for Gisting Evaluation | 文本摘要 | 基于 n-gram 召回率匹配 |
| **METEOR** | Metric for Evaluation of Translation with Explicit ORdering | 翻译/摘要 | 考虑同义词、词形变化，比 BLEU 更全面 |
| **BERTScore** | — | 语义相似度 | 使用 BERT 编码器计算语义相似度（而非字面匹配） |
| **Perplexity** | 困惑度 | 语言模型质量 | 越低越好，表示模型对测试集的预测越准确 |

> **考试陷阱：BLEU vs BERTScore（机器翻译场景）**
> 题目常给出"评估翻译准确性，选哪个指标"，并把 **BERTScore** 作为干扰项——BERTScore 确实更"先进"（基于 BERT 上下文嵌入衡量语义相似度），但 **BLEU 才是机器翻译任务事实上的行业标准指标**，题目默认选 BLEU：
>
> - **BLEU**：基于 **n-gram 精确率**匹配，将机器翻译与一个或多个人工参考翻译比较，得分范围 **0~1**，越高越接近参考翻译，广泛用于翻译质量评估（如 Amazon Translate 的 Active Custom Translation）。
> - **BERTScore**：使用 BERT 编码器计算**语义相似度**而非字面 n-gram 重叠，理论上能捕捉同义改写，但在翻译评估场景中**不如 BLEU 常用/标准化**。
> - **Accuracy（准确率）**：不适用于翻译——翻译是生成任务而非分类任务，无法用"是否命中标签"衡量语法和语义的正确性。
> - **ROUGE**：面向**文本摘要**（召回率导向），不是为翻译设计的。
>
> **记忆技巧**：翻译 → **BLEU**（Bilingual）；摘要 → **ROUGE**（Gisting/摘要）；语义相似度的新兴/进阶指标 → **BERTScore**，但传统选择题里"翻译质量"默认答案仍是 BLEU。

### LLM 专用评估指标

| 指标 | 描述 |
|------|------|
| **事实性 (Factuality)** | 输出是否与事实相符（对抗幻觉） |
| **相关性 (Relevance)** | 回答是否与问题相关 |
| **连贯性 (Coherence)** | 输出文本逻辑是否连贯 |
| **毒性 (Toxicity)** | 输出是否包含有害内容 |

## 图像/生成模型评估指标

| 指标 | 描述 | 越高/低越好 |
|------|------|-----------|
| **PSNR（峰值信噪比）** | 衡量图像重建质量，信号与噪声的比率 | 越高越好 |
| **SSIM（结构相似性）** | 从亮度、对比度、结构三个维度评估图像相似度 | 越高越好（最大值 1） |
| **IoU（交并比）** | 目标检测中预测框与真实框的重叠程度 | 越高越好（最大值 1） |
| **Inception Score** | 评估 GAN 生成图像的真实感与多样性 | 越高越好 |
| **FID（Fréchet Inception Distance）** | 评估真实图像与生成图像的分布距离 | 越低越好 |

## 模型可诠释性（Model Interpretability）（考试重点）

> **模型可诠释性**是指人们能够理解模型预测背后原因的程度。可诠释性越高，越容易理解；但**准确性与可诠释性之间存在权衡**——复杂模型通常准确率更高，但可解释性更低。

### 两类可诠释性方法

| 方法类型 | 适用模型 | 说明 |
|---------|---------|------|
| **内在分析 (Intrinsic)** | 简单模型（线性回归、决策树） | 模型本身结构简单，输入→输出关系直接可读 |
| **事后分析 (Post-hoc)** | 复杂模型（神经网络、集成模型） | 训练完成后，使用外部工具诠释模型行为 |

### 内在分析 vs 事后分析

| 维度 | 内在分析 | 事后分析 |
|------|---------|---------|
| **模型复杂度** | 低（线性关系、简单规则） | 可高（能诠释神经网络） |
| **捕获非线性** | 难以捕获复杂非线性交互 | 可以（神经网络可捕获） |
| **分析粒度** | 全局（整体模型行为） | 本地级别（单个数据点）/ 全局级别（整体行为） |
| **方法无关性** | 依赖模型结构 | 通常**与模型无关**，可应用于多种模型 |

### 事后分析的两个粒度

| 粒度 | 说明 |
|------|------|
| **本地（Local）** | 放大单个数据点，解释**某条具体预测**为什么得出该结果 |
| **全局（Global）** | 缩小视角，查看模型**整体行为规律** |

> **AWS 工具**：**Amazon SageMaker Clarify** 提供事后可解释性分析，包括特征重要性（Feature Importance）和偏见检测。

### 可诠释性 vs 准确性权衡

```
准确性高 ←───────────────────────────→ 可诠释性高
神经网络 / 集成模型               线性回归 / 决策树
（复杂，难以解释）                  （简单，易于解释）
        ↑                               ↑
   高预测能力                      合规审计要求
   非线性捕获                      贷款审批解释
```

> **合规性要求**：在贷款审批、医疗诊断等高风险场景中，监管要求可解释模型；此时应选择简单模型或基于规则的系统，即使牺牲部分准确率。

## 生成式 AI 业务指标（Task Statement 2.2）

> 基础模型和生成式 AI 应用程序需要用业务指标来衡量其影响和价值。

| 业务指标 | 说明 |
|---------|------|
| **跨域性能** | 知识和技能在不同领域的迁移和应用效果 |
| **效率** | 任务完成率、减少人工工作量 |
| **转化率** | AI 推荐/内容带来的业务转化提升 |
| **客户生命周期值 (CLTV)** | AI 个性化体验对客户长期价值的影响（忠诚度、交叉销售） |
| **准确率** | 模型输出正确性 |
| **每位用户平均收入 (ARPU)** | 生成式 AI 带来的收入增长 |

### 输出质量指标

| 指标 | 说明 |
|------|------|
| **相关性 (Relevance)** | 输出是否与问题/需求相关 |
| **准确率 (Accuracy)** | 输出是否事实正确 |
| **连贯性 (Coherence)** | 输出文本逻辑是否连贯 |
| **适当性 (Appropriateness)** | 输出是否符合场景和受众 |

> **AWS 业务指标分析**：**Amazon Lookout for Metrics** + **Amazon Forecast** 组合，使用 ML 分析大量业务数据，动态适应不断变化的业务需求，检测异常值并了解根本原因。

## 业务指标与 ROI

> ML 解决方案必须能够解决业务问题。**业务指标**帮助量化 ML 模型带来的实际业务价值，而非仅关注技术指标。

### 业务指标类型

| 指标类型 | 示例 |
|---------|------|
| **成本降低** | 欺诈减少节省的金额、运营效率提升 |
| **增长指标** | 用户增长 %、销售额增长 % |
| **客户体验** | 基于客户反馈的可衡量改善 |
| **风险量化** | 错误预测的潜在成本（如客户流失、销售额下降） |

### 投资回报率 (ROI) 计算

```
模型上线后 → 收集实际业务数据 → 与初始业务目标比较
         ↓
实际收益（节省/增长）- 构建和运营模型的成本 = ROI
```

### AWS 成本追踪工具

- **成本分配标签**：为 ML 项目使用的所有 AWS 资源添加标签（如标签 key=`project`，value=`fraud-detection`）
- **AWS Cost Explorer**：按标签筛选成本报告，确定特定 ML 项目产生的实际 AWS 费用

## 考试重点总结

### AIF-C01 高频考点

1. **数据集划分**：训练集（学习）/ 验证集（调参）/ 测试集（最终评估），建议 80/10/10
2. **参数 vs 超参数**：自动学习 vs 手动设置
3. **过拟合 vs 欠拟合**：通过训练集/测试集表现差距判断；过拟合最佳修复 = 多样化训练数据
4. **偏差 vs 方差**：高偏差=欠拟合（模型太简单）；高方差=过拟合（对训练噪声过度敏感）；两者此消彼长，需找平衡点
5. **混淆矩阵四格**：TP/TN/FP/FN 及各自含义（鱼/非鱼示例）
6. **准确率局限性**：数据不均衡时无效（模型全预测为正类仍可得高准确率）
7. **Precision vs Recall**：减少 FP 用 Precision；减少 FN 用 Recall；两者平衡用 F1
8. **AUC-ROC**：二元分类综合指标；1=完全准确，0.5=随机；阈值影响 FPR/FNR 权衡
9. **MSE vs RMSE vs MAE**：MSE/RMSE 强调异常值；MAE 不强调；RMSE 单位与原始数据一致
10. **BLEU**：评估机器翻译质量（对比人工翻译）；**ROUGE**：评估文本摘要质量（对比参考摘要）；**BERTScore** 虽更先进（语义相似度）但翻译场景仍以 BLEU 为标准答案
11. **实时推理 vs 批处理**：资源始终运行 vs 按需启停
12. **模型构件**：参数 + 模型定义 + 元数据，存储于 Amazon S3
13. **可诠释性权衡**：准确性↑ ↔ 可诠释性↓；合规要求高时选简单模型/规则系统
14. **内在 vs 事后分析**：内在=简单模型本身可读；事后=外部工具诠释复杂模型（本地/全局）
15. **SageMaker Clarify**：特征重要性 + 偏见检测（事后可解释性工具）
16. **生成式 AI 输出质量**：相关性 / 准确率 / 连贯性 / 适当性
17. **CLTV（客户生命周期值）**：忠诚度计划、交叉销售、个性化体验
18. **Lookout for Metrics + Forecast**：AWS 业务指标异常检测和预测
19. **业务指标**：成本降低、增长 %、客户反馈改善；ROI = 收益 - 成本
20. **AWS Cost Explorer + 成本分配标签**：追踪 ML 项目实际 AWS 费用

### 场景题解题思路

```
场景分析 → 选择评估指标
├── "评估机器翻译质量" → BLEU
├── "评估文本摘要质量" → ROUGE
├── "类别严重不均衡的分类问题" → F1 分数
├── "癌症筛查，不能漏诊" → 最大化 Recall
├── "垃圾邮件过滤，不能误判" → 最大化 Precision
├── "评估图像生成质量" → PSNR / SSIM / FID
└── "目标检测预测框准确度" → IoU（交并比）
```
