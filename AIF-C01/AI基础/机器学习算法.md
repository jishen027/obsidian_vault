## 监督学习算法

### 回归 (Regression)

> **回归** 是找到一个函数，将标签数据集映射到连续变量（数值）的过程。

| 特性 | 描述 |
|------|------|
| **输出类型** | 连续数值（如价格、温度、销量） |
| **典型场景** | 房价预测、天气预测、股价预测 |
| **常见算法** | 线性回归、多项式回归、Ridge/Lasso |

### 分类 (Classification)

> **分类** 是将输入分配到预定义类别的过程。

| 特性 | 描述 |
|------|------|
| **输出类型** | 离散类别（如猫/狗/鸟、垃圾邮件/正常） |
| **典型场景** | 图像分类、垃圾邮件过滤、医疗诊断 |
| **常见算法** | 逻辑回归、SVM、决策树、随机森林 |

### 回归 vs 分类（考试高频对比）

| 特性 | 回归 | 分类 |
|------|------|------|
| **预测目标** | 连续数值 | 离散类别 |
| **输出示例** | 价格 $350,000 | 猫 / 狗 / 鸟 |
| **评估指标** | MSE、RMSE、R² | 准确率、F1、AUC |
| **典型算法** | 线性回归 | 逻辑回归、SVM |

### K 近邻 (KNN)

> **KNN** 本身不是 ML，但当应用于解决 ML 问题时成为 ML 算法。通过找到"最近的 K 个邻居"来预测。

- 适用于分类和回归
- 计算简单，无需训练阶段
- 对高维数据效率较低

## 无监督学习算法

### 聚类 (Clustering)

> 将相似的数据点分组，无需预先知道分组标准。

| 算法 | 特点 | 场景 |
|------|------|------|
| **K-Means** | 将数据分为 K 个簇，迭代更新中心点 | 客户分群、文档聚类 |
| **层次聚类** | 构建树形结构的聚类层次 | 基因数据分析 |
| **DBSCAN** | 基于密度，能发现任意形状的簇 | 异常检测、地理数据 |

### 关联规则 (Association)

> 发现数据中共现的规律，即"经常一起出现的事物"。

- **典型场景**：购物篮分析（买尿布的人也买啤酒）
- **核心指标**：支持度（Support）、置信度（Confidence）、提升度（Lift）
- **典型算法**：Apriori、FP-Growth

### 降维 (Dimensionality Reduction)

> 在保持数据核心信息的前提下，减少特征（维度）数量，常用于数据预处理阶段。

| 算法 | 全称 | 特点 |
|------|------|------|
| **PCA** | 主成分分析 | 最常用，线性降维 |
| **LDA** | 线性判别分析 | 考虑类别标签的降维 |
| **SVD** | 奇异值分解 | 矩阵分解，用于推荐系统 |

## 强化学习

> **强化学习**：Agent 在 Environment 中执行 Action，根据 Reward/Penalty 反馈学习最优 Policy。

```
Agent → Action → Environment → Reward/Penalty → Agent (学习更新)
```

| 组成 | 描述 |
|------|------|
| **Agent** | 执行决策的学习主体 |
| **Environment** | Agent 交互的环境 |
| **Action** | Agent 可以执行的操作 |
| **Reward** | 环境对 Action 的正向反馈 |
| **Penalty** | 环境对 Action 的负向反馈 |
| **Policy** | Agent 的决策策略（输入状态 → 输出动作） |

- **典型场景**：游戏 AI（围棋 AlphaGo）、机器人控制、自动驾驶
- **与 Agentic AI 的关联**：Bedrock Agents 的设计理念借鉴了强化学习中 Agent 的概念

## 模型参数与超参数

> 理解训练时调整的参数是理解 ML 流程的基础。

| 概念 | 定义 | 由谁决定 |
|------|------|---------|
| **参数 (Parameters)** | 模型内部权重，训练过程中自动学习 | 模型训练自动更新 |
| **超参数 (Hyperparameters)** | 训练前手动设置的配置项 | 工程师手动设定 |

### 关键超参数

| 超参数 | 描述 | 影响 |
|--------|------|------|
| **学习率 (Learning Rate)** | 每次更新权重的步长大小 | 过大→不收敛，过小→训练慢 |
| **Epoch** | 训练数据集被完整遍历的次数 | 过多→过拟合，过少→欠拟合 |
| **批大小 (Batch Size)** | 每次更新权重使用的样本数 | 影响训练速度和内存占用 |

### SageMaker 自动调参

- **SageMaker Automatic Model Tuning**（也称超参数调优）
- 自动搜索最优超参数组合
- 可使用 Spot 实例节省成本
- 适用于内置算法、自定义算法、预构建容器

## 过拟合与欠拟合（考试重点）

| 状态 | 描述 | 表现 | 解决方案 |
|------|------|------|---------|
| **过拟合 (Overfitting)** | 模型过度学习训练数据的噪声 | 训练集准确高，测试集准确低 | 增加数据、正则化、Dropout、减少模型复杂度 |
| **欠拟合 (Underfitting)** | 模型过于简单，无法捕捉规律 | 训练集和测试集准确都低 | 增加模型复杂度、增加训练时间、特征工程 |
| **泛化良好** | 在未见数据上也有良好表现 | 训练集和测试集准确相近 | 目标状态 |

```
场景分析 → 诊断模型问题
├── "训练好，测试差" → 过拟合 → 正则化、更多数据
├── "训练和测试都差" → 欠拟合 → 增加模型复杂度
└── "训练和测试都好" → 泛化良好 ✅
```

## 考试重点总结

### AIF-C01 高频考点

1. **监督学习**：回归（连续数值）vs 分类（离散类别）
2. **无监督学习**：聚类（分群）、关联（共现规律）、降维（减少特征）
3. **强化学习**：Agent + Environment + Reward 机制
4. **超参数 vs 参数**：手动设置 vs 自动学习
5. **过拟合 vs 欠拟合**：训练集/测试集性能差距

### 场景题解题思路

```
场景分析 → 选择算法类型
├── "预测未来价格/数量" → 回归
├── "识别属于哪个类别" → 分类
├── "将客户自动分组" → 聚类（无监督）
├── "发现商品关联规律" → 关联规则
├── "减少数据维度" → 降维（PCA）
└── "Agent 学习最优策略" → 强化学习
```
