## ML 问题类型识别框架（考试重点）

> 拿到一个 ML 问题，先判断数据集是否有标签，再判断目标值类型。

```
数据集是否包含标签（目标值）？
├── 有标签（有监督学习）
│   ├── 目标值是离散分类？ → 分类问题 (Classification)
│   │   ├── 两个互斥类别？ → 二元分类 (Binary)
│   │   └── 多个类别？ → 多元分类 (Multi-class)
│   └── 目标值是连续数值？ → 回归问题 (Regression)
│       ├── 预测连续值（线性关系）→ 线性回归
│       └── 预测事件概率（0~1）→ 逻辑回归
└── 无标签（无监督学习）
    ├── 将数据分成离散组？ → 聚类 (Clustering)
    └── 发现数据中的异常值？ → 异常检测 (Anomaly Detection)
```

## 监督学习算法

### 回归 (Regression)

> **回归** 是根据一个或多个与因变量相关的其他变量/属性，来估算因变量（目标变量）值的过程。目标值在数学上是**连续的**。

| 特性 | 描述 |
|------|------|
| **输出类型** | 连续数值（如价格、温度、销量） |
| **典型场景** | 房价预测、天气预测、股价预测 |
| **常见算法** | 线性回归、多项式回归、Ridge/Lasso |

#### 回归类型对比

| 类型 | 自变量数量 | 输出 | 示例 |
|------|----------|------|------|
| **简单线性回归** | 1 个 | 连续值 | 用**体重**预测**身高** |
| **多元线性回归** | 多个 | 连续值 | 用**体重 + 年龄**预测身高；用**卧室数、浴室数、面积**预测房价 |
| **逻辑回归** | 1 个或多个 | 概率（0~1） | 用 BMI + 吸烟状况 + 遗传倾向预测是否患心脏病；预测金融交易是否为欺诈 |

#### 逻辑回归（Logistic Regression）

> **逻辑回归**用于衡量事件发生的概率，使用对数函数计算回归线，输出介于 **0 和 1 之间**。

- **0** → 事件不太可能发生
- **1** → 事件最有可能发生
- 尽管名称包含"回归"，但实际上用于**分类**（预测概率后设置阈值判断类别）
- 示例 1：根据 BMI、吸烟状况、遗传倾向 → 预测一个人是否会患心脏病
- 示例 2：根据交易特征 → 预测金融交易是否为欺诈（训练数据标注为"欺诈"/"非欺诈"）

> 线性回归和逻辑回归都需要**大量标注数据**才能确保模型预测的准确率。

#### 线性回归训练示例

> **线性回归**：寻找与输入数据最佳拟合的直线，找到自变量与因变量之间的线性关系。

**方程**：`y = mx + b`（例：`身高 = m × 体重 + b`）

| 元素 | 含义 | 由谁决定 |
|------|------|---------|
| `m`（斜率） | 模型参数，决定直线倾斜程度 | 训练中迭代自动学习 |
| `b`（截距） | 模型参数，决定直线与纵轴的交点 | 训练中迭代自动学习 |
| `x`（输入特征） | 自变量（如体重） | 输入数据提供 |
| `y`（预测输出） | 因变量（如身高） | 模型计算输出 |

**训练目标**：找到使**误差最小化**的 `m` 和 `b` 值——误差即数据点与直线之间的距离（残差）。

```
训练过程
→ 初始化参数 m, b
→ 前向传播：计算预测值 ŷ = mx + b
→ 计算误差（预测值与真实值的差距）
→ 反向传播：调整 m 和 b 减小误差
→ 重复迭代，直到误差收敛（最佳拟合）
→ 推理：用训练好的 m, b 对新输入 x 预测 y
```

### 分类 (Classification)

> **分类** 是将输入分配到预定义类别（离散值）的过程。

| 特性 | 描述 |
|------|------|
| **输出类型** | 离散类别（如猫/狗/鸟、垃圾邮件/正常） |
| **典型场景** | 图像分类、垃圾邮件过滤、医疗诊断 |
| **常见算法** | 逻辑回归、SVM、决策树、随机森林 |

#### 二元分类 vs 多元分类

| 类型 | 描述 | 示例 |
|------|------|------|
| **二元分类 (Binary)** | 将输入分配到**两个**互斥预定义类别之一 | 根据诊断测试判断是否患病（患病/未患病）；鱼 vs 非鱼 |
| **多元分类 (Multi-class)** | 将输入分配到**多个**类别之一 | 预测文本文档的主题（宗教/政治/金融/其他）；识别多种海洋生物类别 |

### 回归 vs 分类（考试高频对比）

| 特性 | 回归 | 分类 |
|------|------|------|
| **预测目标** | 连续数值 | 离散类别 |
| **输出示例** | 价格 $350,000 | 猫 / 狗 / 鸟 |
| **评估指标** | MSE、RMSE、R² | 准确率、F1、AUC |
| **典型算法** | 线性回归 | 逻辑回归、SVM |

### K 近邻 (KNN)

> **KNN** 本身不是 ML，但当应用于解决 ML 问题时成为 ML 算法。通过找到"最近的 K 个邻居"来预测。

- 适用于分类和回归
- 计算简单，无需训练阶段
- 对高维数据效率较低

## 无监督学习算法

### 聚类 (Clustering)

> **聚类**是将数据对象分为称为"聚类"的组的分类技术。组内成员尽可能彼此相似，与其他组成员尽可能不同。

**配置聚类需要定义**：
1. 用于确定相似性的**特征或属性**
2. 衡量相似性的**距离函数**
3. 要分析的**聚类数量**

| 算法 | 特点 | 场景 |
|------|------|------|
| **K-Means** | 将数据分为 K 个簇，迭代更新中心点 | 客户分群、文档聚类 |
| **层次聚类** | 构建树形结构的聚类层次 | 基因数据分析 |
| **DBSCAN** | 基于密度，能发现任意形状的簇 | 异常检测、地理数据 |

- **示例**：按购买历史记录或点击流活动将客户分组

### 异常检测 (Anomaly Detection)

> **异常检测**识别数据中会引起怀疑的小概率项目、事件或观测结果，因为它们与其余数据存在显著差异。

| 特性 | 描述 |
|------|------|
| **学习类型** | 无监督学习（无需标注，模型学习正常模式后检测偏差） |
| **输出** | 标记出异常值/异常事件 |
| **典型场景** | 欺诈检测、设备传感器故障、医疗失误检测、网络安全入侵 |

- **示例 1**：识别传感器报告数据远超正常范围 → 判断传感器可能出现故障
- **示例 2**：网络流量聚类后发现异常流量 → 预测潜在安全事件

### 关联规则 (Association)

> 发现数据中共现的规律，即"经常一起出现的事物"。

- **典型场景**：购物篮分析（买尿布的人也买啤酒）
- **核心指标**：支持度（Support）、置信度（Confidence）、提升度（Lift）
- **典型算法**：Apriori、FP-Growth

### 降维 (Dimensionality Reduction)

> 在保持数据核心信息的前提下，减少特征（维度）数量，常用于数据预处理阶段。

| 算法 | 全称 | 特点 |
|------|------|------|
| **PCA** | 主成分分析 | 最常用，线性降维 |
| **LDA** | 线性判别分析 | 考虑类别标签的降维 |
| **SVD** | 奇异值分解 | 矩阵分解，用于推荐系统 |

## 自监督学习 (Self-Supervised Learning)

> **自监督学习**：从**无标签数据**中自动生成"伪标签"（pseudo-labels），让模型通过预测数据本身被遮盖/缺失的部分来学习特征表示——本质上是"用监督学习的训练方式，但标签来自数据本身，而非人工标注"。

| 特性 | 描述 |
|------|------|
| **数据要求** | 无需人工标注，直接使用海量原始无标签数据 |
| **核心思路** | 遮盖/隐藏数据的一部分（如遮住单词、图像块），训练模型预测被遮盖的内容 |
| **典型任务** | 掩码语言建模（Masked Language Modeling）、下一词元预测（Next Token Prediction）、图像修复/上色 |
| **典型场景** | 大语言模型（LLM）等**基础模型（Foundation Model）预训练**、图像/语音表示学习 |

#### 三种学习范式对比

| 特性 | 监督学习 | 无监督学习 | 自监督学习 |
|------|---------|-----------|-----------|
| **标签来源** | 人工标注 | 无标签 | 从数据本身自动生成 |
| **目标** | 预测已知标签 | 发现数据结构/模式 | 学习通用特征表示 |
| **典型算法/应用** | 回归、分类 | 聚类、降维 | LLM/基础模型预训练（如 GPT、BERT） |

- **示例**：训练大语言模型时，遮盖句子中的某个词，让模型根据上下文预测被遮盖的词——标签（被遮盖的词）来自句子本身，无需人工标注
- **考试关联**：基础模型的**预训练**阶段通常采用自监督学习（海量无标注文本/图像）；随后的**微调（Fine-tuning）**阶段通常采用监督学习（少量人工标注的任务数据）。区分这两个阶段用的学习范式是 AIF-C01 生成式 AI 相关题目的常见考点

## 强化学习

> **强化学习（Reinforcement Learning, RL）**：与监督/无监督学习不同，RL **没有预先准备好的"数据集"**——Agent 通过**不断试错（trial and error）**，在与环境的持续交互中积累经验，根据 Reward/Penalty 反馈自主学习一套能**最大化长期累积奖励**的行为策略（Policy）。

### 核心循环与关键概念

```
     ┌────────────────────────────────────┐
     │                                    │
     ▼                                    │
  Agent ──Action(a)──▶ Environment        │
     ▲                     │              │
     │                     ▼              │
     └──Reward(r), 新 State(s')───────────┘
```

| 组成 | 描述 |
|------|------|
| **Agent** | 执行决策的学习主体（例：游戏中的玩家、机器人、自动驾驶控制器） |
| **Environment** | Agent 交互的外部世界，接收 Action 并返回新的 State 和 Reward |
| **State (状态)** | Environment 在某一时刻的具体情况，是 Agent 决策的输入 |
| **Action (动作)** | Agent 在当前状态下可以执行的操作 |
| **Reward / Penalty** | 环境对 Action 的**正向/负向数值反馈**，用于评价该动作的好坏 |
| **Policy (策略)** | Agent 的决策函数：输入 State → 输出 Action，训练的最终产物就是一个好的 Policy |
| **Value Function（价值函数）** | 评估某个状态（或状态-动作对）未来能带来多少**累积奖励**，帮助 Agent 判断"长远是否值得" |

- **与监督学习的关键区别**：监督学习有"标准答案"（标签）逐条纠错；强化学习**没有标签**，只有滞后的、稀疏的 Reward 信号——Agent 要自己通过尝试发现"什么样的动作序列能带来高奖励"
- **延迟奖励（Delayed Reward）**：很多场景下 Reward 不是立即给出的（例如下棋，只有赢/输时才有明确反馈），Agent 需要学会将最终结果"归因"到中间的一系列动作上

### 探索与利用（Exploration vs. Exploitation）

> 这是强化学习特有的核心矛盾，也是与其他学习范式最大的区别之一。

| 策略 | 含义 | 风险 |
|------|------|------|
| **利用（Exploitation）** | 选择当前已知**回报最高**的动作 | 可能错过更优但尚未尝试过的动作，陷入局部最优 |
| **探索（Exploration）** | 尝试**未知或较少尝试过**的动作，收集更多信息 | 短期内可能获得较低甚至负向的奖励 |

- **示例**：一个推荐系统 Agent 是应该一直推荐用户点击率最高的内容（利用），还是偶尔推荐一些新内容来了解用户的其他兴趣（探索）？——好的 RL 策略需要在两者间权衡（常见方法如 ε-greedy：以较小概率 ε 随机探索，其余时候利用已知最优动作）

### 强化学习的训练过程（考试关注点：无需数据集，靠试错积累经验）

```
初始化 Policy（通常随机）
→ Agent 观察当前 State
→ 根据 Policy 选择一个 Action（可能探索，也可能利用）
→ Environment 反馈 Reward/Penalty，并转移到新 State
→ Agent 根据反馈更新 Policy / Value Function（学习"这个动作好不好"）
→ 重复大量回合（Episode），逐步改进 Policy
→ 收敛：Agent 学到能最大化长期累积奖励的最优 Policy
```

- **典型场景**：游戏 AI（围棋 AlphaGo、Atari 游戏）、机器人控制、自动驾驶、动态定价、资源调度优化
- **AWS 相关服务/案例**：**AWS DeepRacer**（通过强化学习训练自动驾驶模型赛车，是 AWS 官方用于教学 RL 概念的经典示例）；Amazon SageMaker 支持 RL 训练工作负载

### RLHF（Reinforcement Learning from Human Feedback）—— 与生成式 AI 的关键交叉点

> **RLHF** 是强化学习在大语言模型微调阶段的重要应用，是 AIF-C01 生成式 AI 考点中强化学习的高频结合点。

| 步骤 | 说明 |
|------|------|
| **1. 预训练基础模型** | 通常使用[[#自监督学习 (Self-Supervised Learning)]]在海量无标注文本上完成 |
| **2. 收集人类偏好数据** | 人类标注员对模型生成的多个候选回答进行**排序/打分**（哪个回答更好） |
| **3. 训练奖励模型（Reward Model）** | 用人类偏好数据训练一个模型，使其能够**给任意回答打分**，模拟人类偏好，替代人类持续参与后续训练 |
| **4. 强化学习微调** | 把奖励模型的打分作为 **Reward**，通过强化学习算法（如 PPO）微调语言模型，使其生成的内容更符合人类偏好（更有帮助、更安全、更符合人类价值观） |

- **本质**：把"生成的文本是否让人满意"这一难以直接用损失函数表达的目标，转化为强化学习中的 **Reward 信号**，让模型通过强化学习的方式对齐（Align）人类偏好
- **考试关联**：RLHF 常用于提升基础模型的**有用性（Helpfulness）**和**安全性（Safety）**，是模型对齐（Alignment）技术的代表性方法之一

### 强化学习 vs 其他学习范式（对比速查）

| 特性 | 监督学习 | 无监督学习 | 自监督学习 | 强化学习 |
|------|---------|-----------|-----------|---------|
| **是否需要数据集** | 需要（含标签） | 需要（无标签） | 需要（无标签，自动生成伪标签） | **不需要预先准备的数据集**，通过与环境交互产生经验 |
| **反馈信号** | 每个样本都有明确标签 | 无反馈信号 | 数据自身提供的伪标签 | 延迟、稀疏的 Reward/Penalty |
| **学习目标** | 最小化预测误差 | 发现数据结构 | 学习通用特征表示 | 最大化**长期累积奖励** |
| **典型产物** | 分类器/回归模型 | 聚类结果/降维表示 | 预训练基础模型 | 最优策略（Policy） |

- **与 Agentic AI 的关联**：Bedrock Agents 等 Agentic AI 系统的设计理念借鉴了强化学习中 "Agent 感知环境 → 决策 → 行动 → 获得反馈" 的循环范式，但 Agentic AI 中的 Agent 通常依赖预训练好的基础模型做推理决策，并不一定在生产环境中持续做强化学习训练

## 模型参数与超参数

> 理解训练时调整的参数是理解 ML 流程的基础。

| 概念 | 定义 | 由谁决定 |
|------|------|---------|
| **参数 (Parameters)** | 模型内部权重，训练过程中自动学习 | 模型训练自动更新 |
| **超参数 (Hyperparameters)** | 训练前手动设置的配置项 | 工程师手动设定 |

### 关键超参数

| 超参数                     | 描述            | 影响            |
| ----------------------- | ------------- | ------------- |
| **学习率 (Learning Rate)** | 每次更新权重的步长大小   | 过大→不收敛，过小→训练慢 |
| **Epoch**               | 训练数据集被完整遍历的次数 | 过多→过拟合，过少→欠拟合 |
| **批大小 (Batch Size)**    | 每次更新权重使用的样本数  | 影响训练速度和内存占用   |

### SageMaker 自动调参

- **SageMaker Automatic Model Tuning**（也称超参数调优）
- 自动搜索最优超参数组合
- 可使用 Spot 实例节省成本
- 适用于内置算法、自定义算法、预构建容器

## 过拟合与欠拟合（考试重点）

| 状态 | 描述 | 表现 | 解决方案 |
|------|------|------|---------|
| **过拟合 (Overfitting)** | 模型过度学习训练数据的噪声 | 训练集准确高，测试集准确低 | 增加数据、正则化、Dropout、减少模型复杂度 |
| **欠拟合 (Underfitting)** | 模型过于简单，无法捕捉规律 | 训练集和测试集准确都低 | 增加模型复杂度、增加训练时间、特征工程 |
| **泛化良好** | 在未见数据上也有良好表现 | 训练集和测试集准确相近 | 目标状态 |

```
场景分析 → 诊断模型问题
├── "训练好，测试差" → 过拟合 → 正则化、更多数据
├── "训练和测试都差" → 欠拟合 → 增加模型复杂度
└── "训练和测试都好" → 泛化良好 ✅
```

## AI 工程师进阶内容（超出 AIF-C01 考纲）

> **AIF-C01 只要求知道"这类算法解决什么问题"，不要求理解内部机制**。但如果你的目标不只是通过考试，而是要实际训练、调优、诊断模型，就需要理解算法**为什么**这样工作。本节补齐前文提到但未展开的算法（决策树、随机森林、SVM、Ridge/Lasso）的内部机制，以及模型训练中真正会用到的工程决策。**这部分内容不会出现在 AIF-C01 考试中**，是面向 AI/ML 工程师视角的补充。

### 决策树（Decision Tree）：分裂准则

> 决策树通过一系列"是/否"问题递归地把数据切分成更"纯"的子集，直到满足停止条件。

| 分裂准则                                 | 说明                                                   |
| ------------------------------------ | ---------------------------------------------------- |
| **基尼不纯度（Gini Impurity）**             | 衡量一个节点中样本被随机分类错误的概率，**越低越纯**，是 CART 算法的默认准则，计算比信息增益快 |
| **信息增益（Information Gain / Entropy）** | 基于信息论的"熵"，衡量分裂前后不确定性的减少量，**熵越低越纯**                   |
| **停止条件**                             | 达到最大深度、节点样本数低于阈值、纯度已足够高                              |

- **优点**：天然可解释（对应模型训练与评估笔记中的"内在分析"）、无需特征缩放、能处理非线性关系
- **缺点**：**极易过拟合**（单棵树容易记住训练数据的噪声）、对数据微小变化敏感（不稳定），这正是引入**集成学习**的动机

### 集成学习（Ensemble Learning）：Bagging vs Boosting vs Stacking

> 单个模型（尤其是决策树）容易在**偏差**或**方差**上有明显短板，集成学习通过组合多个模型来弥补这一短板。

| 方法 | 核心思路 | 主要解决 | 代表算法 |
|------|---------|---------|---------|
| **Bagging（装袋）** | 对训练集做**有放回随机抽样**（Bootstrap）生成多个子集，并行训练多棵树，最终**投票/平均**结果；每次分裂还随机抽取部分特征 | **降低方差**（缓解过拟合） | **随机森林（Random Forest）** |
| **Boosting（提升）** | **串行**训练多个弱学习器，每一个新模型重点学习**前一个模型预测错误**的样本（拟合残差） | **降低偏差**（提升整体准确率） | AdaBoost、Gradient Boosting、**XGBoost**、LightGBM |
| **Stacking（堆叠）** | 训练多个**不同类型**的基础模型，再用一个**元模型（Meta-Model）**学习如何组合这些基础模型的预测 | 融合多种模型的互补优势 | 任意基础模型 + 元模型组合 |

> **工程实践提示**：**随机森林通常比单棵决策树更稳健、更不容易过拟合**（因为 Bagging 平均掉了单棵树的方差）；**Boosting 系列（尤其 XGBoost）在结构化表格数据上通常有更高的准确率上限**，但训练是串行的、更容易过拟合，需要更仔细地调参（学习率、树的数量、树的深度）。这也是"随机森林 vs 梯度提升树"在实际项目选型时的核心权衡。

### 支持向量机（SVM）：间隔最大化与核技巧

- **核心思想**：寻找一个能把不同类别**分得最开**的决策边界（超平面），边界的位置由离它最近的少数样本点（**支持向量，Support Vectors**）决定，其余样本点不影响边界位置
- **核技巧（Kernel Trick）**：当数据在原始空间中**线性不可分**时，通过核函数（线性核、多项式核、**RBF/高斯核**）把数据映射到更高维空间，使其在高维空间中变得线性可分，而**无需显式计算**高维坐标（计算效率的关键）
- **特点**：在高维/小样本数据上效果好；对特征缩放敏感（使用前通常需要标准化）；数据量很大时训练较慢

### 正则化的数学直觉：L1（Lasso）vs L2（Ridge）

> 前文"回归"表格中提到的 **Ridge/Lasso** 是线性回归加上正则化项的变体，用于**惩罚过大的模型权重**，缓解过拟合。

| 正则化方式 | 惩罚项 | 效果 | 典型用途 |
|-----------|--------|------|---------|
| **L2（Ridge）** | 权重**平方和** | 让权重整体**趋近于 0 但很少精确为 0** | 存在多重共线性、希望保留所有特征但降低其影响 |
| **L1（Lasso）** | 权重**绝对值和** | 能把不重要特征的权重**精确压缩为 0** | 需要**自动特征选择**、假设只有少数特征真正重要 |
| **Elastic Net** | L1 + L2 的加权组合 | 兼顾两者效果 | 特征数远大于样本数、特征间存在相关性 |

> **考试与工程的分界**：AIF-C01 只要求知道"正则化用于缓解过拟合"（模型训练与评估笔记已覆盖）；**L1 会产生稀疏解（自动特征选择）而 L2 不会**，是实际调参和特征工程时才需要用到的区分依据。

### 偏差-方差权衡（Bias-Variance Tradeoff）：比"过拟合/欠拟合"更严谨的视角

```
模型总误差 ≈ 偏差² (Bias²) + 方差 (Variance) + 不可约误差 (Irreducible Error)

高偏差（欠拟合）：模型假设过于简单，无法捕捉数据规律，训练集和测试集误差都高
高方差（过拟合）：模型对训练数据的微小波动过度敏感，训练集误差低但测试集误差高
```

- **Bagging（如随机森林）主要降低方差**：多棵树平均后，个别树的随机波动被抵消
- **Boosting（如 XGBoost）主要降低偏差**：串行纠正前序模型的系统性错误
- **工程实践提示**：诊断模型问题时，"过拟合/欠拟合"是**现象**，"高方差/高偏差"是**成因**——两者是同一件事的不同描述层次，考试层面理解"现象+解决方案"已足够，工程调参时理解"成因"能更精准地选择该用 Bagging 还是 Boosting、该加数据还是该加复杂度。

### 梯度下降的变体与优化器

> 前文线性回归训练示例中的"梯度下降"只是最基础的形式，实际工程中通常使用以下变体：

| 变体 | 每次更新使用的数据量 | 特点 |
|------|---------------------|------|
| **批量梯度下降（Batch GD）** | **全部**训练数据 | 梯度方向稳定，但每步计算成本高，数据量大时不可行 |
| **随机梯度下降（SGD）** | **单个**样本 | 更新快、有噪声（可能帮助跳出局部最优），但收敛路径震荡 |
| **小批量梯度下降（Mini-batch GD）** | 一小批样本（如 32/64/128） | **工程实践中最常用**，在稳定性和效率之间取得平衡 |

- **常见优化器**（在梯度下降基础上进一步改进）：**Momentum**（累积历史梯度方向，平滑更新、加速收敛）、**RMSProp**（为每个参数自适应调整学习率）、**Adam**（结合 Momentum + RMSProp 的思路，是当前最常用的默认优化器）

### 超参数搜索策略

> 前文提到 **SageMaker Automatic Model Tuning** 能自动搜索最优超参数，其背后依赖以下搜索策略：

| 策略 | 说明 | 特点 |
|------|------|------|
| **网格搜索（Grid Search）** | 穷举给定超参数网格中的**所有**组合 | 保证在网格范围内找到最优解，但组合数随参数数量**指数级增长**，成本高 |
| **随机搜索（Random Search）** | 在参数空间中**随机采样**若干组合进行尝试 | 高维参数空间下通常比网格搜索更高效 |
| **贝叶斯优化（Bayesian Optimization）** | 根据**已尝试过的结果**建立代理模型，智能推荐下一组更可能表现好的超参数 | 通常比前两者用更少的尝试次数找到更优解，**SageMaker Automatic Model Tuning 默认采用这一策略** |

### 类别不平衡数据的处理技术

> 模型训练与评估笔记已覆盖"类别不平衡时应使用 F1 而非 Accuracy"，这里补充**训练阶段**如何应对不平衡本身：

| 技术 | 说明 |
|------|------|
| **过采样（Oversampling）** | 复制或合成少数类样本，**SMOTE（合成少数类过采样技术）**是常用方法，通过在少数类样本间插值生成新的合成样本，而非简单重复 |
| **欠采样（Undersampling）** | 减少多数类样本数量，使类别比例趋于平衡，但可能丢失多数类的有效信息 |
| **类别加权（Class Weighting）** | 训练时给少数类样本的损失赋予更高权重，让模型"更重视"少数类的错误 |
| **调整分类阈值** | 不使用默认的 0.5 阈值，根据业务对 Precision/Recall 的偏好调整判定边界（完整的 Precision/Recall 权衡逻辑见 [[Model training and evaluation]]） |

## 考试重点总结

### AIF-C01 高频考点

1. **ML 问题类型识别**：有标签→监督学习；无标签→无监督学习
2. **监督学习**：回归（连续数值）vs 分类（离散类别）
3. **二元 vs 多元分类**：两类互斥 vs 多类别之一
4. **线性回归 vs 逻辑回归**：预测连续值 vs 预测概率（0~1）
5. **无监督学习**：聚类（分群）、异常检测（找偏差）、关联（共现规律）、降维（减少特征）
6. **聚类配置三要素**：相似性特征、距离函数、聚类数量
7. **自监督学习**：标签由数据本身自动生成，无需人工标注；是基础模型**预训练**阶段的典型范式（区别于微调阶段常用的监督学习）
8. **强化学习**：Agent + Environment + Reward 机制
9. **超参数 vs 参数**：手动设置 vs 训练中自动学习
10. **过拟合 vs 欠拟合**：训练集/测试集性能差距

### 场景题解题思路

```
场景分析 → 选择算法类型
├── "预测未来价格/数量" → 回归
├── "识别属于哪个类别" → 分类
├── "将客户自动分组" → 聚类（无监督）
├── "发现商品关联规律" → 关联规则
├── "减少数据维度" → 降维（PCA）
└── "Agent 学习最优策略" → 强化学习
```
