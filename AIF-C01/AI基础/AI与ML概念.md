# AI 与机器学习基础概念

> **人工智能 (AI)** 是一个宽泛术语，指让机器模拟人类智能的技术。机器学习 (ML) 是 AI 的子集，生成式 AI 是 ML 的子集。理解它们之间的层级关系是 AIF-C01 的核心基础。
>
> 相关文档：[[机器学习算法]] | [[深度学习与神经网络]] | [[大语言模型 - LLM]] | [[AIF-C01 考试概览]]

## 核心概念层级

### AI / ML / 深度学习 / 生成式 AI 的关系

```
人工智能 (AI) ← 宽泛概念
└── 机器学习 (ML) ← 通过数据学习，无需明确编程
    └── 深度学习 (Deep Learning) ← 使用神经网络
        └── 生成式 AI (Generative AI) ← 能生成新内容
            └── 大语言模型 (LLM) ← 文本生成的子集
```

### 定义对比

| 概念 | 定义 | 关键特征 |
|------|------|---------|
| **AI (人工智能)** | 机器模拟人类智能的技术总称 | 宽泛术语，包含所有子领域 |
| **ML (机器学习)** | 机器通过数据自动改善任务表现，无需明确编程 | 有算法、有数据、有学习过程 |
| **深度学习** | 使用多层神经网络处理复杂特征的 ML 子领域 | 数据复杂时使用，特征不明确时使用 |
| **生成式 AI** | 能生成新内容（文本、图像、音频等）的 AI | 多模态输出 |
| **LLM** | 生成类人文字的大型语言模型，是生成式 AI 的子集 | 文本模态，基于 NLP |

## AI 的核心价值

> **人工智能**属于计算机科学领域，致力于解决通常与人类智能相关的认知问题（学习、创造、图像识别）。目标是创建可从数据中找出意义的**自主学习系统**。

| 价值维度 | 说明 | 实例 |
|---------|------|------|
| **处理大量数据** | 快速处理海量数据，解决复杂问题 | 实时欺诈检测 |
| **自动化重复任务** | 执行单调重复工作，让员工专注创造性工作 | 简历筛选、数据录入 |
| **发现模式与预测趋势** | 识别数据中的规律，支持更明智的决策 | 需求预测、库存管理 |
| **个性化体验** | 基于用户历史偏好提供定制化服务 | 内容推荐、精准营销 |

## AI 核心技术能力

### 1. 回归分析与推理（Regression & Inference）

> AI 使用**回归分析**处理历史数据（时间序列数据）并预测未来值，AI 做出的预测称为**推理 (Inference)**，结果是**概率性的**（有根据的猜测）。

- **时间序列数据**：按时间顺序排列的历史数据
- **推理 (Inference)**：模型基于学习到的模式做出预测，输出概率性结果
- **示例**：分析历史客流量，预测某天商店需要配置多少销售人员

### 2. 异常检测（Anomaly Detection）

> AI 能识别何时与预期模式存在偏差，即**异常 (Anomaly)**。

- **工作原理**：先学习正常模式，再检测与该模式的偏差
- **示例**：呼叫中心全天接听电话数量呈可预测规律，当应用程序离线导致电话骤降时，AI 检测异常并自动通知 IT 部门

### 3. 计算机视觉（Computer Vision）

> 使用 AI 处理图像和视频，执行对象识别、面部识别、分类、推荐、监控和检测。

- **常见任务**：对象检测、人脸识别、图像分类、质量检测
- **示例 1**：检测产品表面划痕，用红框标出划痕位置
- **示例 2**：发现电路板上缺少电容器（无需人工参与）
- **相关服务**：[[AWS AI托管服务]]（Amazon Rekognition）

### 4. 语言翻译（Language Translation）

> 现代 AI 翻译不再逐字翻译，而是分析所有文本元素并识别单词间如何相互影响，在目标语言中准确传达短语含义。

- **示例**：客户用西班牙语，支持代表用英语，应用程序实时双向翻译
- **相关服务**：[[AWS AI托管服务]]（Amazon Translate）

### 5. 自然语言处理（NLP）

> **NLP (Natural Language Processing)** 使机器能够理解、诠释和生成听起来自然的人类语言。

- **支持技术**：Alexa 设备、酒店预订聊天机器人等对话式 AI
- **示例**：聊天机器人提示客户提供预订所需信息，并识别用户意图
- **相关服务**：[[AWS AI托管服务]]（Amazon Comprehend、Amazon Lex、Amazon Transcribe）

### 6. 生成式 AI（Generative AI）

> 生成式 AI 可以进行看似智能的对话，生成故事、图像、视频甚至音乐等**原创内容**。

- **使用方式**：从**提示词 (Prompt)** 开始
- **示例**：在 Amazon Bedrock 中输入提示词 `Generate a song from these lyrics`，模型可生成完整歌词（含主歌、副歌、过渡段等）
- **相关文档**：[[大语言模型 - LLM]] | [[Amazon Bedrock]] | [[提示工程 - Prompt Engineering]]

## 三种机器学习类型（考试重点）

### 类型对比

| 类型 | 数据特征 | 典型算法 | 适用场景 |
|------|---------|---------|---------|
| **监督学习 (Supervised)** | **有标签数据** | 回归、分类、决策树、SVM | 价格预测、垃圾邮件过滤、图像分类 |
| **无监督学习 (Unsupervised)** | **无标签数据** | 聚类、关联规则、降维 | 客户分群、市场篮子分析、异常检测 |
| **强化学习 (Reinforcement)** | 环境反馈 (奖惩) | Q-Learning、策略梯度 | 游戏 AI、机器人控制、推荐系统 |

### 监督学习 vs 无监督学习（考试高频对比）

| 特性 | 监督学习 | 无监督学习 |
|------|---------|----------|
| **数据需求** | 需要人工标注标签 | 不需要标签 |
| **准确性** | 通常更高 | 较低，仍需人工验证 |
| **前期工作** | 多（数据标注成本高） | 少 |
| **结果** | 预测已知类别 | 发现未知模式 |
| **关键词** | "分类"、"预测数值" | "分群"、"发现规律" |

> **强化学习**：Agent 在 Environment 中行动，通过反馈（奖励/惩罚）学习最优策略。类似于 Agentic AI 工作流的理念基础。

### 无监督学习 vs 强化学习（考试易混淆对比）

| 特性 | 无监督学习 | 强化学习 |
|------|---------|---------|
| **标注数据** | 不需要 | 不需要 |
| **预设目标** | 无（由算法自行发现模式） | 有（明确指定最终目标） |
| **训练输入** | 有输入，无指定输出 | 通过试错，探索不断被验证和改进 |
| **学习方式** | 发现数据中的隐藏结构 | 探索环境，最大化累计奖励 |
| **典型场景** | 异常检测、客户分群 | 游戏 AI、自动驾驶、机器人控制 |

### 各类型具体示例

**监督学习示例 — 鱼类图像分类**：
- 训练数据包含鱼的图片（标注为"鱼"）和其他动物图片（标注为"不是鱼"）
- 模型查看图像像素，识别聚类和模式，迭代调整参数
- 输出为**概率**（将图像识别为鱼类的概率），而非绝对判断
- **挑战**：可能需要数千张图片，且每张都需要人工标注
- **解决方案**：**Amazon SageMaker Ground Truth** — 利用 **Amazon Mechanical Turk** 众包服务，在全球找到大量费用合理的劳动力完成数据标注

**无监督学习示例**：
- **网络安全**：识别不同类型的网络流量，自动聚类后预测潜在安全事件
- **设备监控**：检查从传感器收集的数据，若油井温度传感器报告值远超正常范围，模型检测到异常并预警

**强化学习示例 — AWS DeepRacer**：
- **Agent（代理）**：模型赛车
- **Environment（环境）**：赛道
- **Action（操作）**：赛车在赛道上向前行驶
- **Goal（目标）**：留在赛道上并尽可能高效地跑完全程
- 训练时允许赛车有时执行不会得到奖励的操作（探索），以促进学习

## ML 工作原理

> 机器学习是一门开发**算法和统计模型**的科学，计算机系统使用这些算法在**没有明确指令**的情况下，通过处理大量历史数据来识别模式并执行复杂任务。

### 训练流程

```
已知数据（含特征）→ 算法 → 找出特征与输出的相关性 → 调整内部参数 → 迭代直到输出匹配
                                                                        ↓
新数据（训练未见过）→ 训练好的模型 → 推理 (Inference) → 预测结果
```

| 概念 | 说明 |
|------|------|
| **特征 (Features)** | 输入数据中的可测量属性；表格中的**列**，图像中的**像素** |
| **参数 (Parameters)** | 模型内部数值（如斜率、权重），训练中迭代调整直到产生预期输出 |
| **推理 (Inference)** | 使用训练好的模型对训练期间**从未见过的新数据**进行预测 |

> 模型训练本质是一个**优化问题**：不断调整参数，使预测误差（预测值与真实值的差距）最小化。

## ML 训练数据类型

> Amazon S3 是训练数据的**主要来源**，因为它可以存储任何类型的数据，成本低，且存储容量近乎无限。

| 数据类型 | 格式特征 | 常见来源 / 工具 | 训练路径 |
|---------|---------|--------------|---------|
| **结构化数据** | 行列表格格式，特征即列，可用 SQL 查询 | CSV 文本文件、Amazon RDS、Amazon Redshift | 导出到 Amazon S3 |
| **半结构化数据** | 不完全遵循表格规则，元素可具有不同或缺失属性 | JSON 文件（键值对）、Amazon DynamoDB、Amazon DocumentDB | 导出到 Amazon S3 |
| **非结构化数据** | 无固定数据模型，不能以表格格式存储 | 图像、视频、文本文件、社交媒体帖子（存储于 Amazon S3） | 用 Tokenization 等技术从对象中提取特征 |
| **时间序列数据** | 每条记录带时间戳，按顺序存储 | 微服务性能指标（内存、CPU、每秒事务数）、Amazon S3 | 模型发现趋势后主动预测（如提前扩容） |

### 数据类型详解

**结构化数据**：最易理解和处理，用 SQL 可直接查询，适合大多数传统 ML 算法。

**半结构化数据（JSON 示例）**：
```json
{
  "user_id": "12345",
  "name": "Alice",
  "purchase_history": ["item_a", "item_b"]
}
```
键值对格式，不同文档可有不同字段，Amazon DynamoDB 和 DocumentDB 是专用事务数据库。

**非结构化数据**：用**分词化 (Tokenization)** 处理文本，将文本拆分为单词或短语单元，从而提取可用于机器学习的特征。

**时间序列数据**：对训练需要预测未来趋势的模型非常重要，采样率高时数据量极大，存储在 Amazon S3 中用于模型训练。

## 模态 (Modalities)

> **模态** 指模型能感知和生成的内容类型，类比人类的感觉器官。

| 模态 | 示例 | 相关服务 |
|------|------|---------|
| **文本 (Text)** | 生成文章、翻译、摘要 | LLM、Amazon Comprehend |
| **图像 (Vision)** | 图像生成、对象识别 | Stable Diffusion、Amazon Rekognition |
| **音频 (Audio)** | 语音识别、音乐生成 | Amazon Transcribe、Amazon Polly |
| **视频 (Video)** | 视频分析、动作识别 | Amazon Rekognition Video |
| **分子 (Molecular)** | 药物发现、基因组数据分析 | 专业科学 AI 模型 |

> LLM 主要是**文本模态**，但现代 LLM 正在演进为**多模态 (Multimodal)**，可跨模态处理。

## NLP (自然语言处理)

> **NLP (Natural Language Processing)** 是 ML 中理解和处理人类语言的技术，交汇于计算机科学与语言学。

### NLP 核心任务

| 任务 | 描述 | AWS 服务 |
|------|------|---------|
| **情感分析 (Sentiment Analysis)** | 判断文本正面/负面/中性 | Amazon Comprehend |
| **实体识别 (NER)** | 提取人名、地名、组织等实体 | Amazon Comprehend |
| **文本分类 (Classification)** | 将文本归入预定义类别 | Amazon Comprehend |
| **机器翻译 (Translation)** | 语言之间的文本翻译 | Amazon Translate |
| **语音识别 (ASR)** | 将语音转为文字 | Amazon Transcribe |
| **文本生成 (Generation)** | 生成连贯的自然语言文本 | Amazon Bedrock (LLM) |
| **问答 (Q&A)** | 基于上下文回答问题 | Amazon Kendra / Bedrock |

### 关键 NLP 术语

| 术语 | 定义 |
|------|------|
| **语料库 (Corpus)** | 用于训练的相关文本集合 |
| **Token (词元)** | 文本被分割的最小单位（词或子词） |
| **Tokenization** | 将文本分割成 Token 序列的过程 |
| **Embedding** | 将文本转换为数值向量的表示 |

## 数据生命周期 (CRISP-DM)

> **CRISP-DM** 是经典的数据挖掘跨行业标准流程，定义了 ML 项目的完整生命周期。

```
业务理解 → 数据理解 → 数据准备 → 建模 → 评估 → 部署
(Business)   (Data       (Data        (Modeling) (Evaluation) (Deployment)
             Understanding) Preparation)
```

### 各阶段说明

| 阶段 | 核心问题 | 关键活动 |
|------|---------|---------|
| **业务理解** | 业务需要什么？ | 定义目标、成功标准 |
| **数据理解** | 我们有什么数据？ | 数据探索、质量评估 |
| **数据准备** | 如何整理数据？ | 清洗、转换、特征工程 |
| **建模** | 使用什么算法？ | 选择模型、训练、调参 |
| **评估** | 模型够好吗？ | 性能指标评估、业务目标验证 |
| **部署** | 如何让人使用？ | 模型部署、监控、维护 |

### 数据准备步骤

| 步骤 | 描述 |
|------|------|
| **结构化 (Structuring)** | 将内容整理成便于处理的格式 |
| **清洗 (Cleaning)** | 移除异常值、填充空值、去除重复项 |
| **丰富 (Enriching)** | 从外部来源追加相关上下文数据 |
| **验证 (Validating)** | 验证数据的真实性与合规性 |

## AI 适合 vs 不适合的使用案例（任务陈述 1.2）

### AI 适合的场景

| 场景 | 说明 |
|------|------|
| **全天候重复任务** | AI 可 24/7 工作且不降低性能，适合员工觉得单调乏味的重复工作 |
| **海量数据高速分析** | 分析速度远超人类能力，适合需要处理大规模数据的复杂问题 |
| **模式检测与欺诈识别** | AI 擅长识别模式偏差，非常适合欺诈检测和异常识别 |
| **需求预测减少浪费** | 通过预测产品或资源需求，帮助提高效率、减少浪费 |
| **提升决策质量** | 基于数据驱动的洞察，支持企业做出更明智的决策 |

### AI 不适合的场景

#### 1. 成本效益不合理

> 使用 ML 训练 AI 会消耗大量资源：处理能力耗资高、模型需频繁重新训练。**启动 AI 项目前必须确认收益将超过成本。**

**评估方法**：
```
设定目标节省金额（如欺诈减少带来的收益）
         ↓
估算构建模型的成本
         ↓
若成本 > 节省金额 → 不应启动该 AI 项目
```

#### 2. 需要完全可解释性（模型可诠释性）

> **模型可诠释性 (Model Interpretability)**：人们对复杂神经网络的内部机制如何影响预测结果并不完全理解。复杂模型通常在**准确性与可解释性**之间进行权衡。

- 若业务或合规性要求**完全透明**（如贷款审批需要解释原因）→ 使用较简单的模型（通常性能较低）
- 或采用**不需要 AI 的基于规则的系统**
- 示例：规则"信用评分 ≥ 750 且申请金额 ≤ $10,000 → 自动批准"，完全透明且可预测

#### 3. 需要确定性结果

> **确定性 (Deterministic) vs 概率性 (Probabilistic)** 是选择规则系统还是 ML 的核心判断维度。

| 特性 | 基于规则的系统（确定性） | ML 模型（概率性） |
|------|----------------------|----------------|
| **行为** | 相同输入**始终**产生相同输出 | 相同输入可能产生**不同**结果 |
| **可预测性** | 完全可预测 | 包含随机性 |
| **学习能力** | 不自动学习（需手动更新规则） | 随时间不断学习和适应 |
| **适用场景** | 规则清晰、合规性要求高 | 模式复杂、数据驱动决策 |

> 如果需要**确定性**，基于规则的系统是更好的选择。

2. **三种学习类型**：监督（标签数据）/ 无监督（无标签）/ 强化（奖惩反馈）
3. **NLP 概念**：语料库、Tokenization、Embedding
4. **模态**：文本、图像、音频、视频
5. **CRISP-DM 流程**：业务理解 → 数据准备 → 建模 → 评估 → 部署
6. **推理 (Inference)**：AI 预测的概率性结果，不是确定答案
7. **异常检测**：识别与正常模式的偏差
8. **计算机视觉**：对象识别、质量检测（Amazon Rekognition）
9. **AI 行业应用**：医疗、制造、零售、金融、娱乐等场景
10. **SageMaker Ground Truth + Mechanical Turk**：解决监督学习数据标注挑战的 AWS 服务
11. **无监督 vs 强化学习**：两者均不需要标注数据；区别在于强化学习有明确预设目标
12. **AWS DeepRacer**：强化学习的典型 AWS 示例（代理=赛车，环境=赛道）
13. **AI 成本效益评估**：启动前确认收益 > 成本（设定目标节省 vs 估算构建成本）
14. **模型可诠释性 (Interpretability)**：复杂模型准确性高但透明度低，合规要求高时用简单模型或规则系统
15. **确定性 vs 概率性**：规则系统=确定性（同输入→同输出）；ML=概率性（包含随机性，结果可变）

### 场景题解题思路

```
场景分析 → 选择学习类型
├── "有标注数据，预测类别/数值" → 监督学习
├── "无标注数据，发现模式/分群" → 无监督学习
├── "Agent 与环境交互，通过反馈学习" → 强化学习
├── "识别图像中的对象" → 计算机视觉（监督学习）
└── "分析文字情感/提取实体" → NLP（监督学习）

场景分析 → 识别 AI 技术类型
├── "预测未来数值（销售额、人力需求）" → 回归分析 / 时间序列
├── "检测异常行为（欺诈、设备故障）" → 异常检测
├── "图像质量检测/人脸识别/对象检测" → 计算机视觉
├── "实时语言翻译" → 语言翻译（Amazon Translate）
├── "理解用户意图/语音交互" → NLP（Amazon Comprehend / Lex）
└── "生成原创文本/图像/音乐" → 生成式 AI（Amazon Bedrock）

场景分析 → 判断是否适合使用 AI（任务陈述 1.2）
├── "构建成本 > 预期节省" → 不适合使用 AI
├── "合规要求必须解释每个决策" → 简单模型 或 基于规则的系统（非 AI）
├── "需要相同输入始终给出相同结果" → 基于规则的确定性系统
├── "24/7 重复任务 / 海量数据分析" → 适合使用 AI
├── "欺诈检测 / 异常识别" → 适合使用 AI（模式识别强项）
└── "需求预测 / 减少浪费" → 适合使用 AI
```
