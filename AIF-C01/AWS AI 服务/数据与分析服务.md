# 数据与分析服务

> AI/ML 工作负载的核心是数据。AWS 提供了完整的数据准备、存储、查询和集成服务栈，支撑 ML 流程中的数据摄取和处理阶段。这些服务在 AIF-C01 中作为 ML 流程支撑服务出现。
>
> 相关文档：[[Amazon SageMaker]] | [[Amazon Bedrock]] | [[AI与ML概念]]

---

## 数据服务概览

| 服务 | 类别 | 核心功能 |
|------|------|---------|
| **Amazon Athena** | 查询分析 | 使用 SQL 查询 S3 中的半结构化数据 |
| **AWS Glue** | 数据集成 | Serverless ETL，数据发现、准备、移动 |
| **Amazon OpenSearch** | 搜索/向量数据库 | 全文搜索 + 向量搜索 |
| **Amazon Kinesis** | 流式数据 | 实时数据流摄取和处理 |
| **Amazon QuickSight** | 商业智能 (BI) | 交互式仪表板和数据可视化 |

## Amazon QuickSight（商业智能 / 数据可视化）

> **Amazon QuickSight** 是 AWS 的**商业智能（BI）服务**，让用户能从多种数据源快速创建和分享**交互式仪表板与可视化报表**，支持接近实时的数据分析——这是它与本笔记其他"数据准备/ML 支撑"类服务的本质区别：**QuickSight 面向的是"给业务人员看的成品仪表板"，而不是"给 ML 流程用的数据处理步骤"**。

### 核心定位（考试重点：不要和这些工具混淆）

| 工具 | 定位 | 能否做交互式 BI 仪表板 |
|------|------|---------------------|
| **Amazon QuickSight** | **商业智能服务**，专为创建交互式仪表板和可视化报表设计 | ✅ 是——这正是它存在的目的 |
| **CloudWatch Dashboard** | **监控** AWS 基础设施/服务指标（服务器指标、日志、性能），面向运维/SRE | ❌ 否——只用于监控 AWS 资源本身，不是通用业务数据可视化工具 |
| **SageMaker Canvas** | 无代码**建模**工具，让不懂 ML 的用户训练/部署模型 | ❌ 否——产出的是"模型"而非"仪表板"，可视化的是模型效果，不是业务 BI 报表 |
| **SageMaker Data Wrangler** | ML 流程中**数据准备/特征工程**阶段的可视化数据分析工具，内置分析可快速生成图表 | ❌ 否——图表用于**辅助数据清洗决策**，不是给业务方看的交互式仪表板产品 |

> **考试陷阱**：题目描述"需要为销售/业务数据创建**交互式、可分享、近实时更新**的仪表板，供管理者监控 KPI 和趋势" → 答案几乎总是 **Amazon QuickSight**。其余三个选项都"沾边"可视化——CloudWatch 看起来像仪表板但只服务于**基础设施监控**；Canvas/Data Wrangler 虽然也能生成图表，但那些图表是 **ML 流程内部的辅助产物**（分别用于"看模型效果""看数据分布做清洗决策"），而不是面向业务用户的成品 BI 报表。

### 与 Amazon Q 的关系

- **Q in QuickSight** 是在 QuickSight 之上叠加的**生成式 BI**能力（自然语言问答生成图表、自动生成数据叙述），完整的 Amazon Q 产品家族及选型判断见 [[Amazon Q]] 独立笔记
- **判断依据**：题目问"BI 分析师想用自然语言直接问仪表板数据" → **Q in QuickSight**（生成式交互层）；题目问"需要一个 BI 工具本身来做可视化" → **QuickSight**（底层 BI 服务本身）

## Amazon Athena

> **Amazon Athena** 是交互式查询服务，直接使用 **SQL** 查询存储在 S3 中的半结构化数据（CSV、JSON、Parquet、ORC 等），无需加载到数据库。

### 核心特点

| 特性 | 描述 |
|------|------|
| **Serverless** | 无需管理服务器，按扫描数据量计费 |
| **SQL 查询** | 标准 SQL 语法（基于 Presto/Hive） |
| **直接查询 S3** | 无需数据迁移，数据存在 S3 即可查询 |
| **多格式支持** | CSV、JSON、Parquet、ORC、Avro 等 |
| **Glue 集成** | 使用 AWS Glue Data Catalog 作为数据目录 |

### 支持的数据类型（HiveQL）

| 数据类型 | 描述 |
|---------|------|
| **VARCHAR** | 可变长字符串 |
| **STRING** | 字符串（单/双引号括起） |
| **BINARY** | 二进制数据（Parquet 格式使用） |
| **ARRAY、MAP、STRUCT** | 复杂嵌套类型 |

### 适用 ML 场景

```
ML 数据准备 → 使用 Athena
├── "分析 S3 中的训练数据集统计" → SQL 查询 S3
├── "从日志中提取特征数据" → 查询 JSON/CSV 日志
├── "验证数据质量" → SQL 聚合和过滤
└── "探索大型数据集" → 按需查询，无需加载
```

## AWS Glue

> **AWS Glue** 是 Serverless 数据集成服务，使数据工程师和分析师能够发现、准备、移动和集成来自多个来源的数据。

### 核心组件

| 组件 | 描述 |
|------|------|
| **Glue Data Catalog** | 集中的元数据存储，Athena 和其他服务的数据目录 |
| **Glue Crawlers（爬虫）** | 自动扫描数据源，推断 Schema，填充 Data Catalog |
| **Glue ETL Jobs** | 数据转换脚本（支持 Python Shell、Spark、Ray） |
| **Glue Data Quality** | 使用 DQL 定义和评估数据质量规则 |
| **Glue DataBrew** | 可视化数据准备工具（无代码） |

### ETL 引擎类型

| 引擎 | 特点 |
|------|------|
| **Python Shell** | 轻量任务，标准 Python 脚本 |
| **Apache Spark** | 大规模分布式数据处理 |
| **Ray（预览）** | 新型分布式框架，高效的 Spark 替代 |

### Glue Data Quality

- 使用 **DQL（数据质量定义语言）** 定义数据质量规则
- 25+ 开箱即用的 DQ 规则
- 使用 **ML 检测异常**（难以用规则描述的数据质量问题）
- 评估结果记录到 CloudWatch 或 S3

### 适用 ML 场景

```
ML 数据流程 → 使用 Glue
├── "自动发现 S3 数据的结构" → Glue Crawler
├── "将多个数据源合并清洗" → Glue ETL Job (Spark)
├── "验证数据集质量" → Glue Data Quality
└── "为 Athena 查询创建数据目录" → Glue Data Catalog
```

## Amazon OpenSearch（向量数据库 + 全文搜索）

> **Amazon OpenSearch Service** 基于 Apache Lucene 搜索库（原 ElasticSearch 分支），提供全文搜索和向量搜索能力，是 Bedrock Knowledge Bases 的常用向量存储。

### 历史背景

> 2021 年，AWS 因 Elastic 公司更改开源许可协议，Fork 了 ElasticSearch 和 Kibana，创建了 OpenSearch 和 OpenDashboards。

### 两种部署模式

| 模式 | 特点 |
|------|------|
| **OpenSearch Serverless** | 按使用量计费，无需管理集群，推荐用于 Bedrock Knowledge Bases |
| **OpenSearch Managed Clusters** | 自行管理集群大小和配置，成本可优化 |

### 向量搜索能力

| 功能 | 描述 |
|------|------|
| **KNN 搜索** | K 近邻相似度搜索 |
| **HNSW 算法** | 高效近似最近邻搜索 |
| **混合搜索** | 全文搜索 + 向量搜索组合 |

### 与 Bedrock 集成

- 作为 **Bedrock Knowledge Bases** 的向量存储后端
- 存储文档的嵌入向量
- 检索时执行语义相似度搜索

## 数据格式说明

### ML 常用数据格式

| 格式 | 特点 | 适用场景 |
|------|------|---------|
| **CSV** | 人类可读，无压缩 | 小型结构化数据集 |
| **JSON/JSONL** | 灵活，支持嵌套 | API 数据、Fine-tuning 数据集 |
| **Parquet** | 列式存储，压缩高效 | 大型分析数据集，Athena 查询 |
| **ORC** | 高度压缩的列式格式 | Hive/Spark 大数据处理 |

## 考试重点总结

### AIF-C01 高频考点

1. **Athena** = SQL 查询 S3 数据（Serverless，按扫描量计费）
2. **Glue** = Serverless ETL + 数据目录 + 数据质量
3. **Glue Crawler** = 自动发现数据结构
4. **OpenSearch** = 全文搜索 + 向量数据库（Bedrock Knowledge Bases 后端）
5. **Glue Data Quality** = ML 数据质量验证
6. **QuickSight** = 商业智能仪表板/可视化，与 CloudWatch Dashboard（AWS 基础设施监控）、SageMaker Canvas（无代码建模）、Data Wrangler（ML 数据准备中的辅助图表）四者容易混淆，判断依据是"给谁看、看什么"——QuickSight 面向业务方看 KPI/趋势，其余三者都不是通用 BI 工具

### 场景题解题思路

```
场景分析 → 选择数据服务
├── "用 SQL 查询 S3 中的 CSV 日志" → Amazon Athena
├── "自动爬取 S3 数据建立元数据目录" → AWS Glue Crawler
├── "跨多数据源 ETL 合并数据" → AWS Glue ETL Job
├── "为 Bedrock RAG 提供向量存储" → OpenSearch Serverless
├── "验证训练数据集质量" → Glue Data Quality
├── "实时数据流摄取" → Amazon Kinesis
└── "为业务数据创建交互式、可分享的仪表板" → Amazon QuickSight
```
