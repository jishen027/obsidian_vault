# Amazon Q Developer - AI 编码助手

> **Amazon Q Developer** 是 AWS 的生成式 AI 编码助手，前身为 **Amazon CodeWhisperer**（2024 年 4 月更名并大幅扩展能力），集成于 IDE、命令行（CLI）和 AWS 控制台，提供代码补全、聊天问答、**自主智能体式编码（Agentic Coding）**、代码转换、安全扫描等能力，帮助开发者更快地理解、编写、调试和运维基于 AWS 的应用。
>
> 相关文档：[[Amazon Bedrock]] | [[AWS CloudFormation]] | [[IAM]] | [[CloudWatch]]

## 核心概念

### 为什么需要 Q Developer

- **传统开发流程的痛点**：编写样板代码、排查安全漏洞、升级过时的依赖库/语言版本都是耗时但重复性高的工作，尤其是大型代码库的语言版本升级（如 Java 版本迁移）往往需要数周甚至数月的人工工作量
- **Q Developer 的核心价值**：基于大语言模型理解代码上下文和 AWS 服务/IAM 策略/SDK 用法，不仅提供实时代码建议，还能**自主执行多步骤开发任务**（读写文件、生成代码 diff、运行 shell 命令），大幅缩短从需求到可用代码的周期
- **与 CodeWhisperer 的关系**：Q Developer 保留了 CodeWhisperer 的实时代码建议和安全扫描能力，并新增了聊天界面、自主智能体、云资源集成等全面扩展，是 CodeWhisperer 的**更名 + 能力扩展**，而非全新产品

### Q Developer vs Q Business（考试要点）

| 服务 | 定位 | 用户群 | 典型场景 |
|------|------|--------|---------|
| **Amazon Q Developer** | 面向开发者的编码助手 | 软件工程师、云架构师 | 代码编写、调试、代码转换、AWS 资源理解与运维 |
| **Amazon Q Business** | 面向业务用户的企业 AI 助手 | 非技术业务团队 | 基于企业知识库（SharePoint、Confluence、内部 Wiki 等）的自然语言问答 |

> **考试陷阱**：**Q Developer 和 Q Business 是两个面向不同用户群的独立产品，容易混淆**——题目强调"帮助开发者写代码、理解 AWS 服务、排查问题"→ **Q Developer**；题目强调"让非技术业务人员通过自然语言查询企业内部文档/知识库"→ **Q Business**（定位上与 [[Amazon Kendra]] 存在功能重叠，均可作为企业知识库问答方案）。

## 核心能力

### 代码补全与聊天

| 能力 | 说明 |
|------|------|
| **实时代码建议** | 基于当前代码上下文，实时提供从单行代码到完整函数的建议（继承自 CodeWhisperer） |
| **聊天问答（Chat）** | 在 IDE 内以自然语言提问，获得代码解释、调试建议、AWS 服务用法说明 |
| **跨语言代码翻译** | 支持在不同编程语言之间转换代码逻辑 |

### 自主智能体式编码（Agentic Coding）

- **自主执行多步骤任务**：包括实现新功能、编写文档、编写测试、代码审查、重构、执行软件升级等，智能体会**自动读写文件、生成代码 diff、运行 shell 命令**，并结合用户反馈实时调整
- **IDE 支持**：Visual Studio Code、JetBrains 系列均已支持智能体式编码体验
- **CLI 智能体**：命令行版本的 Q Developer 可直接在终端中完成多步骤开发任务（读写本地文件、查询 AWS 资源、生成代码），**无需在终端和 IDE 之间切换上下文**，适合习惯命令行工作流的开发者

> **考试要点**：题目强调**"希望 AI 自主完成从需求描述到代码实现、测试、文档的完整流程"**（而非仅是单行代码建议）→ 对应 Q Developer 的**智能体式编码**能力，这是它与传统代码补全工具的核心区别。

### 代码转换（Code Transformation）

- **典型场景**：**Java 版本升级**——Q Developer 可分析整个代码库，识别不兼容的 API、更新依赖项、重构过时的代码模式，并生成完整的转换方案
- 大幅缩短传统需要数周/数月人工完成的语言版本迁移工作量

### 安全扫描

| 扫描能力 | 说明 |
|---------|------|
| **静态应用安全测试（SAST）** | 检测代码中的安全漏洞和策略违规 |
| **密钥检测（Secrets Detection）** | 识别代码中意外硬编码的密钥/凭证 |
| **基础设施即代码扫描（IaC Scanning）** | 检测 CloudFormation/Terraform 等 IaC 文件中的安全配置问题 |
| **支持语言** | 内置扫描覆盖 Python、Java、JavaScript 等主流语言项目 |

## 部署与集成方式

| 集成方式 | 说明 |
|---------|------|
| **IDE 插件** | VS Code、JetBrains、Eclipse（即将支持）等主流 IDE |
| **命令行（CLI）** | 终端内的智能体式对话，直接读写本地文件、查询 AWS 资源、执行命令 |
| **AWS 控制台** | 在 AWS 管理控制台内直接获得帮助，也提供移动端（iOS/Android）应用内集成 |
| **深度 AWS 集成** | 相比通用代码助手，Q Developer 更擅长 AWS 相关工作——理解 AWS 服务、[[IAM]] 策略、SDK 用法的准确度更高 |

| 机制 | 说明 |

## 典型应用场景

| 场景 | 推荐配置 |
|------|---------|
| **日常编码中获得实时代码建议** | Q Developer IDE 插件（代码补全） |
| **大型代码库的语言版本升级（如 Java 迁移）** | Q Developer 代码转换（Code Transformation） |
| **希望 AI 自主完成功能实现、测试、文档全流程** | Q Developer 智能体式编码（IDE/CLI） |
| **上线前排查代码中的安全漏洞/硬编码密钥** | Q Developer 安全扫描（SAST + 密钥检测 + IaC 扫描） |
| **习惯终端工作流，不想频繁切换到 IDE** | Q Developer CLI 智能体 |
| **理解/调试 AWS 相关代码、IAM 策略、SDK 用法** | Q Developer 聊天问答，深度 AWS 集成优势明显 |
| **企业内部非技术人员查询知识库文档** | 改用 Amazon Q Business（而非 Q Developer） |
| **企业级语义搜索，无需生成式对话** | 改用 [[Amazon Kendra]]（而非 Q Developer/Q Business） |

## 考试重点总结

### 高频考点

1. **核心定位**：面向开发者的生成式 AI 编码助手，前身为 CodeWhisperer（2024-04 更名并扩展能力）
2. **判断依据**：面向"写代码、调试、AWS 相关开发工作"选 Q Developer；面向"业务用户查询企业知识库"选 Q Business
3. **智能体式编码是核心差异化能力**：不仅是代码补全，还能自主完成实现功能、测试、文档、重构等多步骤任务
4. **代码转换聚焦语言版本升级**：典型场景是 Java 版本迁移，大幅缩短传统人工升级周期
5. **安全扫描三件套**：SAST（漏洞检测）、密钥检测、IaC 扫描，覆盖开发阶段的安全左移
6. **CLI 智能体支持终端原生工作流**：无需在终端和 IDE 之间切换即可完成多步骤任务
7. **深度 AWS 集成是差异化优势**：相比通用代码助手，对 AWS 服务/IAM/SDK 的理解更准确
8. **Q Developer vs Q Business 是两个独立产品**：分别面向开发者和业务用户，不可混淆
9. **Q Business 与 Kendra 功能存在重叠**：都可用于企业知识库问答，但 Q Business 提供生成式对话体验，Kendra 更偏传统语义检索
10. **提供免费层**：每月固定额度的智能体交互和代码转换行数，适合个人开发者试用

### 场景题解题思路

```
场景分析 → 判断是否用 Q Developer
├── "开发者需要实时代码建议/补全" → Q Developer（代码补全）
├── "希望 AI 自主完成功能实现/测试/文档的完整流程" → Q Developer 智能体式编码
├── "大型代码库需要升级编程语言版本（如 Java）" → Q Developer 代码转换
├── "上线前需要扫描代码安全漏洞/硬编码密钥" → Q Developer 安全扫描
├── "习惯终端工作流，需要 AI 辅助多步骤开发任务" → Q Developer CLI
├── "需要理解/调试 AWS 服务相关代码或 IAM 策略" → Q Developer（深度 AWS 集成）
├── "业务用户需要查询企业内部文档/知识库" → 改用 Amazon Q Business（而非 Q Developer）
└── "只需企业级语义搜索，不需要生成式对话" → 改用 Amazon Kendra（而非 Q Developer/Q Business）
```

## 最佳实践

1. **日常编码优先启用实时建议**：降低样板代码编写成本，让开发者专注业务逻辑
2. **大型语言版本升级评估代码转换能力**：相比纯人工迁移，可大幅压缩项目周期
3. **将安全扫描纳入开发阶段而非上线后检查**：尽早发现漏洞和硬编码密钥，降低修复成本
4. **复杂多步骤任务优先尝试智能体式编码**：而非逐行手动实现，尤其适合功能实现、测试编写、重构等结构化任务
5. **终端重度用户评估 CLI 智能体**：减少 IDE 与终端之间的上下文切换成本
6. **AWS 相关开发工作优先使用 Q Developer 而非通用代码助手**：其对 AWS 服务/IAM/SDK 的理解更准确
7. **明确区分 Q Developer 与 Q Business 的使用场景**：不要用 Q Developer 满足业务用户的知识库问答需求，反之亦然
8. **智能体输出仍需人工代码审查**：自动生成的代码 diff 和转换方案应经过人工复核后再合并，尤其是生产环境相关变更
