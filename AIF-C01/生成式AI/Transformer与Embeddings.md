# Transformer 架构与 Embeddings

> **Transformer** 是由 Google 研究人员提出的神经网络架构（论文《Attention Is All You Need》），通过**多头注意力机制**和**位置编码**实现高效的自然语言处理，是所有现代 LLM 的基础。**Embeddings（嵌入）** 是将文本转换为数值向量的方法，是 RAG 和语义搜索的关键。
>
> 相关文档：[[大语言模型 - LLM]] | [[提示工程 - Prompt Engineering]] | [[Amazon Bedrock]]

## 从深度学习到生成式 AI

> 生成式 AI 通过使用**深度学习模型**实现，这些模型已在包含文本字符串（称为"**序列**"）的超大数据集上进行了预训练。Transformer 是连接深度学习与生成式 AI 的核心架构。

```
深度学习（神经网络）
    └── Transformer 神经网络（并行处理序列）
            └── 预训练大语言模型 (LLM)
                    └── 生成式 AI（文本、图像、音乐等）
```

### RNN vs Transformer（处理序列的方式）

| 特性 | RNN（循环神经网络） | Transformer |
|------|-----------------|------------|
| **处理方式** | **顺序**处理，一次一个词 | **并行**处理整个序列 |
| **训练速度** | 慢 | 快 |
| **数据集规模** | 受限于顺序处理 | 可使用更大的数据集 |
| **长距离依赖** | 难以捕获 | 通过注意力机制轻松捕获 |

> Transformer 的并行处理能力加快了训练速度，使得在超大规模数据集上训练成为可能，这正是 LLM 得以产生的关键。

### Transformer 在生成式 AI 中的作用

```
输入序列（提示词 Prompt）→ Transformer → 输出序列（对提示词的响应）
```

**LLM 的能力来源于**：
- 数十亿个特征（参数），涵盖广泛的人类知识
- 在超大规模文本数据集上的预训练
- 对自然语言语义的深度理解

### LLM 擅长的任务

| 任务 | 说明 |
|------|------|
| **文本摘要** | 阅读长篇文章并生成摘要 |
| **文本生成** | 以类人方式生成连贯文本 |
| **语言翻译** | 跨语言翻译，理解语境而非逐字翻译 |
| **创意写作** | 撰写故事、信件、文章、诗歌等原创内容 |
| **代码生成** | 理解编程语言，为开发人员编写代码 |
| **问答** | 基于广泛知识回答问题 |

> **试用资源**：访问 [partyrock.aws](https://partyrock.aws) 可免费开发自己的生成式 AI 应用程序。

## Transformer 架构

### 核心特点

| 特性                               | 描述                                  |
| -------------------------------- | ----------------------------------- |
| **多头注意力 (Multi-Head Attention)** | 并行关注输入的不同方面，捕获多维度语义关系               |
| **位置编码 (Positional Encoding)**   | 为序列中的每个词添加位置信息（Transformer 本身无顺序感知） |
| **自注意力 (Self-Attention)**        | 序列内部元素互相关注，理解上下文关系                  |
| **交叉注意力 (Cross-Attention)**      | 编码器与解码器之间的注意力（用于翻译等任务）              |
| **并行计算**                         | 与 RNN 不同，Transformer 可并行处理整个序列，训练更快 |

### Encoder-Decoder 结构

```
输入文本 → [编码器 Encoder] → 语义表示
                                    ↓
                            [解码器 Decoder] → 输出文本
```

| 组件 | 职责 | 典型用途 |
|------|------|---------|
| **Encoder（编码器）** | 理解输入，生成语义表示 | 文本理解、分类、嵌入 |
| **Decoder（解码器）** | 基于编码器输出生成新序列 | 文本生成、翻译 |
| **Encoder-Decoder** | 两者结合 | 翻译（输入→输出序列） |

### Transformer 关键组件总览（推理流程）

> 以下是从输入提示词到最终补全内容的完整 Transformer 流程：

| 组件 | 功能 |
|------|------|
| **输入 (Input)** | 原始文本 → Tokenizer → Token ID 序列 |
| **上下文窗口 (Context Window)** | 模型一次能处理的最大 Token 数 |
| **嵌入层 (Embedding Layer)** | Token ID → 高维嵌入向量（携带语义信息） |
| **位置编码 (Positional Encoding)** | 为每个 Token 加入位置信息，帮助模型感知词序 |
| **编码器 (Encoder)** | 多层堆叠，构建输入的上下文表示 |
| **自注意力 (Self-Attention)** | 计算序列内各分词的关联权重（Q/K/V 机制） |
| **解码器 (Decoder)** | 基于编码器表示，逐步生成输出 Token |
| **Softmax 输出** | 将最终向量转化为词汇表上的**概率分布**，取概率最高的 Token 作为下一个词 |

### Transformer 层内部结构

> 编码器与解码器各自由**多个相同层**堆叠而成，**每层**包含 **2 个子层**：

```
每个 Transformer 层
├── 子层 1：自注意力（Self-Attention）
│              + 残差连接（Residual Connection）
│              + 层归一化（Layer Normalization）
└── 子层 2：前馈神经网络（Feed-Forward Network）
               + 残差连接（Residual Connection）
               + 层归一化（Layer Normalization）
```

| 训练稳定技术 | 作用 |
|------------|------|
| **残差连接 (Residual Connections)** | 将子层的输入**直接加**到子层的输出，有助于梯度在深层网络中流动，促进训练 |
| **层归一化 (Layer Normalization)** | 稳定每层的激活分布，加速训练并**防止过拟合** |

> 在**模型预训练和微调**阶段，Transformer 通过这些机制帮助模型从训练数据中获得对语言的**上下文理解**。

## Tokenization（词元化）

> **Tokenization** 是将输入文本转换为模型内部词汇表的 Token 序列的过程，是 LLM 处理文本的第一步。

### 工作原理

```
原始文本 → Tokenizer → Token ID 序列 → 模型处理
"Hello World" → [15339, 1917] → 模型推理 → 生成下一个 Token
```

### 关键概念

| 概念 | 描述 |
|------|------|
| **Token（分词）** | 文本分割的最小单位，可以是字、词或子词 |
| **词汇表 (Vocabulary)** | 模型训练时建立的所有已知 Token 的集合；每个 Token 对应词汇表中的唯一 ID |
| **分词 ID / 输入 ID (Token ID / Input ID)** | 每个 Token 在词汇表中的数字编号，代表词汇表中的一个具体分词 |
| **上下文窗口 (Context Window)** | 模型一次能处理的最大 Token 数量 |
| **Tokenizer（分词器）** | 将人类文本转换为包含**分词 ID（输入 ID）向量**的工具 |

> 每个基于语言的生成式 AI 模型都有一个 **Tokenizer**，将人类文本转换为包含**分词 ID（输入 ID）的向量**。每个输入 ID 代表模型词汇表中的一个分词。

> LLM 按 **Token** 计费，而非按字符或单词计费。1 Token ≈ 0.75 个英文词（中文每个汉字通常为 1-2 个 Token）。

## Embeddings（嵌入向量）

> **Embeddings（嵌入）** 是任何实体的**数字向量化表示**，是获取每个分词**高维表示形式**所必需的一组输入 ID。嵌入可捕获文本、图像、视频或音频等分词的**语义含义**，使模型能从统计上表示和理解人类语言。

### 向量 (Vector) 基础

> **向量（Vector）** 是一个**有序的数字列表**，表示某些实体或概念的**特征或属性**。在生成式 AI 中，向量不仅是一串数字，还表示该数字列表在**高维向量空间中的具体位置**。

| 类比 | 说明 |
|------|------|
| **Excel 电子表格** | 列号 + 行号 → 确定电子表格中某个单元格的位置；向量中的数字列表 → 确定在向量空间/向量数据库中的位置 |
| **坐标系** | 2D 平面上的点由 (x, y) 确定；高维嵌入向量由数百至数千个数字确定语义空间中的位置 |

> 向量表示法的强大之处在于其能够对**项目之间的相关关系**进行编码，捕获有意义的**关联、类比和层次结构**。例如，海牛和儒艮之间的向量差异可能类似于两种鲨鱼之间的向量差异——模型从统计上学习并编码了这些语义关联。

### 语义接近原则（考试重点）

> 向量对分词在大型文本语料库中的**含义和上下文**进行编码。

```
向量空间中的语义关系：
距离近 → 语义相似    |    距离远 → 语义不同

"猫" ←→ "狗"（动物，距离近）
"猫" ←→ "汽车"（无关联，距离远）
```

> **核心规律**：向量空间中分词彼此**越接近**，它们的语义含义**越相似**。模型正是根据这些向量之间的关系来**生成文本**。

### 嵌入向量的流转

> 模型处理流程中，嵌入向量会被传递到 Transformer 的**自注意力层（Self-Attention Layer）**：

```
原始文本 → Tokenizer → Token ID（输入 ID）向量
    → 嵌入层（Embedding Layer）→ 嵌入向量（高维语义表示）
    → 自注意力层（Self-Attention）→ 上下文感知的向量表示
    → 解码器 → Softmax → 输出补全内容
```

### 核心用途

| 用途 | 描述 |
|------|------|
| **语义搜索** | 基于含义而非关键词搜索相似内容 |
| **RAG 知识检索** | 将查询和文档转为向量，计算相似度找到相关内容 |
| **聚类分析** | 找到语义相似的文本群组 |
| **推荐系统** | 找到与用户偏好相似的内容 |

### 向量空间示例

```
语义相似的词 → 向量距离近
"苹果" → [0.2, 0.8, 0.3, ...]  (水果)
"香蕉" → [0.2, 0.7, 0.4, ...]  (水果) ← 距离近
"汽车" → [0.9, 0.1, 0.6, ...]  (交通) ← 距离远

蔬菜、肉类、乳制品 → 在向量空间中各自形成簇
```

## 向量数据库 (Vector Database)

> **向量数据库** 专门存储和检索高维向量，支持高效的相似度搜索（最近邻搜索）。是 RAG 架构的核心组件。

### 相似度搜索算法

| 算法 | 全称 | 特点 |
|------|------|------|
| **KNN** | K-Nearest Neighbor | 精确搜索，计算量大 |
| **ANN** | Approximate Nearest Neighbor | 近似搜索，更快但精度略低 |
| **HNSW** | Hierarchical Navigable Small World | 高效 ANN 算法，广泛使用 |

### 常用向量数据库对比

| 数据库 | 类型 | 特点 |
|--------|------|------|
| **Amazon OpenSearch Serverless** | AWS 托管 | 全文搜索 + 向量搜索，AWS 原生集成 |
| **Amazon Aurora (pgvector)** | 关系型 + 向量 | 已有 Aurora 用户的首选扩展 |
| **Pinecone** | 专用向量数据库 | 使用最简单，丰富云集成 |
| **MongoDB Atlas** | 文档 + 向量 | 灵活的文档模型 |
| **Redis Enterprise Cloud** | 内存 + 向量 | 毫秒级低延迟 |

## 注意力机制详解

### 自注意力 (Self-Attention)

> 让序列中每个词都能"关注"到其他词，理解上下文关系。这种机制帮助模型在**生成每个输出分词**时，权衡输入不同部分的重要性，从而捕获 RNN 等先前架构难以学习的**长距离依赖关系**。

**示例**："银行倒了很多树" vs "他去银行取钱"
- 自注意力帮助模型理解"银行"在不同上下文中的不同含义

#### 自注意力工作原理：Q、K、V 向量

> 自注意力通过为每个输入分词计算三组向量来工作：**查询（Query）、键（Key）、值（Value）**。

| 向量 | 缩写 | 作用 |
|------|------|------|
| **查询向量 (Query)** | Q | 代表当前分词"想要关注什么" |
| **键向量 (Key)** | K | 代表序列中每个分词"能提供什么信息" |
| **值向量 (Value)** | V | 代表实际要传递的信息内容 |

**计算流程**：

```
① 输入嵌入向量 → 线性变换 → 生成 Q、K、V 向量
② Q 与所有 K 做点积（Dot Product）→ 原始注意力分数
③ 归一化（Scale + Softmax）→ 注意力权重（Attention Weights）
④ 注意力权重 × V 向量 → 加权求和 → 当前分词的输出表示
⑤ 在多个层中重复 → 逐步构建输入的复杂语义表示
```

> 此过程在编码器的**多个层**中重复，使模型能够构建越来越复杂的输入表示形式。

#### 位置嵌入 (Positional Embedding)

> **位置嵌入**对序列中每个分词的**相对位置**进行编码，协助模型区分出现在不同位置的相同分词。这对于理解**句子结构和词序**至关重要（Transformer 本身没有内置的顺序感知能力）。

```
示例：
"猫 追 狗" ≠ "狗 追 猫"
                ↑
位置嵌入帮助模型区分相同词在不同位置时的不同语义
```

> 位置编码方案允许模型捕获序列的顺序，**无需进行循环或卷积运算**，这正是 Transformer 能够并行处理的关键。

### 多头注意力 (Multi-Head Attention)

> 并行运行多个注意力头，每个头关注输入的不同方面。

```
多头注意力 = [注意力头1 + 注意力头2 + ... + 注意力头N] → 合并
                  ↓                ↓
            语法关系         语义关系         ... 等多维度
```

## 考试重点总结

### AIF-C01 高频考点

1. **Transformer 是现代 LLM 的基础**（来自 2017 年论文《Attention Is All You Need》）
2. **Transformer 并行处理**：相比 RNN 顺序处理，速度更快、可用更大数据集，可捕获长距离依赖
3. **向量（Vector）**：有序数字列表，表示实体特征，同时表示高维向量空间中的位置
4. **嵌入（Embeddings）**：分词的高维数字向量化表示，捕获语义含义；嵌入传递到自注意力层
5. **语义接近原则**：向量空间距离越近 → 语义越相似
6. **Tokenizer**：将人类文本转为含**分词 ID（输入 ID）的向量**；每个 ID = 词汇表中的一个分词
7. **自注意力 Q/K/V**：查询-键-值机制，通过点积计算注意力权重，加权求和得到输出
8. **位置嵌入**：对每个 Token 的位置编码，帮助模型感知词序（无需循环/卷积）
9. **每个 Transformer 层 = 2 个子层**：自注意力 + 前馈网络，各附残差连接和层归一化
10. **Softmax 输出**：将最终向量转为词汇表概率分布，选取概率最高的 Token
11. **上下文窗口**：模型一次能处理的最大 Token 数
12. **向量数据库**：存储嵌入向量，支持相似度搜索（用于 RAG）
13. **生成式 AI = 深度学习 + Transformer + 超大规模预训练数据**

### 场景题解题思路

```
场景分析 → 选择向量数据库
├── "AWS 原生，全文+向量搜索" → Amazon OpenSearch Serverless
├── "已有 Aurora，想加向量搜索" → Aurora pgvector
├── "最简单，入门快" → Pinecone
├── "低延迟实时查询" → Redis Enterprise Cloud
└── "灵活文档模型" → MongoDB Atlas
```
