# 大语言模型 - LLM

> **大语言模型 (Large Language Model, LLM)** 是生成式 AI 的文本子集，能生成类人自然语言文本，基于 Transformer 架构和大规模语料训练。理解 LLM 的核心概念是 AIF-C01 考试中权重最高的内容（Domain 2 + 3）。
>
> 相关文档：[[Transformer与Embeddings]] | [[提示工程 - Prompt Engineering]] | [[Amazon Bedrock]] | [[AI与ML概念]]

---

## 生成式 AI 与 LLM 的关系

```
生成式 AI (Generative AI)
├── 文本生成 → LLM（大语言模型）← 最常见、最流行
├── 图像生成 → Stable Diffusion、DALL-E、Amazon Titan Image
├── 音频生成 → 音乐合成、语音克隆
└── 视频生成 → 视频合成模型
```

> LLM 是文本模态，是生成式 AI 中最流行的部分，但常被误认为等同于生成式 AI（实际上是子集）。现代 LLM 正进化为**多模态 (Multimodal)**。

---

## 生成式 AI 的本质（考试重点）

> **生成式 AI** 是**深度学习**的子集，也是一种**多用途技术**——专注于生成**全新原创内容**，而非对现有内容进行查找或分类。

### 生成式 AI vs 传统 AI

| 对比维度 | 传统 AI / ML | 生成式 AI |
|---------|------------|---------|
| **核心目标** | 对数据进行**分类**或**预测** | 生成**全新原创内容** |
| **输出类型** | 类别标签、数值预测 | 文本、图像、音频、视频、代码 |
| **技术基础** | 统计模型、监督/无监督学习 | 深度学习 + Transformer + 大规模预训练 |

> **关键区别**：传统 AI 专注于根据输入数据进行**分类或预测**；生成式 AI 专注于创建**全新原创内容**。

### 模型内容生成机制

> 生成式 AI 模型从大量训练数据中**学习统计模式和表示方式**，然后利用这些知识生成与训练数据相似的输出。

```
训练阶段（Pre-training）
    大量数据 → 学习统计模式与表示方式 → 形成数十亿参数（Parameters）

推理阶段（Inference）
    提示词（Prompt）→ 预测下一个词/Token → 输出补全内容（Completion）
```

> 模型核心机制：**对下一个词（Token）应该是什么做出猜测** —— 这是一个概率性的过程，而非确定性结果。

### 模型规模与能力的关系

> 通过增加可训练参数的数量，模型规模也随之增加。

| 规律 | 说明 |
|------|------|
| **参数量↑ → 规模↑** | 增加可训练参数，模型规模也随之增加 |
| **参数量↑ → 内存↑** | 模型参数越多，所需存储内存越多 |
| **参数量↑ → 能力↑** | 更多参数使模型能够执行更高级的任务 |

> 基础模型（Foundation Models）是非常庞大而复杂的神经网络，具有在**训练/预训练阶段**学习的**数十亿个参数**。您可以原样使用这些模型，也可以应用微调技术按照特定使用案例调整模型。

### 生成式 AI 的数学基础

> 大多数 AI/ML/生成式 AI 模型依赖**统计学**和**线性代数**进行计算。机器学习更适合处理数字，而不是原始文本、图像或视频，因此需要这些数学工具做转换和优化。

| 数学工具 | 在生成式 AI 中的用途 |
|---------|------------------|
| **概率建模 (Probability Modeling)** | 计算下一个词/Token 的概率分布 |
| **损失函数 (Loss Functions)** | 衡量预测误差，在训练中用于优化模型参数 |
| **矩阵乘法 (Matrix Multiplication)** | 神经网络层间数据传播的核心深度学习计算 |

## 基础模型 (Foundation Models)

> **基础模型 (Foundation Models, FM)** 是在海量数据上预训练的大型模型，可作为多种下游任务的起点，无需从头训练。

### 基础模型特点

| 特性 | 描述 |
|------|------|
| **大规模预训练** | 在数 TB 文本数据上训练，耗费数百万美元 |
| **通用能力** | 一个模型能胜任翻译、摘要、问答、代码生成等多种任务 |
| **可微调** | 可通过少量数据适配特定领域 |
| **零样本/少样本学习** | 无需额外训练即可执行新任务 |

### 主流基础模型（Amazon Bedrock 提供）

| 模型 | 提供商 | 特点 |
|------|--------|------|
| **Claude** | Anthropic | 长上下文、安全性强 |
| **Llama** | Meta | 开源基础模型 |
| **Mistral** | Mistral AI | 轻量高效 |
| **Titan** | Amazon | AWS 自研系列 |
| **Stable Diffusion** | Stability AI | 图像生成 |
| **Cohere** | Cohere | 企业级文本处理 |

## 预训练（Pre-training）详解

> LLM 对语言的**深度统计表示**进行编码，这种理解在**预训练阶段**逐渐形成——模型从大量非结构化数据中学习，是所有能力的来源。

### 预训练数据规模与来源

| 特性 | 说明 |
|------|------|
| **数据量级** | 千兆字节（GB）→ 太字节（TB）→ **拍字节（PB）**的文本 |
| **数据来源** | 从互联网抓取的内容 + 专门为训练语言模型汇编的大型文本语料库 |
| **计算资源** | 需要大量 **GPU（图形处理单元）**支持大规模矩阵运算，成本极高 |

### 自监督学习（Self-Supervised Learning）

> 预训练采用**自监督学习**方式：模型从数据本身生成训练信号（如预测下一个词），**无需人工标注**。

| 过程 | 说明 |
|------|------|
| **内化模式与结构** | 模型在大量文本中学习语言的规律和统计结构 |
| **完成训练目标** | 学到的模式帮助模型完成架构对应的训练目标（如下一词预测） |
| **权重持续更新** | 训练期间**模型权重不断更新**，以最小化训练目标的**损失函数** |
| **嵌入生成** | 编码器为每个分词生成**嵌入/向量表示** |

### 数据质量策管（考试重点）

> 从互联网等公共来源收集的原始数据必须经过**处理和策管**，以提高质量、消除偏见或删除有害内容。

```
原始互联网数据（海量原始分词）
    ↓ 质量策管（清洗 / 去偏 / 去有害内容）
可用于预训练的数据
    ≈ 原始分词的 1% ~ 3%
```

> **关键数据点（考试）**：经过数据质量策管后，通常**仅有 1%～3% 的分词**用于实际预训练。在估算预训练所需原始数据量时，务必将此倍数纳入计算。

### 涌现能力（Emergent Capabilities）

> 研究人员发现，**模型越大，无需额外上下文学习或进一步训练即可完成任务的可能性就越大**。这种随规模增加而出现的新能力称为**涌现能力（Emergent Capabilities）**。

| 趋势 | 说明 |
|------|------|
| **规模与能力正相关** | 模型能力随规模增加而增加，推动了持续开发更大模型 |
| **训练成本制约** | 训练大型模型既困难又耗资巨大，不能无限扩展 |
| **三大驱动因素** | 高度可扩展的 Transformer 架构 + 海量训练数据 + 强大 GPU 计算资源 |

## 定制化基础模型的三种方式（考试重点）

| 方法 | 描述 | 成本 | 适用场景 |
|------|------|------|---------|
| **提示工程 (Prompt Engineering)** | 通过精心设计输入提示引导模型 | 最低（无需训练） | 快速迭代、通用任务 |
| **RAG（检索增强生成）** | 检索外部知识库注入上下文 | 低（无需训练模型） | 需要最新/私有知识 |
| **Fine-tuning（微调）** | 用特定数据集继续训练模型 | 高（需要训练资源） | 特定领域风格/知识 |

### 选择逻辑

```
选择定制化方式
├── "需要最新信息（实时数据）" → RAG
├── "需要私有企业知识" → RAG（Knowledge Base）
├── "需要特定风格/语气" → Fine-tuning
├── "需要特定领域专业知识" → Fine-tuning 或 Domain-specific RAG
└── "快速测试和原型" → 提示工程（Prompt Engineering）
```

## Fine-tuning 微调

> **Fine-tuning** 是在预训练基础模型上，使用较小的特定数据集继续训练，使模型适应特定任务或领域。

### 微调类型

| 类型 | 描述 |
|------|------|
| **指令微调 (Instruction Fine-tuning)** | 提供输入-输出对示例，教模型遵循指令 |
| **领域特定微调 (Domain-specific Fine-tuning)** | 使用特定领域知识库微调，增强专业能力 |
| **持续预训练 (Continuous Pre-training)** | 在已有知识上追加训练新知识 |

### Fine-tuning 数据格式

```json
{
  "prompt": "系统提示（定义任务）\n\n### 输入：\n[具体输入内容]\n\n### 响应：",
  "completion": "[期望的模型输出]"
}
```

> 常用 **JSONL 格式**（每行一个 JSON 对象）作为微调数据集格式。

## RAG（检索增强生成）

> **RAG (Retrieval-Augmented Generation)** 在 LLM 生成响应之前，先从外部知识库检索相关信息，注入上下文，从而避免模型幻觉、提供最新知识。

### RAG 工作流程

```
用户提问 → 向量化查询 → 搜索向量数据库 → 检索相关文档块
    ↓                                              ↓
生成响应 ← LLM 推理 ← 注入上下文 + 提问 ← 返回相关知识
```

### RAG 核心组件

| 组件 | 描述 | AWS 对应服务 |
|------|------|------------|
| **向量数据库** | 存储文档的向量嵌入 | OpenSearch、Aurora（pgvector）、Pinecone |
| **嵌入模型** | 将文本转为向量 | Amazon Titan Embeddings、Cohere Embed |
| **知识库** | 文档存储 | Amazon S3 |
| **检索器** | 根据查询找到最相关文档 | Amazon Bedrock Knowledge Bases |
| **LLM** | 基于检索结果生成答案 | Amazon Bedrock 各模型 |

### RAG 数据库选择

| 向量数据库 | 特点 |
|-----------|------|
| **Amazon OpenSearch Serverless** | AWS 原生，全托管，支持向量搜索 |
| **Amazon Aurora (pgvector)** | 关系型数据库扩展，适合已用 Aurora 的场景 |
| **Pinecone** | 第三方，易用，多种嵌入支持，丰富云集成 |
| **MongoDB Atlas** | 文档数据库 + 向量搜索 |
| **Redis Enterprise Cloud** | 低延迟，适合实时查询 |

## 模型幻觉 (Hallucination)

> **幻觉** 是 LLM 自信地生成错误或虚构信息的现象。

| 原因 | 缓解方法 |
|------|---------|
| 训练数据截止日期之后的信息 | 使用 RAG 提供最新知识 |
| 训练数据中的错误或偏见 | Fine-tuning 修正 |
| 模型对边缘知识的不确定 | 提示中要求引用来源 |
| 温度参数过高 | 降低 Temperature 参数 |

## 单模态 vs 多模态模型

### 定义对比

| 类型 | 定义 | 示例 |
|------|------|------|
| **单模态 (Unimodal)** | 专注于处理**一种**数据模态，输入和输出均为同一类型 | LLM（文本输入→文本补全） |
| **多模态 (Multimodal)** | 处理和生成**多种**数据类型（文本 + 图像 + 视频 + 音频） | GPT-4V、Claude（图文）、DALL-E |

> **LLM 是单模态生成式 AI** 的典型示例：输入是文本，输出（补全）也是文本。

### 多模态模型的优势

> 多模态模型可以理解**不同来源的数据**，提供**更可靠的预测**。这种能力融合了跨模型推理、翻译、搜索和创作，更接近人类智能。

### 多模态使用案例

| 使用案例 | 说明 |
|---------|------|
| **图像字幕 (Image Captioning)** | 模型为图像生成文本描述 |
| **可视化问答 (Visual Q&A)** | 模型回答关于图像内容的问题 |
| **文本到图像合成** | 根据文本描述生成图像（DALL-E、Stable Diffusion、Midjourney） |
| **营销与产品设计** | 生成营销素材、产品概念图 |
| **客户服务 / 聊天机器人** | 结合文字和视觉的多模态交互 |
| **虚拟化身 (Virtual Avatar)** | 基于文字或图像生成虚拟形象 |

## 扩散模型 (Diffusion Models)（考试重点）

> **扩散模型**是一种生成模型类别，学习如何**反转一个渐进产生噪声的过程**——从随机噪声出发，通过迭代降噪生成高质量图像或音频。它们支持多模态模型的各类任务，包括图像生成、分辨率提升和局部重绘。

### 三个主要组成部分（考试必记）

| 组成部分 | 英文 | 说明 |
|---------|------|------|
| **正向扩散** | Forward Diffusion | 向原始数据**逐步添加高斯噪声**，直到变为纯随机噪声 |
| **反向扩散** | Reverse Diffusion | 训练模型**逐步预测并去除噪声**，从噪声恢复原始数据分布 |
| **稳定扩散** | Stable Diffusion | 在**隐空间（Latent Space）** 而非像素空间中执行扩散，效率更高 |

```
正向扩散：原始图像 → 逐步加高斯噪声 → 纯随机噪声
反向扩散：纯随机噪声 → 模型逐步预测噪声并去除 → 生成目标图像
稳定扩散：在低维隐空间（而非原始像素空间）中执行上述过程
```

> 扩散模型尝试根据上一步的部分降噪输出**预测每一步添加的噪声**，从随机噪声开始，通过迭代降噪生成连贯的高质量输出。

### Stable Diffusion 的特点

| 特性 | 说明 |
|------|------|
| **隐空间 (Latent Space)** | 不在像素空间操作，而在**压缩后的隐空间**中进行扩散，速度更快 |
| **高斯噪声编码** | 使用高斯噪声对图像进行编码，再通过噪声预测器和反向扩散重现图像 |
| **AWS 访问方式** | 通过 **Amazon SageMaker JumpStart** 访问，只需几行代码即可微调和部署 |

### 扩散模型 vs 其他生成方法

| 方法 | 优势 | 劣势 |
|------|------|------|
| **扩散模型** | 输出质量更高、多样性和一致性更强、训练**更稳定**且更易于训练 | 推理速度相对较慢 |
| **生成式对抗网络 (GAN)** | 推理速度快 | 训练不稳定，容易模式崩溃 |
| **变分自编码器 (VAE)** | 训练稳定 | 生成质量相对较低 |

### 扩散模型示例

| 模型 | 用途 | AWS 访问 |
|------|------|---------|
| **Stable Diffusion** | 文本到图像生成 | SageMaker JumpStart |
| **DALL-E** | 文本到图像合成 | — |
| **Midjourney** | 艺术风格图像生成 | — |
| **Whisper** | 语音识别与翻译（音频扩散） | — |
| **AudioLM** | 音频生成 | — |

## 模型推理参数

| 参数 | 描述 | 影响 |
|------|------|------|
| **Temperature** | 控制输出随机性（0-1） | 低→确定性强，高→创意性强 |
| **Top P** | 概率核采样（0-1） | 控制输出词汇的多样性 |
| **Top K** | 每步只从前 K 个词中选择 | 限制候选词范围 |
| **Max Tokens** | 最大输出长度 | 控制响应长度 |

```
参数调整场景
├── "需要一致性/精确答案" → Temperature 低（接近 0）
├── "需要创意写作/多样输出" → Temperature 高（接近 1）
└── "控制成本/简洁回复" → Max Tokens 设置上限
```

| 模式 | 描述 | 成本特点 |
|------|------|---------|
| **On-Demand（按需）** | 无需预置，按调用次数计费（类似 Serverless） | 弹性，适合变化负载 |

## 主要生成式 AI 架构对比（考试重点）

> 考试要求了解以下主要架构的优势和局限性，在选择合适架构前应先评估目标和数据集。

| 架构 | 全称 | 工作原理 | 优势 | 局限性 | 典型用途 |
|------|------|---------|------|-------|---------|
| **Transformer** | — | 自注意力机制，并行处理序列 | 长距离依赖、可并行训练、规模可扩展 | 计算资源需求大 | LLM、文本生成、翻译 |
| **GAN** | 生成式对抗网络 | 生成器 vs 判别器对抗博弈 | 高质量图像生成 | 训练不稳定，易模式崩溃 | 图像合成、数据增强 |
| **VAE** | 变分自编码器 | 编码到潜在空间→采样→解码生成 | 训练稳定，潜在空间可插值 | 生成质量相对较低 | 图像生成、异常检测 |
| **自回归模型** | Autoregressive Model | 逐词预测，基于前文生成下一词 | 精确概率建模，文本质量高 | 生成速度较慢（顺序计算） | 文本生成（GPT 系列） |
| **扩散模型** | Diffusion Model | 迭代从噪声去噪生成内容 | 质量高、多样性强、训练稳定 | 推理速度较慢 | 图像/音频生成 |

```
选择架构
├── "文本生成 / NLP" → Transformer（LLM）或 自回归模型
├── "高质量图像生成（可接受训练不稳定）" → GAN
├── "稳定训练、高质量图像生成" → 扩散模型（Stable Diffusion）
├── "图像生成 + 可编辑潜在空间" → VAE
└── "根据文字描述生成图像（AWS）" → SageMaker JumpStart（Stable Diffusion）
```

## 生成式 AI 的优势与局限性（Task Statement 2.2）

### 优势

| 优势 | 说明 |
|------|------|
| **适应性 (Adaptability)** | 一个基础模型可适用于多种不同任务，无需单独训练 |
| **响应能力 (Responsiveness)** | 可实时生成对自然语言提示词的响应 |
| **简单性 (Simplicity)** | 简化了许多 AI 应用程序的构建过程，成本更低、速度更快 |
| **通用技术** | 跨越多个经济领域的众多应用程序均可使用 |

### 局限性

| 局限性 | 说明 | 缓解方法 |
|-------|------|---------|
| **幻觉 (Hallucination)** | 自信地给出错误或虚构的答案 | RAG、降低 Temperature、RLHF |
| **无记忆性（无状态）** | 每次调用独立，不记得之前的对话 | 在提示词中携带历史；使用 RAG |
| **知识截止日期** | 只知道训练截止日期前的信息 | RAG（检索最新信息） |
| **复杂推理有限** | 在复杂多步推理和数学方面可能出错 | 思维链 (CoT) 提示、RLHF |
| **有毒/有害输出** | 互联网训练数据含不当语言 | 指令微调 + RLHF + Guardrails |

> **10 岁孩子类比**：如果一个 10 岁孩子按提示词说明能完成某任务（如判断邮件是否为投诉），LLM 一般也能做到。但对于需要新知识（如新 AWS 服务详情）的任务，需先通过 RAG 提供相关文档。

### 五个阶段总览

```
① 确定使用案例（Identify Use Case）
   └─ 明确 LLM 的具体角色；范围越窄越省成本

③ 适应、调整和增强（Adapt, Align, Augment）
   └─ 提示工程 → 上下文学习 → Fine-tuning → RLHF（高度迭代）
④ 评估、部署和迭代（Evaluate, Deploy, Iterate）
   └─ 指标评估 → 部署到基础设施 → 与应用集成 → 优化计算资源
⑤ 监控（Monitor）
   └─ 持续监控性能、安全、质量和合规性
```

### 基础模型生命周期（考试指南明确列出）

| 阶段 | 说明 |
|------|------|
| **1. 数据选择** | 收集、清洗、策管训练数据（仅 1-3% 的原始分词可用） |
| **2. 模型选择** | 选择合适的架构和基础模型 |
| **3. 预训练** | 在大规模数据上自监督学习 |

| **6. 部署** | 部署到生产环境，与应用集成 |

## 迁移学习（Transfer Learning）

> **迁移学习**是将预训练模型中已学到的知识**迁移**到新任务上，使用**预训练模型**作为新数据集训练的起点，无需从头训练。这是微调基础模型的核心原理。

| 特性 | 说明 |
|------|------|
| **更小的数据集** | 只需相对少量的特定领域数据即可微调 |
| **更少的训练时间** | 模型已具备通用知识，只需适配新领域 |
| **更快的上市速度** | 大幅缩短从数据收集到部署的周期 |

```
预训练通用基础模型（已学习广泛语言/图像知识）
    ↓ 迁移学习（Transfer Learning）
使用小型特定数据集微调（Fine-tuning）
    ↓
适应特定任务/领域的专用模型
```

> **SageMaker JumpStart** 提供预构建的基础模型和解决方案，可基于自定义数据集快速进行迁移学习，并快速投入生产。

## RLHF（基于人类反馈的强化学习）（考试重点）

> **RLHF (Reinforcement Learning from Human Feedback)** 是一种通过引入**人类反馈**来微调和对齐 LLM 的技术，使其输出更符合人类偏好。

### HHH 原则（三个核心价值观）

| 价值观 | 英文 | 说明 |
|-------|------|------|
| **有用性 (Helpful)** | Helpful | 提供真正有帮助的答案 |
| **诚实性 (Honest)** | Honest | 不产生幻觉或虚假信息 |
| **无害性 (Harmless)** | Harmless | 不生成有毒、攻击性或有害内容 |

### RLHF 的作用

| 问题 | RLHF 的解决方式 |
|------|--------------|
| LLM 使用有毒语言 | 人工标注不良响应，降低其权重 |
| 生成错误/有害信息 | 强化学习使模型趋向准确、无害的响应 |
| 输出不自然 | 对更自然语言的响应给予正向奖励 |

> **重要提示**：仅通过 RLHF 训练可能很难克服 LLM 的某些基本局限性，如复杂推理、数学计算等问题。

## 考试重点总结

### AIF-C01 高频考点

**生成式 AI 基础**
1. **LLM 是生成式 AI 的文本子集**（非等价关系）
2. **生成式 AI 是深度学习的子集**，用于创建全新原创内容（非分类/预测）
3. **模型输出机制**：预测下一个词/Token，是概率性猜测过程
4. **参数量 → 规模 → 内存 → 能力**（正向关系）
5. **数学基础**：概率建模、损失函数、矩阵乘法

**预训练与规模**
6. **预训练 = 自监督学习**：从 GB/TB/PB 级文本中学习语言统计表示
7. **数据质量策管**：策管后仅 **1%～3%** 的分词用于预训练（重要估算倍数）
8. **涌现能力**：模型越大，无需 few-shot 即可完成更多任务
9. **迁移学习**：用预训练模型作起点 + 小型数据集微调，节省时间和成本

**生成模型架构**
10. **单模态 vs 多模态**：LLM = 单模态（文本↔文本）；多模态 = 文本 + 图像 + 音频
11. **扩散模型三大组成**：正向扩散 / 反向扩散 / 稳定扩散（考试必记）
12. **Stable Diffusion = 隐空间**（非像素空间），SageMaker JumpStart 提供
13. **GAN vs VAE vs 扩散模型**：GAN 质量高但训练不稳定；VAE 稳定但质量低；扩散最佳
14. **自回归模型**：逐词顺序预测（GPT 系列），文本质量高但生成慢

**优势与局限**
15. **三大优势**：适应性、响应能力、简单性
16. **LLM 无记忆性（无状态）**：每次调用独立，不记得之前对话
17. **幻觉**：LLM 自信给出错误答案；RAG + Temperature + RLHF 缓解

**项目开发**
18. **项目生命周期**：确定使用案例 → 实验选择 → 适应调整（高度迭代）→ 评估部署 → 监控
19. **基础模型生命周期**：数据选择 → 模型选择 → 预训练 → 微调 → 评估 → 部署 → 反馈
20. **开发顺序**：提示工程先行 → 上下文学习 → Fine-tuning → RLHF（成本由低到高）
21. **RLHF**：HHH 原则（有用 / 诚实 / 无害）；降低毒性和错误信息

**定制与部署**
22. **三种定制方式**：提示工程（免训练）/ RAG（实时知识）/ Fine-tuning（专业能力）
23. **RAG 解决幻觉问题**：检索最新/私有知识注入上下文
24. **Temperature 参数**：低=确定，高=创意
25. **部署模式**：On-Demand vs Provisioned Throughput，自定义模型必须用后者

**使用案例**
26. **代码生成**：Amazon Q Developer（前身 CodeWhisperer）
27. **企业搜索**：Amazon Kendra；**推荐**：Amazon Personalize；**聊天机器人**：Amazon Lex

### 场景题解题思路

```
场景分析 → 选择 LLM 定制方式
├── "模型不知道公司内部文档" → RAG（Knowledge Base）
├── "需要模型写特定格式报告" → Fine-tuning（指令微调）
├── "回答总是太随机/不一致" → 降低 Temperature
├── "需要最新新闻信息" → RAG（不能靠 Fine-tuning，数据会过期）
└── "快速验证 AI 方案可行性" → 提示工程（Prompt Engineering）

场景分析 → 识别模型类型
├── "输入文本，输出文本" → 单模态 LLM
├── "输入图像+文本，输出文本" → 多模态模型
├── "根据文字描述生成图像" → 扩散模型（Stable Diffusion / DALL-E）
├── "语音识别/翻译" → Whisper（扩散模型类）
├── "需要高质量图像生成，稳定训练" → 扩散模型（优于 GAN/VAE）
└── "在 AWS 上快速部署图像生成模型" → SageMaker JumpStart（Stable Diffusion）

场景分析 → 预训练数据问题
├── "模型训练需要多少原始数据" → 目标数据量 ÷ 1%~3%（策管后仅留 1-3%）
└── "模型在某类任务无需示例即可完成" → 涌现能力（模型规模足够大）
```
