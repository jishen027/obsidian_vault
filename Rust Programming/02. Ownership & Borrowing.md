# Ownership & Borrowing - Memory Management Without a GC

> **Ownership** is the idea that sets Rust apart from other languages. In C# and JavaScript a **garbage collector** decides when memory is freed. In Rust the **compiler** decides, using a few simple rules it checks at compile time. Learn this note well and the rest of Rust gets much easier.
>
> Related notes: [[01. Introduce Rust]] | [[03. Lifetimes]] | [[07. Concurrency]]

---

## Mental Model: Coming from C# / JavaScript

### How the three languages handle memory

| Topic | C# | JavaScript | Rust |
|------|----|-----------|------|
| **Who frees memory?** | GC (non-deterministic) | GC (non-deterministic) | Compiler-inserted `drop` at end of scope (**deterministic**) |
| **`b = a` for a heap object** | Copies the **reference**: both point to the same object | Copies the **reference**: both point to the same object | **Moves** ownership: `a` is no longer usable |
| **Value copy semantics** | `struct` types (int, DateTime, custom structs) | Primitives (number, string, boolean) | Types that implement `Copy` (i32, f64, bool, char, ...) |
| **Explicit deep copy** | `MemberwiseClone()`, copy constructor | `structuredClone()`, spread `{...obj}` (shallow) | `.clone()` |
| **Deterministic cleanup** | `IDisposable` + `using` | none (`try/finally`) | **Automatic**: every value acts as if it were inside a `using` |
| **Pass by reference** | `ref` / `in` / `out` | Objects are always shared references | `&mut T` / `&T` (borrow) |

> **Key point**: In C#/JS, many variables can point to the same heap object, and the GC frees it once nobody references it. Rust instead says that **every value has exactly one owner**. Others may only **borrow** it, briefly, under strict rules.

### Stack vs Heap (quick refresher)

| | Stack | Heap |
|---|-------|------|
| Stores | Fixed-size values known at compile time (`i32`, `bool`, `[u8; 4]`) | Growable / dynamically sized data (`String`, `Vec<T>`, `Box<T>`) |
| Speed | Very fast (push/pop) | Slower (allocation + pointer chase) |
| C# analogy | Value types (locals) | Objects created with `new` |

Ownership rules mainly matter for **heap-owning** types like `String` and `Vec`.

## The Three Ownership Rules

1. Each value has an **owner** (a variable).
2. There can only be **one owner at a time**.
3. When the owner goes **out of scope**, the value is **dropped** (memory freed).

```rust
fn main() {
    {
        let s = String::from("hello");  // s owns the heap string
        println!("{s}");
    }                                    // scope ends → s dropped → memory freed
    // println!("{s}");                  // ❌ s doesn't exist here
}
```

### Move semantics

```rust
let s1 = String::from("hello");
let s2 = s1;              // ownership MOVES from s1 to s2 (no deep copy!)
// println!("{s1}");      // ❌ E0382: borrow of moved value: `s1`
println!("{s2}");         // ✅
```

Compare C#:

```csharp
var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;        // both point to the SAME list
list2.Add(4);
Console.WriteLine(list1.Count); // 4 — surprise shared mutation
```

Rust rules this out: after the move, only **one** variable can reach the data.

### Copy types (behave like C# structs / JS primitives)

Simple stack-only types implement the `Copy` trait, so assignment **copies** the value and both variables stay valid:

```rust
let a = 5;
let b = a;                // copy
println!("{a} {b}");      // ✅ both valid
```

| `Copy` types | Not `Copy` (move instead) |
|------------|--------------------------|
| `i32`, `u64`, `f64`, `bool`, `char` | `String`, `Vec<T>`, `HashMap<K, V>` |
| `&T` (shared references) | `Box<T>`, `&mut T` |
| Tuples/arrays of `Copy` types: `(i32, bool)`, `[u8; 4]` | Any struct holding a non-`Copy` field |

### Clone: an explicit deep copy

```rust
let s1 = String::from("hello");
let s2 = s1.clone();      // deep copy of the heap data
println!("{s1} {s2}");    // ✅ both valid
```

> **Key point**: `.clone()` is always **visible** in the code, so you can spot expensive copies at a glance. A beginner's shortcut: when the borrow checker blocks you, `.clone()` often gets you unstuck. Refine the code later.

### Ownership and functions

Passing a value to a function **moves** it, just like assignment:

```rust
fn take(s: String) {
    println!("{s}");
}                          // s dropped here

fn main() {
    let s = String::from("hi");
    take(s);               // ownership moved into take()
    // println!("{s}");    // ❌ E0382: s was moved
}
```

Moving a value in and handing it back again is clumsy. That's why Rust has **borrowing**.

## Borrowing (References)

A **reference** lets you use a value **without taking ownership**. Creating one is called **borrowing**.

```rust
fn length(s: &String) -> usize {   // borrows s
    s.len()
}                                   // nothing dropped: we didn't own it

fn main() {
    let s = String::from("hello");
    let n = length(&s);             // lend s
    println!("{s} has {n} chars");  // ✅ s still valid
}
```

### Mutable borrows

```rust
fn shout(s: &mut String) {
    s.push_str("!");
}

fn main() {
    let mut s = String::from("hi"); // variable must be `mut`
    shout(&mut s);                  // lend mutably
    println!("{s}");                // "hi!"
}
```

C# analogy: `void Shout(ref string s)`. Unlike C#, Rust writes `&mut` at the **call site**, so mutation can't hide.

### The borrowing rules (the core of Rust)

At any moment, a value can have **either**:

| Option | Syntax | Count |
|--------|--------|-------|
| **Many readers** | `&T` | any number of immutable references |
| **One writer** | `&mut T` | exactly **one** mutable reference, and **no** readers |

…and every reference must always point to valid data (see [[03. Lifetimes]]).

> **Key point**: "**Many readers XOR one writer.**" This one rule prevents data races, iterator invalidation and dangling pointers, all at compile time.

### Why this matters: an example C# developers will recognise

```csharp
// C# — compiles fine, crashes at RUNTIME
var nums = new List<int> { 1, 2, 3 };
foreach (var n in nums)
    nums.Add(n);  // InvalidOperationException: Collection was modified
```

```rust
// Rust — rejected at COMPILE time
let mut v = vec![1, 2, 3];
let first = &v[0];        // immutable borrow
v.push(4);                // ❌ E0502: cannot borrow `v` as mutable because it is also borrowed as immutable
println!("{first}");
```

Why? `push` may **reallocate** the vector, which would leave `first` pointing at freed memory. C++ would let this through and crash; C# would throw at runtime. Rust refuses to compile it.

### Borrows end at their last use (Non-Lexical Lifetimes)

```rust
let mut s = String::from("hi");
let r1 = &s;
let r2 = &s;
println!("{r1} {r2}");    // last use of r1 and r2
let r3 = &mut s;          // ✅ OK: the earlier borrows have ended
r3.push('!');
```

## Slices: `String` vs `&str`

A **slice** is a borrowed view into part of a collection.

| Type | Owns data? | C# analogy | Use for |
|------|-----------|-----------|---------|
| `String` | ✅ heap, growable | `StringBuilder` / `string` | Owned, modifiable text; struct fields |
| `&str` | ❌ borrowed view | `ReadOnlySpan<char>` | Function parameters, string literals |
| `Vec<T>` | ✅ | `List<T>` | Owned list |
| `&[T]` | ❌ | `ReadOnlySpan<T>` / `ArraySegment<T>` | Read-only parameter for any list or array |

```rust
fn first_word(s: &str) -> &str {      // accepts &String AND string literals
    s.split(' ').next().unwrap_or("")
}

fn main() {
    let owned = String::from("hello world");
    println!("{}", first_word(&owned));       // &String auto-converts to &str
    println!("{}", first_word("good morning")); // literals are &'static str
}
```

> **Key point (idiom)**: Take **`&str`** and **`&[T]`** as parameters, not `&String` or `&Vec<T>`. They accept more inputs at no extra cost.

## Common Compiler Errors & Fixes

| Error | Meaning | Typical fix |
|-------|---------|-------------|
| **E0382** use of moved value | You used a variable after moving it | Borrow (`&x`) instead, or `.clone()` |
| **E0499** two mutable borrows | Two `&mut` to the same value are alive at once | Narrow the scope of the first borrow |
| **E0502** mutable + immutable borrow | Reading and writing overlap | Finish reading before you mutate; copy the value out first |
| **E0596** cannot borrow as mutable | Variable isn't declared `mut` | `let mut x = ...` |
| **E0106** missing lifetime specifier | Returning a reference with unclear origin | Return an owned value, or see [[03. Lifetimes]] |

## Cheat Sheet

```
Do I need to give this value away forever?   → pass by value (move):  fn f(x: T)
Do I just need to read it?                   → shared borrow:         fn f(x: &T)
Do I need to modify it in place?             → mutable borrow:        fn f(x: &mut T)
Do I need an independent copy?               → x.clone()
```
