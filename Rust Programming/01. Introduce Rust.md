# Introduce Rust - What Rust Is and Why It Exists

> **Rust** is a systems programming language built around three goals: **speed, memory safety, and fearless concurrency**. It delivers C/C++-level performance while eliminating whole classes of memory bugs **at compile time**, without a garbage collector.
>

## The Problem Rust Solves

### The memory-management trade-off

| Approach | Languages | Trade-off |
|----------|-----------|-----------|
| **Manual memory management** | C, C++ | Fast, but prone to use-after-free, double-free, buffer overflows, data races |
| **Garbage collection (GC)** | Java, Go, Python, C# | Safe, but runtime overhead and unpredictable GC pauses |
| **Ownership + borrow checker** | **Rust** | Safe **and** fast; the cost is a steeper learning curve |

> **Key point**: Roughly **70%** of serious security vulnerabilities reported by Microsoft and Chromium are memory-safety bugs. Rust's design prevents most of them before the program ever runs.

### Choosing a language (rough guide)

```
What do you need?
├── Max performance + memory safety + no GC     → Rust
├── Max performance, huge existing codebase     → C / C++
├── Simple concurrent network services, fast dev → Go
├── Enterprise apps, large ecosystem            → Java / C#
└── Scripting, data science, rapid prototyping  → Python
```

## Core Concepts

### 1. Ownership

Every value has **exactly one owner**. When the owner goes out of scope, the value is dropped (memory freed) automatically.

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1;            // ownership MOVES to s2
    // println!("{}", s1);  // ❌ compile error: value borrowed after move
    println!("{}", s2);     // ✅
}                           // s2 goes out of scope → memory freed
```

> **Key point**: Three ownership rules — (1) each value has one owner, (2) only one owner at a time, (3) when the owner goes out of scope, the value is dropped. Details in [[02. Ownership & Borrowing]].

### 2. Borrowing & References

You can lend access to a value without transferring ownership.

| Reference type | Syntax | How many at once? |
|----------------|--------|-------------------|
| **Immutable borrow** | `&T` | Any number |
| **Mutable borrow** | `&mut T` | Exactly **one**, and no immutable borrows at the same time |

```rust
fn length(s: &String) -> usize { s.len() }  // borrows, does not take ownership

fn main() {
    let mut s = String::from("hi");
    let n = length(&s);     // immutable borrow
    s.push_str(" there");   // ✅ mutation OK — the borrow above has ended
    println!("{s} ({n})");
}
```

> **Key point**: "Many readers XOR one writer" — this single rule prevents **data races** at compile time.

### 3. Lifetimes

The compiler tracks how long every reference is valid, guaranteeing a reference never outlives the data it points to → **no dangling pointers**. Most lifetimes are inferred; explicit annotations (`'a`) are only needed in ambiguous cases. See [[03. Lifetimes]].

### 4. No Null, No Exceptions

| Concept | Replaces | Variants |
|---------|----------|----------|
| **`Option<T>`** | `null` | `Some(value)` / `None` |
| **`Result<T, E>`** | Exceptions | `Ok(value)` / `Err(error)` |

```rust
fn divide(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 { Err("divide by zero".into()) } else { Ok(a / b) }
}

fn main() {
    match divide(10.0, 2.0) {
        Ok(v)  => println!("result = {v}"),
        Err(e) => println!("error: {e}"),
    }
}
```

> **Key point**: The compiler **forces** you to handle both cases (via `match`, `?`, `unwrap`, etc.), so "forgot to check for null" bugs disappear. See [[05. Error Handling]].

### 5. Zero-Cost Abstractions

High-level features — iterators, closures, generics, traits — compile down to code as efficient as hand-written low-level loops. "What you don't use, you don't pay for."

```rust
let sum: i32 = (1..=100).filter(|n| n % 2 == 0).sum();  // as fast as a manual for-loop
```

### 6. Fearless Concurrency

The type system (marker traits **`Send`** and **`Sync`**) prevents sharing data unsafely across threads. If it compiles, it is free of data races. See [[07. Concurrency]].

### 7. `unsafe` Escape Hatch

For low-level work (FFI, raw pointers, hardware access), code can opt out of some checks inside an `unsafe { }` block. Safety bugs are then confined to small, auditable regions.

## Coming from C# / JavaScript: Quick Syntax Map

| Concept              | C#                                | JavaScript                             | Rust                                          |
| -------------------- | --------------------------------- | -------------------------------------- | --------------------------------------------- |
| Variable             | `var x = 5;`                      | `let x = 5;`                           | `let x = 5;` (**immutable** by default)       |
| Mutable variable     | `var x = 5;`                      | `let x = 5;`                           | `let mut x = 5;`                              |
| Constant             | `const int Max = 10;`             | `const MAX = 10;`                      | `const MAX: u32 = 10;`                        |
| Function             | `int Add(int a, int b) => a + b;` | `function add(a, b) { return a + b; }` | `fn add(a: i32, b: i32) -> i32 { a + b }`     |
| String interpolation | `$"Hi {name}"`                    | `` `Hi ${name}` ``                     | `format!("Hi {name}")`                        |
| Print                | `Console.WriteLine(x)`            | `console.log(x)`                       | `println!("{x}")`                             |
| List                 | `List<int>`                       | `[]`                                   | `Vec<i32>` / `vec![1, 2, 3]`                  |
| Dictionary           | `Dictionary<K, V>`                | `Map` / `{}`                           | `HashMap<K, V>`                               |
| Null                 | `null`                            | `null` / `undefined`                   | `Option<T>` → [[05. Error Handling]]          |
| Exceptions           | `try` / `catch`                   | `try` / `catch`                        | `Result<T, E>` + `?` → [[05. Error Handling]] |
| Class                | `class`                           | `class`                                | `struct` + `impl` → [[04. Structs & Enums]]   |
| Interface            | `interface`                       | (TS) `interface`                       | `trait` → [[06. Traits & Generics]]           |
| Lambda               | `x => x * 2`                      | `x => x * 2`                           | `\|x\| x * 2`                                 |
| LINQ / array methods | `.Where().Select()`               | `.filter().map()`                      | `.iter().filter().map().collect()`            |
| Async                | `async Task<T>` + `await x`       | `async` + `await x`                    | `async fn` + `x.await` → [[07. Concurrency]]  |
| Package manager      | NuGet                             | npm                                    | Cargo / crates.io                             |
| Memory               | Garbage collector                 | Garbage collector                      | Ownership → [[02. Ownership & Borrowing]]     |

> **Key point**: Rust is **expression-based**. The last expression in a block **without a semicolon** is its value, so `fn add(a: i32, b: i32) -> i32 { a + b }` needs no `return`. `if` and `match` return values too: `let x = if ok { 1 } else { 0 };`.

## Tooling & Ecosystem

| Tool | Purpose |
|------|---------|
| **`rustup`** | Installs and manages Rust toolchains (stable / beta / nightly) |
| **`cargo`** | Build system + package manager |
| **crates.io** | Public package registry (packages are called **crates**) |
| **`rustfmt`** | Official code formatter (`cargo fmt`) |
| **`clippy`** | Linter with hundreds of idiom checks (`cargo clippy`) |
| **rust-analyzer** | Language server for IDE support (VS Code, JetBrains, etc.) |
| **docs.rs** | Auto-generated documentation for every published crate |

### Common Cargo commands

```bash
cargo new hello_rust   # create a new project
cd hello_rust
cargo run              # compile + run → prints "Hello, world!"
cargo build --release  # optimized build
cargo test             # run tests
cargo check            # type-check quickly without producing a binary
cargo add serde        # add a dependency
```

### Project layout

```
hello_rust/
├── Cargo.toml   # project manifest: name, version, dependencies
├── Cargo.lock   # exact resolved dependency versions
└── src/
    └── main.rs  # entry point: fn main()
```

## Pros & Cons

| Pros ✅ | Cons ❌ |
|---------|---------|
| Memory safety without GC | Steep learning curve ("fighting the borrow checker") |
| C/C++-level performance | Slower compile times |
| Data-race-free concurrency | More verbose than Python / Go |
| Excellent tooling (cargo, clippy, rustfmt) | Younger ecosystem in some domains |
| Exceptionally helpful compiler errors | Some patterns (graphs, self-referential structs) are awkward |
