# Traits & Generics - Shared Behavior Without Inheritance

> A **trait** defines behavior that types can implement, close to a **C# interface**. Combined with **generics**, traits are how Rust gets polymorphism without inheritance. This note also covers **iterators** (Rust's LINQ) and **closures** (Rust's lambdas / arrow functions).
>
> Related notes: [[01. Introduce Rust]] | [[04. Structs & Enums]] | [[05. Error Handling]] | [[07. Concurrency]]

---

## Concept Mapping

| C# | JavaScript / TypeScript | Rust |
|----|------------------------|------|
| `interface IShape` | (TS) `interface Shape` | `trait Shape` |
| `class Circle : IShape` | `class Circle implements Shape` | `impl Shape for Circle` |
| Default interface methods (C# 8+) | — | Default trait methods |
| Extension methods | Prototype patching (discouraged) | Implement your own trait for an existing type |
| `where T : IComparable<T>` | (TS) `<T extends Comparable>` | `T: PartialOrd` / `where T: PartialOrd` |
| `List<IShape>` (virtual dispatch) | Array of objects (duck typing) | `Vec<Box<dyn Shape>>` |
| LINQ (`Select`, `Where`, ...) | Array methods (`map`, `filter`, ...) | Iterator adaptors (`map`, `filter`, ...) |
| `Func<T, R>` / `Action<T>` / lambda | Arrow function | Closure: `Fn` / `FnMut` / `FnOnce` |
| Operator overloading (`operator +`) | — | Implement `std::ops::Add` |

## Traits

### Defining and implementing

```rust
trait Shape {
    fn area(&self) -> f64;                     // required method

    fn describe(&self) -> String {             // default method (can be overridden)
        format!("shape with area {:.2}", self.area())
    }
}

struct Circle { r: f64 }
struct Square { side: f64 }

impl Shape for Circle {
    fn area(&self) -> f64 { std::f64::consts::PI * self.r * self.r }
}

impl Shape for Square {
    fn area(&self) -> f64 { self.side * self.side }
    fn describe(&self) -> String { format!("square {}x{}", self.side, self.side) }
}
```

C#, for comparison:

```csharp
interface IShape {
    double Area();
    string Describe() => $"shape with area {Area():F2}";  // default interface method
}
class Circle : IShape { public double R; public double Area() => Math.PI * R * R; }
```

> **Key point**: In C#, a class lists its interfaces **in its own declaration**. In Rust, `impl Trait for Type` is a **separate block**, so you can add a trait to a type **after** it's defined, even a type from the standard library.

### Traits on existing types (like C# extension methods)

```rust
trait Shout {
    fn shout(&self) -> String;
}

impl Shout for str {
    fn shout(&self) -> String { self.to_uppercase() + "!" }
}

fn main() {
    println!("{}", "hello".shout());   // "HELLO!"
}
```

> **Orphan rule**: you can only write `impl Trait for Type` if **either** the trait **or** the type is defined in your crate. You can't implement `Display` for `Vec<T>`, because both are foreign.

## Generics

### Generic functions with trait bounds

```rust
fn largest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut max = items[0];
    for &item in items {
        if item > max { max = item; }
    }
    max
}

fn main() {
    println!("{}", largest(&[3, 7, 2]));        // 7
    println!("{}", largest(&[1.5, 0.2]));       // 1.5
    println!("{}", largest(&['a', 'z', 'm']));  // 'z'
}
```

C#: `T Largest<T>(T[] items) where T : IComparable<T>`.

### `where` clauses (for readability)

```rust
use std::fmt::{Debug, Display};

fn report<T, U>(a: T, b: U) -> String
where
    T: Display + Clone,
    U: Debug,
{
    format!("{a} / {b:?}")
}
```

### Generic structs

```rust
struct Pair<T> { a: T, b: T }

impl<T: PartialOrd + std::fmt::Display> Pair<T> {
    fn print_max(&self) {
        let max = if self.a > self.b { &self.a } else { &self.b };
        println!("max = {max}");
    }
}
```

## Static vs Dynamic Dispatch

```rust
// Static dispatch — compiler generates a copy per concrete type (monomorphization)
fn print_area(s: &impl Shape) {                // shorthand for <T: Shape>(s: &T)
    println!("{}", s.area());
}

// Dynamic dispatch — one function, calls go through a vtable at runtime
fn print_all(shapes: &[Box<dyn Shape>]) {
    for s in shapes { println!("{}", s.describe()); }
}

fn main() {
    let shapes: Vec<Box<dyn Shape>> = vec![
        Box::new(Circle { r: 1.0 }),
        Box::new(Square { side: 2.0 }),
    ];                                          // like List<IShape> in C#
    print_all(&shapes);
}
```

| | Static (`impl Trait` / `<T: Trait>`) | Dynamic (`dyn Trait`) |
|---|------------------------------------|---------------------|
| Resolved | Compile time | Runtime (vtable) |
| Speed | Fastest (can be inlined) | Small indirection cost |
| Binary size | Larger (one copy per type) | Smaller |
| Mixed types in one collection? | ❌ | ✅ `Vec<Box<dyn Shape>>` |
| C# analogy | Generics over structs (JIT specialization) | Calling through an interface reference |

> **Key point**: Default to **static** dispatch (`impl Trait`). Switch to `dyn Trait` when you need a **heterogeneous collection** or want smaller binaries.

## Essential Standard Traits

| Rust trait | Purpose | C# / JS equivalent | Derivable? |
|-----------|---------|-------------------|-----------|
| `Debug` | `{:?}` developer formatting | Debugger display / `console.log(obj)` | ✅ |
| `Display` | `{}` user-facing formatting | `ToString()` / `toString()` | ❌ write it |
| `Clone` | Explicit deep copy `.clone()` | `ICloneable` / `structuredClone` | ✅ |
| `Copy` | Implicit bitwise copy | Value-type (`struct`) semantics | ✅ |
| `PartialEq` / `Eq` | `==` comparison | `IEquatable<T>` / `Equals` | ✅ |
| `PartialOrd` / `Ord` | `<`, `>` and sorting | `IComparable<T>` | ✅ |
| `Hash` | Usable as a `HashMap` key | `GetHashCode()` | ✅ |
| `Default` | `T::default()` zero value | `default(T)` / parameterless ctor | ✅ |
| `From` / `Into` | Type conversion | Implicit/explicit conversion operators | ❌ |
| `Iterator` | Can be iterated | `IEnumerable<T>` / JS iterator protocol | ❌ |
| `Drop` | Cleanup when the value goes out of scope | `IDisposable.Dispose()` (automatic) | ❌ |

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash, Default)]
struct UserId(u64);                 // one line gets you Equals, GetHashCode, ToString-ish, Clone...
```

## Iterators: Rust's LINQ

### LINQ / JS array methods → Rust iterators

| C# LINQ | JavaScript | Rust |
|---------|-----------|------|
| `Select` | `map` | `map` |
| `Where` | `filter` | `filter` |
| `SelectMany` | `flatMap` | `flat_map` |
| `Aggregate` | `reduce` | `fold` / `reduce` |
| `FirstOrDefault(pred)` | `find` | `find` → `Option<T>` |
| `Any` / `All` | `some` / `every` | `any` / `all` |
| `Take` / `Skip` | `slice` | `take` / `skip` |
| `Count` / `Sum` / `Max` | `length` / `reduce` | `count` / `sum` / `max` |
| `Zip` | — | `zip` |
| `Select((x, i) => ...)` | `map((x, i) => ...)` | `enumerate().map(\|(i, x)\| ...)` |
| `ToList()` / `ToArray()` | (already an array) | `collect::<Vec<_>>()` |
| `ToDictionary()` | `Object.fromEntries` | `collect::<HashMap<_, _>>()` |

```rust
struct User { name: String, age: u32, active: bool }

fn main() {
    let users = vec![
        User { name: "ann".into(), age: 31, active: true },
        User { name: "bob".into(), age: 17, active: false },
        User { name: "cat".into(), age: 25, active: true },
    ];

    let names: Vec<String> = users
        .iter()                                  // borrow each element
        .filter(|u| u.active && u.age >= 18)
        .map(|u| u.name.to_uppercase())
        .collect();                              // like .ToList()

    let total_age: u32 = users.iter().map(|u| u.age).sum();
    println!("{names:?}, total age = {total_age}");
}
```

> **Key point**: Rust iterators are **lazy**, like LINQ and unlike JS array methods. Nothing runs until you call a **consumer** (`collect`, `sum`, `count`, `for` loop...). They compile down to plain loops, so you pay **zero** overhead.

### Three ways to iterate a collection

| Method | Yields | Collection afterward | Use when |
|--------|--------|---------------------|----------|
| `.iter()` | `&T` | Still usable | Reading |
| `.iter_mut()` | `&mut T` | Still usable | Modifying in place |
| `.into_iter()` | `T` (owned) | **Moved / consumed** | Transforming into something new |

## Closures: Rust's Lambdas

```rust
let offset = 10;
let add = |n: i32| n + offset;          // captures `offset` by reference
println!("{}", add(5));                 // 15

fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 { f(x) }
println!("{}", apply(|n| n * 2, 21));   // 42
```

| Rust closure trait | Captures | Can be called | C# analogy |
|-------------------|----------|---------------|-----------|
| `Fn` | By shared reference | Many times | `Func<T, R>` that only reads |
| `FnMut` | By mutable reference | Many times | Lambda that mutates a captured variable |
| `FnOnce` | By value (moves) | **Once** | — |

```rust
let name = String::from("Jeb");
let greet = move || println!("hi {name}");  // `move` forces ownership into the closure
greet();
// println!("{name}");                       // ❌ name was moved into the closure
```

> **Key point**: `move` closures are required whenever the closure **outlives** the current scope: threads, async tasks, returned closures. See [[07. Concurrency]].

## Cheat Sheet

```
Shared behavior across types?             → trait + impl Trait for Type
Function works for any type with ability? → generic <T: Trait> or &impl Trait
Mixed types in one Vec?                   → Vec<Box<dyn Trait>>
Equals/Hash/Clone/Debug?                  → #[derive(...)]
LINQ-style data processing?               → .iter().filter().map().collect()
Pass behavior as a parameter?             → closure + F: Fn(..) -> ..
Closure must outlive scope?               → move || ...
```
