# Error Handling - Option, Result, and the ? Operator

> Rust has **no exceptions and no null**. A missing value is an **`Option<T>`**; an operation that can fail returns a **`Result<T, E>`**. Errors show up in function **signatures**, and the compiler makes you deal with them. The **`?`** operator keeps this almost as short as code that uses exceptions.
>
> Related notes: [[01. Introduce Rust]] | [[04. Structs & Enums]] | [[06. Traits & Generics]]

---

## Concept Mapping

| C# | JavaScript | Rust |
|----|-----------|------|
| `null` / `Nullable<T>` / `string?` | `null` / `undefined` | `Option<T>` (`Some(v)` / `None`) |
| `throw new Exception(...)` | `throw new Error(...)` | `return Err(...)` |
| `try { } catch { }` | `try { } catch { }` | `match result { Ok(..) => .., Err(..) => .. }` |
| Exceptions bubble up implicitly | Exceptions bubble up implicitly | `?` propagates **explicitly** |
| Unhandled exception / `Environment.FailFast` | Uncaught error crashes the process | `panic!` (unrecoverable) |
| `Exception` class hierarchy | `Error` subclasses | Error **enums** implementing `std::error::Error` |
| `NullReferenceException` | `TypeError: cannot read property of undefined` | **Impossible**: no null in safe Rust |

> **Key point**: In C#/JS, any line can throw and the signature won't tell you. In Rust, `fn parse(s: &str) -> Result<u32, ParseIntError>` tells you exactly **what can fail and how**.

---

## Two Kinds of Errors

| Kind | Mechanism | When to use |
|------|-----------|-------------|
| **Recoverable** | `Result<T, E>` | File not found, bad user input, network timeout: expected failures |
| **Unrecoverable** | `panic!` | Bugs and broken invariants (index out of bounds, "this can never happen") |

```rust
panic!("something went terribly wrong");   // unwinds the stack and crashes the thread
let v = vec![1, 2, 3];
let x = v[99];                              // panics: index out of bounds
```

## `Option<T>`: Replacing Null

```rust
fn find_user(id: u32) -> Option<String> {
    if id == 1 { Some(String::from("Jeb")) } else { None }
}

fn main() {
    match find_user(1) {
        Some(name) => println!("found {name}"),
        None => println!("no user"),
    }
}
```

### Nullable operators → Option methods

| C# / JS | Rust | Notes |
|---------|------|-------|
| `x ?? defaultValue` | `x.unwrap_or(default_value)` | |
| `x ?? Compute()` | `x.unwrap_or_else(\|\| compute())` | Lazy: only runs if `None` |
| `x?.Name` | `x.map(\|u\| u.name)` | Transform the value if present |
| `x?.Address?.City` | `x.and_then(\|u\| u.address).map(\|a\| a.city)` | Chain optional steps |
| `x!` (null-forgiving) / `x.Value` | `x.unwrap()` | Panics if `None` |
| `x ?? throw new Ex("msg")` | `x.expect("msg")` | Panics with your message |
| `if (x is { } v)` / `if (x != null)` | `if let Some(v) = x` | |
| `x.HasValue` | `x.is_some()` / `x.is_none()` | |
| Turn null into an error | `x.ok_or(MyError::NotFound)?` | Option → Result |

## `Result<T, E>`: Replacing Exceptions

```rust
fn parse_age(s: &str) -> Result<u32, std::num::ParseIntError> {
    s.trim().parse::<u32>()
}

fn main() {
    match parse_age("42") {
        Ok(age) => println!("age = {age}"),
        Err(e) => println!("invalid: {e}"),
    }
}
```

### The `?` operator: concise propagation

`?` means: *"If this is `Ok(v)`, give me `v`. If it's `Err(e)`, **return** `Err(e)` from the current function right now."*

```rust
use std::fs;
use std::io;

fn read_username(path: &str) -> Result<String, io::Error> {
    let text = fs::read_to_string(path)?;   // returns early on error
    Ok(text.trim().to_string())
}
```

C#, for comparison:

```csharp
string ReadUsername(string path) {
    var text = File.ReadAllText(path);       // may throw — invisible in the signature
    return text.Trim();
}
```

> **Key point**: `?` reads like `await`. It's a small postfix marker that says "this step can stop the function here". It works in functions returning `Result` **or** `Option`, and it converts error types automatically through the `From` trait.

### Useful Result methods

| Method | Effect |
|--------|--------|
| `.map(\|v\| ...)` | Transform the `Ok` value |
| `.map_err(\|e\| ...)` | Transform the `Err` value (e.g. wrap it in your own error) |
| `.and_then(\|v\| ...)` | Chain another fallible step |
| `.unwrap_or(default)` / `.unwrap_or_default()` | Fall back on error |
| `.ok()` | `Result<T, E>` → `Option<T>` (drop the error) |
| `.unwrap()` / `.expect("msg")` | Get the value or **panic** |

## Custom Error Types

### Hand-written (to understand the mechanics)

```rust
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum AppError {
    MissingConfig(String),
    InvalidPort(ParseIntError),
}

impl fmt::Display for AppError {                    // like overriding Exception.Message
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            AppError::MissingConfig(key) => write!(f, "missing config key: {key}"),
            AppError::InvalidPort(e) => write!(f, "invalid port: {e}"),
        }
    }
}

impl std::error::Error for AppError {}

impl From<ParseIntError> for AppError {             // lets `?` convert automatically
    fn from(e: ParseIntError) -> Self {
        AppError::InvalidPort(e)
    }
}

fn get_port(value: Option<&str>) -> Result<u16, AppError> {
    let raw = value.ok_or(AppError::MissingConfig("PORT".into()))?;
    let port: u16 = raw.parse()?;                   // ParseIntError → AppError via From
    Ok(port)
}
```

### In practice: the `thiserror` and `anyhow` crates

```rust
// Libraries: typed errors with `thiserror` (generates Display + From for you)
#[derive(Debug, thiserror::Error)]
enum AppError {
    #[error("missing config key: {0}")]
    MissingConfig(String),
    #[error("invalid port: {0}")]
    InvalidPort(#[from] std::num::ParseIntError),
}
```

```rust
// Applications: one catch-all error type with `anyhow` (like catching `Exception`)
use anyhow::{Context, Result};

fn main() -> Result<()> {
    let text = std::fs::read_to_string("config.toml")
        .context("failed to read config.toml")?;   // adds context, like wrapping in an inner exception
    println!("{text}");
    Ok(())
}
```

| Crate | Use in | C# analogy |
|-------|--------|-----------|
| **`thiserror`** | Libraries: callers need to `match` on specific errors | Custom exception classes |
| **`anyhow`** | Applications / binaries: you mostly report errors | `catch (Exception ex)` + `throw new X("context", ex)` |

## When Is `unwrap()` OK?

| ✅ Acceptable | ❌ Avoid |
|--------------|---------|
| Quick prototypes and examples | Library code |
| Tests | Handling user input, files, network |
| A provable invariant (prefer `expect("why this can't fail")`) | Anywhere a failure is realistic |

---

## Cheat Sheet

```
Value might be absent?                 → Option<T>
Operation might fail?                  → Result<T, E>
Pass the error up to the caller?       → ?
Give a default instead?                → unwrap_or / unwrap_or_else / unwrap_or_default
Convert Option → Result?               → .ok_or(err)?
Writing a library?                     → custom enum (+ thiserror)
Writing an app?                        → anyhow::Result + .context("...")
It's a bug, not an expected failure?   → panic! / expect("reason")
```
