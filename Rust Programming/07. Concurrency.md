# Concurrency - Threads, Shared State, Channels, and Async

> Rust promises **fearless concurrency**: if multi-threaded code compiles, it has **no data races**. The ownership and borrowing rules ([[02. Ownership & Borrowing]]) plus two marker traits, **`Send`** and **`Sync`**, make this work. Rust also has `async`/`.await`, like C# and JavaScript, with some important differences.
>
> Related notes: [[01. Introduce Rust]] | [[02. Ownership & Borrowing]] | [[03. Lifetimes]] | [[06. Traits & Generics]]

---

## Concurrency Models Compared

|                                   | JavaScript                                               | C#                                       | Rust                                              |
| --------------------------------- | -------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------- |
| **Threads**                       | Single-threaded event loop; Web Workers / worker_threads | `Thread`, thread pool, `Task`            | `std::thread`, plus async runtimes                |
| **Shared memory between threads** | Almost none (message passing; `SharedArrayBuffer` aside) | Yes, freely                              | Yes, but **only** through thread-safe types       |
| **Data races**                    | Rare (no shared memory)                                  | Possible: found at **runtime** (if ever) | **Compile error**                                 |
| **Async/await**                   | Built in, Promise-based                                  | Built in, `Task`-based                   | Built in syntax; **runtime is a library** (Tokio) |
| **Async values**                  | `Promise` starts **immediately**                         | `Task` starts **immediately** (hot)      | `Future` does **nothing until awaited** (lazy)    |

## Threads

### Spawning a thread

```rust
use std::thread;
use std::time::Duration;

fn main() {
    let handle = thread::spawn(|| {
        for i in 1..=3 {
            println!("worker: {i}");
            thread::sleep(Duration::from_millis(10));
        }
    });

    println!("main thread continues");
    handle.join().unwrap();            // like thread.Join() / await task
}
```

### `move` closures: giving data to a thread

```rust
let data = vec![1, 2, 3];

// ❌ Without `move`: E0373 closure may outlive the current function, but it borrows `data`
let handle = thread::spawn(move || {   // ✅ ownership of `data` moves into the thread
    println!("{data:?}");
});
handle.join().unwrap();
// println!("{data:?}");               // ❌ data now belongs to the thread
```

> **Key point**: In C# a lambda can capture any local, and the GC keeps it alive for the thread. A Rust thread might outlive the function that started it, so it must **own** what it uses (`move`). If you need to **share** the data, use `Arc` (below).

### Scoped threads: borrowing safely

`thread::scope` guarantees that all spawned threads finish before the scope ends, so they **can** borrow local data:

```rust
let mut nums = vec![1, 2, 3];
thread::scope(|s| {
    s.spawn(|| println!("sum = {}", nums.iter().sum::<i32>()));
    s.spawn(|| println!("len = {}", nums.len()));
});                                     // all threads joined here
nums.push(4);                           // ✅ borrows have ended
```

## Shared State: `Arc<Mutex<T>>`

```rust
use std::sync::{Arc, Mutex};
use std::thread;

fn main() {
    let counter = Arc::new(Mutex::new(0));          // shared, thread-safe counter
    let mut handles = vec![];

    for _ in 0..10 {
        let c = Arc::clone(&counter);               // bump the reference count
        handles.push(thread::spawn(move || {
            let mut n = c.lock().unwrap();          // acquire the lock
            *n += 1;
        }));                                        // lock released when `n` is dropped
    }

    for h in handles { h.join().unwrap(); }
    println!("result = {}", *counter.lock().unwrap());   // 10
}
```

C#, for comparison:

```csharp
int counter = 0;
object gate = new();
Parallel.For(0, 10, _ => { lock (gate) { counter++; } });
// Nothing stops you from writing `counter++` OUTSIDE the lock — a silent race.
```

> **Key point**: In C#, the lock (`gate`) and the data (`counter`) are **separate**, so you can forget the lock. In Rust, the `Mutex` **owns** the data: the **only** way to reach it is through `.lock()`. Forgetting the lock is impossible.

### Building blocks

| Rust | Purpose | C# analogy |
|------|---------|-----------|
| `Rc<T>` | Shared ownership, **single thread** only | — (GC does this) |
| `Arc<T>` | Shared ownership **across threads** (atomic ref count) | Normal object reference (GC) |
| `Mutex<T>` | Exclusive access to data | `lock` / `Monitor` |
| `RwLock<T>` | Many readers or one writer | `ReaderWriterLockSlim` |
| `AtomicUsize`, `AtomicBool`, ... | Lock-free counters / flags | `Interlocked.Increment` |
| `OnceLock<T>` / `LazyLock<T>` | One-time initialization | `Lazy<T>` |

> **Trap**: Use `Rc` instead of `Arc` with threads and you get a **compile error** (`Rc` is not `Send`). The compiler catches the bug that C# would leave for production.

## Message Passing: Channels

*"Do not communicate by sharing memory; instead, share memory by communicating."*

```rust
use std::sync::mpsc;      // multi-producer, single-consumer
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    for id in 0..3 {
        let tx = tx.clone();                     // one sender per producer
        thread::spawn(move || {
            tx.send(format!("hello from worker {id}")).unwrap();
        });
    }
    drop(tx);                                    // close the original sender

    for msg in rx {                              // loop ends when all senders are dropped
        println!("{msg}");
    }
}
```

| Rust | C# | JavaScript |
|------|----|-----------|
| `mpsc::channel()` | `System.Threading.Channels.Channel<T>` | `postMessage` / `MessageChannel` |
| `tx.send(v)` | `writer.WriteAsync(v)` | `port.postMessage(v)` |
| `for msg in rx` | `await foreach (var m in reader.ReadAllAsync())` | `onmessage = e => ...` |

> **Key point**: `send` **moves** the value into the channel, so the sender can't touch it afterward. Ownership transfer is enforced.

## `Send` and `Sync`: The Secret Sauce

| Trait | Meaning | Examples that are **NOT** |
|-------|---------|--------------------------|
| **`Send`** | Ownership can be **transferred** to another thread | `Rc<T>` |
| **`Sync`** | Can be **shared** between threads by reference (`&T` is `Send`) | `RefCell<T>`, `Cell<T>`, `Rc<T>` |

The compiler implements both **automatically** for types whose fields are all `Send`/`Sync`. `thread::spawn` requires its closure to be `Send + 'static`. That one bound is why the bugs above get caught.

## Async / Await

### Hello async with Tokio

```toml
# Cargo.toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

```rust
use tokio::time::{sleep, Duration};

async fn fetch(id: u32) -> String {
    sleep(Duration::from_millis(100)).await;   // non-blocking, like await Task.Delay(100)
    format!("data {id}")
}

#[tokio::main]                                 // sets up the runtime (C#/JS have one built in)
async fn main() {
    // Run concurrently — like Task.WhenAll / Promise.all
    let (a, b) = tokio::join!(fetch(1), fetch(2));
    println!("{a}, {b}");

    // Spawn a background task — like Task.Run
    let handle = tokio::spawn(fetch(3));
    println!("{}", handle.await.unwrap());
}
```

### Key differences from C# / JS

| Topic | C# / JavaScript | Rust |
|-------|----------------|------|
| Syntax | `await fetch()` (prefix) | `fetch().await` (**postfix**, so it chains: `get().await?.json().await?`) |
| Start | `Task` / `Promise` starts running **when created** | `Future` is **lazy**: nothing happens until it's `.await`ed or spawned |
| Runtime | Built in (thread pool / event loop) | Pick a library: **Tokio** (de facto standard), async-std, smol |
| Cancellation | `CancellationToken` / `AbortController` | **Drop the future** to cancel it; or `tokio_util::sync::CancellationToken` |
| Spawned task data | Captures anything (GC) | Must be `Send + 'static` → `move` + `Arc` |

> **Trap**: Calling `fetch(1);` without `.await` does **nothing**, unlike JS where the request would still fire. The compiler warns: *"unused implementer of `Future` that must be used"*.

### C# / JS async APIs → Tokio

| C# | JavaScript | Rust (Tokio) |
|----|-----------|--------------|
| `Task.WhenAll(a, b)` | `Promise.all([a, b])` | `tokio::join!(a, b)` |
| `Task.WhenAny(a, b)` | `Promise.race([a, b])` | `tokio::select! { .. }` |
| `Task.Run(() => ...)` | — | `tokio::spawn(async move { .. })` |
| `Task.Run` for CPU-heavy work | Worker thread | `tokio::task::spawn_blocking(..)` |
| `Task.Delay(ms)` | `setTimeout` / `await sleep` | `tokio::time::sleep(..)` |
| `SemaphoreSlim` | — | `tokio::sync::Semaphore` |
| `HttpClient` | `fetch` | `reqwest` crate |

> **Trap**: Never call **blocking** code (`std::thread::sleep`, heavy CPU loops, blocking file I/O) inside an async task. It stalls the executor thread, the same way `.Result` / `.Wait()` causes trouble in C#. Use the async version or `spawn_blocking`.

## Cheat Sheet

```
Run work in parallel (CPU-bound)?          → std::thread::spawn / thread::scope (or the `rayon` crate)
Thread needs local data?                   → move closure (or thread::scope to borrow)
Share data between threads?                → Arc<T> (read-only) / Arc<Mutex<T>> (mutable)
Many readers, few writers?                 → Arc<RwLock<T>>
Simple counter / flag?                     → Atomic*
Pass messages between threads?             → mpsc::channel (or crossbeam / tokio::sync::mpsc)
Lots of I/O (HTTP, DB, sockets)?           → async + Tokio
Wait for several futures?                  → tokio::join! (all) / tokio::select! (first)
Compiler says "not Send"?                  → Rc → Arc, RefCell → Mutex
```
