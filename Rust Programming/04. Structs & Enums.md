# Structs & Enums - Modeling Data Without Classes

> Rust has **no classes and no inheritance**. You model data with **structs** (like C# classes or records), attach behavior with **`impl` blocks**, and share behavior through **traits** ([[06. Traits & Generics]]). Rust **enums** are far more powerful than C# enums: they work like TypeScript discriminated unions, checked by the compiler.
>
> Related notes: [[01. Introduce Rust]] | [[02. Ownership & Borrowing]] | [[05. Error Handling]] | [[06. Traits & Generics]]

---

## Concept Mapping

| C#                                          | JavaScript / TypeScript                          | Rust                                                |
| ------------------------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| `class` / `record`                          | `class` / object literal                         | `struct`                                            |
| Methods inside the class                    | Methods inside the class                         | Methods inside a separate `impl` block              |
| Constructor `new User(...)`                 | `constructor()`                                  | Associated function, by convention `User::new(...)` |
| `static` method                             | `static` method                                  | Associated function (no `self`)                     |
| `this`                                      | `this`                                           | `self` (always explicit)                            |
| Inheritance `: BaseClass`                   | `extends`                                        | ❌ none: use **composition + traits**                |
| `enum` (just named integers)                | (TS) `enum`                                      | Simple `enum`, **or** enums carrying data           |
| Abstract record hierarchy + `switch`        | Discriminated union `type A = {kind:...} \| ...` | `enum` + `match`                                    |
| `record` auto-generated `Equals`/`ToString` | —                                                | `#[derive(PartialEq, Debug, Clone)]`                |
| `with` expression (records)                 | Spread `{...obj, age: 31}`                       | Struct update syntax `User { age: 31, ..u }`        |

## Structs

### Definition, construction, methods

```rust
#[derive(Debug, Clone, PartialEq)]
struct User {
    name: String,
    age: u32,
    active: bool,
}

impl User {
    // Associated function (like a static method / constructor)
    fn new(name: &str, age: u32) -> Self {
        Self { name: name.to_string(), age, active: true } // field init shorthand: `age` = `age: age`
    }

    // Method borrowing self immutably (read-only)
    fn greet(&self) -> String {
        format!("Hi, I'm {} ({})", self.name, self.age)
    }

    // Method borrowing self mutably (modifies)
    fn birthday(&mut self) {
        self.age += 1;
    }

    // Method taking ownership (consumes the value)
    fn into_name(self) -> String {
        self.name
    }
}

fn main() {
    let mut u = User::new("Jeb", 30);   // `mut` needed to call birthday()
    u.birthday();
    println!("{}", u.greet());
    println!("{u:?}");                  // Debug print (from #[derive(Debug)])
    let name = u.into_name();           // u is moved; can't use it after this
    println!("{name}");
}
```

The C# equivalent, for comparison:

```csharp
public class User {
    public string Name { get; set; }
    public uint Age { get; set; }
    public bool Active { get; set; } = true;
    public User(string name, uint age) { Name = name; Age = age; }
    public string Greet() => $"Hi, I'm {Name} ({Age})";
    public void Birthday() => Age++;
}
```

### The three kinds of `self`

| Signature | Meaning | C# analogy |
|-----------|---------|-----------|
| `&self` | Read-only access | Normal instance method (on a `readonly struct`) |
| `&mut self` | Can modify fields | Normal instance method that mutates |
| `self` | Takes ownership; the caller can't use the value afterward | No direct equivalent (like `Dispose` + return a result) |

> **Key point**: Rust variables are **immutable by default**. `let u` means you can only call `&self` methods. You need `let mut u` to call `&mut self` methods.

### Struct update syntax

```rust
let u2 = User { name: String::from("Ann"), ..u1.clone() };  // like C# `u1 with { Name = "Ann" }`
```

> **Trap**: `..u1` **moves** the non-`Copy` fields out of `u1`. Use `..u1.clone()` if you still need `u1`.

### Other struct forms

```rust
struct Point(i32, i32);         // tuple struct — fields accessed as p.0, p.1
struct Meters(f64);             // "newtype" — type-safe wrapper (Meters ≠ f64)
struct Marker;                  // unit struct — no fields, used with traits
```

### Composition instead of inheritance

```rust
struct Address { city: String }

struct Employee {
    user: User,         // "has-a" instead of "is-a"
    address: Address,
    salary: u32,
}
```

You get shared behavior across types from **traits**, not base classes. See [[06. Traits & Generics]].

## Enums

### Simple enums (like C#)

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
enum Direction { North, East, South, West }
```

### Enums with data (algebraic data types)

Each variant can carry **different** data. In C# this needs a class hierarchy; in TypeScript, a discriminated union.

```rust
enum Shape {
    Circle { radius: f64 },
    Rectangle { width: f64, height: f64 },
    Triangle(f64, f64, f64),
}

impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle { radius } => std::f64::consts::PI * radius * radius,
            Shape::Rectangle { width, height } => width * height,
            Shape::Triangle(a, b, c) => {
                let s = (a + b + c) / 2.0;
                (s * (s - a) * (s - b) * (s - c)).sqrt()
            }
        }
    }
}
```

The same model in TypeScript:

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rectangle"; width: number; height: number }
  | { kind: "triangle"; a: number; b: number; c: number };
```

…and in C#:

```csharp
abstract record Shape;
record Circle(double Radius) : Shape;
record Rectangle(double Width, double Height) : Shape;
// switch expression — missing cases are only a WARNING in C#
```

> **Key point**: A Rust `match` must be **exhaustive**. Add a new variant (say `Shape::Square`) and every `match` that doesn't handle it becomes a **compile error**. Refactoring gets much safer.

### Standard-library enums you'll use constantly

```rust
enum Option<T> { Some(T), None }        // replaces null      → [[05. Error Handling]]
enum Result<T, E> { Ok(T), Err(E) }     // replaces exceptions → [[05. Error Handling]]
```

## Pattern Matching

### `match`: like C# `switch` expressions, with more power

```rust
let n = 7;
let desc = match n {
    0 => "zero",
    1..=9 => "single digit",          // range
    10 | 20 | 30 => "round",          // multiple patterns
    x if x < 0 => "negative",         // guard
    _ => "big",                       // catch-all (like `default` / `_` in C#)
};
```

`match` is an **expression**, so it returns a value, like a C# `switch` expression.

### Destructuring

```rust
let p = Point(3, 4);
let Point(x, y) = p;                  // like C# deconstruction `var (x, y) = p;`

let u = User::new("Jeb", 30);
let User { name, age, .. } = u;       // like JS `const { name, age } = u;`
```

### `if let` and `let else`: matching just one pattern

```rust
// if let — handle one case, ignore the rest
if let Shape::Circle { radius } = shape {
    println!("circle with r = {radius}");
}

// let else — unwrap or bail out early (great for guard clauses)
fn print_user(id: u32) {
    let Some(user) = find_user(id) else {
        println!("not found");
        return;
    };
    println!("{}", user.name);        // `user` is available here
}
```

## Cheat Sheet

```
Need a data type with named fields?          → struct
Need methods?                                → impl block (&self / &mut self / self)
Need a constructor?                          → fn new(...) -> Self (convention)
Need "one of several shapes of data"?        → enum with data + match
Need to handle just one variant?             → if let / let else
Want Equals/ToString/Clone auto-generated?   → #[derive(Debug, Clone, PartialEq)]
Want to reuse behavior across types?         → trait (see [[06. Traits & Generics]])
```
