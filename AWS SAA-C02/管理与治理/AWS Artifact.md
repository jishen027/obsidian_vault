# AWS Artifact - 合规报告与协议自助门户

> **AWS Artifact** 是**免费的自助服务门户**，让客户随时按需**下载 AWS 的合规报告/认证证书**（证明 AWS 底层基础设施满足特定安全和合规标准），并**查看、接受、管理与 AWS 之间的法律协议**（如 HIPAA 业务伙伴附录）。它回答的问题很单一："**AWS 一侧的合规证明文件在哪里拿？**"——本身**不做任何审计证据的自动收集，也不检查客户自己资源的配置是否合规**，这与 [[AWS Audit Manager]]（持续收集**客户自己**的合规证据）和 [[AWS Config]]（持续评估**客户资源配置**是否合规）有本质区别，是 AIF-C01/SAA-C02 都容易混淆的高频对比点。
>

## 核心概念

### 为什么需要 AWS Artifact

- 云的**共享责任模型**下，客户在向自己的审计方、监管机构或客户证明合规时，经常需要提交"**AWS 基础设施本身是否合规**"的证明材料（如 SOC 2 报告、ISO 27001 证书）
- 在没有 Artifact 之前，这类文件需要联系 AWS 客户经理人工索取，流程慢且不透明；**Artifact 把这一过程自助化**——登录控制台即可随时查看、下载最新版本的报告
- **Artifact 只解决"文件从哪来"，不解决"我自己的系统是否合规"**——后者需要客户自己用 [[AWS Config]]（资源配置合规）、[[AWS Audit Manager]]（证据收集）等工具持续评估

### AWS Artifact 在合规工具链中的定位（考试要点）

| 服务 | 核心问题 | 产出/机制 | 典型场景 |
|------|---------|-----------|---------|
| **AWS Artifact** | AWS 自身的合规认证文件在哪下载？与 AWS 的法律协议在哪签署？ | 静态 PDF 报告 / 在线协议接受 | 提交给外部审计方证明底层基础设施合规、签署 HIPAA BAA |
| **[[AWS Audit Manager]]** | 如何持续、自动收集**我自己工作负载**的合规证据？ | 自动化证据收集 + 评估报告 | 准备内部/外部审计，减少人工整理证据的工作量——**⚠️ 已于 2026-04-30 起进入维护模式，停止向新账户开放**，新需求见 [[AWS Audit Manager]] 独立笔记中的替代方案 |
| **[[AWS Config]]** | 我自己的**资源配置**是否合规？ | 配置合规检测（Rule + Remediation） | 持续监控配置漂移，自动修复不合规资源 |
| **[[AWS Trusted Advisor]]** | 账户是否违反 AWS 通用最佳实践？ | 六大类别红/黄/绿检查 | 快速体检，规则不可自定义 |

> **考试陷阱**：四者常在同一道题的选项中一起出现——题目问"需要下载 AWS 的 SOC 2/ISO 27001 报告提交给审计方" → **AWS Artifact**（只是下载别人已经做好的报告）；问"需要持续、自动化地收集我们自己系统的合规证据，减轻审计准备的人工工作量" → **[[AWS Audit Manager]]**；问"需要检测我们自己的 S3/EC2 配置是否符合内部安全基准" → **[[AWS Config]]**；问"需要快速了解账户是否违反通用最佳实践"→ **[[AWS Trusted Advisor]]**。**记忆技巧：Artifact 是"拿 AWS 的证书"，Audit Manager 是"攒自己的证据"。**

## 两大核心功能

### AWS Artifact Reports（合规报告）

> 提供对 AWS **全球基础设施和服务**的第三方审计报告、认证证书的**按需下载**。

| 报告类型 | 说明 |
|---------|------|
| **SOC 1 / SOC 2 / SOC 3** | 服务组织控制报告，覆盖安全、可用性、处理完整性、保密性、隐私等控制目标 |
| **ISO 27001 / 27017 / 27018** | 信息安全管理体系、云安全、云隐私保护国际标准认证 |
| **PCI DSS 合规证明（AOC）** | 支付卡数据安全标准的合规证明，处理支付卡数据的工作负载常需引用 |
| **FedRAMP、CSA STAR 等** | 面向政府、特定行业或框架的专项认证材料 |

- 部分敏感报告（如 SOC 2 Type II 的完整报告）需要先**在线接受保密协议（NDA）**才能下载，属于"受限报告"
- 报告**按区域、按服务范围**组织——不同 AWS 服务、不同区域覆盖的认证范围可能不同，下载前需确认报告是否覆盖目标服务/区域

#### 第三方/ISV 合规报告（Third-Party Reports，考试重点）

> Artifact Reports 页面有一个**"Third-party reports"（第三方报告）标签页**，提供对通过 **AWS Marketplace** 销售产品的**独立软件供应商（ISV）**的安全合规报告的**按需访问**——不仅能拿到 AWS 自身的合规证明，也能在同一个门户里拿到你所依赖的第三方软件供应商的合规报告（如 SOC 2、ISO 认证）。

#### 通知订阅（Notifications，考试重点：新报告/新协议可用时自动提醒）

> Artifact 支持**订阅通知**——可以配置当**新的报告/协议**，或**已有报告/协议出现新版本**（包括第三方 ISV 报告）时，**自动通过邮件/Amazon SNS 收到提醒**，无需每次手动登录检查是否有更新。这项能力使 Artifact 不仅是"被动的下载门户"，还能**主动通知**合规团队关注的报告何时更新。

> **考试陷阱**：题目描述"需要在新的 ISV 合规报告（如供应商的 SOC 2）可用时**自动收到邮件通知**" → 正确答案是 **AWS Artifact**（其通知订阅功能覆盖包括 ISV 报告在内的所有 Artifact 报告）——容易被误判为 **AWS Audit Manager**（它是收集**自己**系统的审计证据，不负责下发第三方报告的可用性通知）或 **AWS Config**（配置合规监控，与外部合规报告无关）或 **AWS Trusted Advisor**（最佳实践建议，与合规文档订阅无关）。

### AWS Artifact Agreements（协议管理）

> 让客户在线**查看、接受、跟踪**与 AWS 之间的各类法律协议，无需线下签署纸质文件。

| 协议类型 | 说明 |
|---------|------|
| **业务伙伴附录（BAA）** | 处理受 **HIPAA** 监管的健康信息（PHI）时，需要先接受 BAA，明确双方在保护 PHI 上的责任划分 |
| **AWS 数据处理协议（DPA）** | 涉及处理受 **GDPR** 等数据保护法规约束的个人数据时的补充条款 |
| **其他区域/行业专属协议** | 视客户所在地区和行业不同，可能出现在协议列表中供按需接受 |

> **考试要点**：题目描述"公司将在 AWS 上处理患者健康信息（PHI），需要先与 AWS 签署一份明确双方责任的协议" → **AWS Artifact Agreements 中接受 BAA**，而不是去客服邮件索要纸质合同。

## 组织级使用（AWS Organizations 集成）

- 在 **[[AWS Organizations]]** 的管理账户中，可以代表整个组织**集中下载报告、集中接受协议**，无需让每个成员账户各自登录 Artifact 分别操作
- 简化多账户企业在合规材料获取和协议签署上的管理开销，是组织级治理的标准实践之一

---

## 成本与访问

- **AWS Artifact 本身完全免费**，任何 AWS 账户都可以访问（部分报告仍需接受 NDA 才能查看内容）
- 通过 [[IAM]] 策略可以精细控制哪些身份可以查看/下载报告、接受协议，避免敏感合规文件被过度访问

## 典型应用场景

| 场景 | 推荐做法 |
|------|---------|
| **审计方要求提供 AWS 基础设施的 SOC 2/ISO 27001 证明** | AWS Artifact Reports 下载对应报告 |
| **即将在 AWS 上处理患者健康信息（PHI）** | AWS Artifact Agreements 接受 BAA |
| **处理受 GDPR 约束的欧盟个人数据** | AWS Artifact Agreements 查看/接受 DPA |
| **需要持续、自动收集自己系统的合规证据** | 改用 [[AWS Audit Manager]]（而非 Artifact） |
| **需要检测自己资源的配置是否合规** | 改用 [[AWS Config]]（而非 Artifact） |
| **企业级统一下载报告/接受协议，无需逐账户操作** | [[AWS Organizations]] 管理账户集中管理 Artifact |
| **快速判断某份报告是否覆盖目标服务/区域** | 下载前核对报告范围（Scope），避免误用不适用的认证 |

## 考试重点总结

### 高频考点（SAA-C02 / AIF-C01 通用）

1. **核心定位**：免费自助门户，下载 AWS 自身的合规报告/证书 + 管理与 AWS 的法律协议，**不做客户自己系统的合规检查或证据收集**
2. **两大功能**：Reports（SOC/ISO/PCI DSS 等认证报告，部分需接受 NDA）+ Agreements（BAA、DPA 等协议在线接受）
3. **AWS Artifact vs AWS Audit Manager**：Artifact 是"下载 AWS 已经做好的报告"；Audit Manager 是"持续自动收集客户自己工作负载的合规证据"，两者不可互换
4. **AWS Artifact vs AWS Config**：Artifact 关注 AWS 基础设施合规证明；Config 关注客户自己资源的配置是否合规
5. **BAA 是 HIPAA 场景的关键协议**：处理健康信息前需先通过 Artifact 接受
6. **组织级集中管理**：管理账户可代表整个 [[AWS Organizations]] 下载报告/接受协议
7. **完全免费**：本身不产生任何费用，仅受 IAM 权限控制访问范围
8. **第三方/ISV 报告 + 通知订阅**：Reports 页面的"Third-party reports"标签可下载通过 AWS Marketplace 销售的 ISV 供应商合规报告；支持配置邮件/SNS 通知，在新报告/协议（含 ISV 报告）可用或有新版本时自动提醒，这是 Artifact 独有能力，不能用 Audit Manager/Config/Trusted Advisor 替代

### 场景题解题思路

```
场景分析 → 判断是否使用 AWS Artifact
├── "需要下载 AWS 的 SOC 2/ISO 27001/PCI DSS 合规报告给审计方" → AWS Artifact Reports
├── "需要下载 AWS Marketplace 上 ISV 供应商的合规报告" → AWS Artifact Reports 的 Third-party reports 标签
├── "希望新的合规报告/协议可用时自动收到邮件通知" → AWS Artifact 通知订阅功能
├── "即将处理患者健康信息（PHI），需要与 AWS 签署责任协议" → AWS Artifact Agreements（BAA）
├── "处理受 GDPR 约束的个人数据，需要补充数据处理条款" → AWS Artifact Agreements（DPA）
├── "需要持续自动收集自己系统的审计证据" → 改用 AWS Audit Manager
├── "需要检测自己的资源配置是否合规" → 改用 AWS Config
├── "需要快速体检账户是否违反通用最佳实践" → 改用 AWS Trusted Advisor
└── "企业级统一管理多账户的报告下载/协议接受" → AWS Organizations 管理账户 + Artifact
```

## 最佳实践

1. **审计前先查 Artifact 而非联系客户经理**：多数常见合规报告已可自助下载，无需走人工索取流程
2. **下载报告前核对适用范围（服务/区域）**：避免拿一份不覆盖目标服务的认证去回应审计问题
3. **组织级账户统一管理协议接受状态**：避免各成员账户重复接受或遗漏关键协议（如 BAA）
4. **Artifact 仅是起点，不是终点**：AWS 基础设施合规不等于客户自己的应用/数据合规，仍需 [[AWS Config]]、[[AWS Audit Manager]] 等工具持续评估客户侧的合规状态
5. **涉及 HIPAA/PHI 的工作负载上线前务必先接受 BAA**：这是合规前提，而非事后补救项

## AIF-C01 考试视角（简化版）

> AIF-C01 Domain 5（安全、合规、治理）中，AWS Artifact 通常作为 [[负责任的AI与安全]] 笔记里 [[负责任的AI与安全#AI 合规性 (Compliance for AI)|AI 合规性]] 章节的一个选项出现，考查深度远低于对 Bedrock/SageMaker 等 AI 服务本身的要求——**只需记住"Artifact = 下载 AWS 的合规报告"这一句话**，并能与 Audit Manager 区分开。

| 记忆锚点 | 内容 |
|---------|------|
| **一句话定位** | AWS Artifact = 下载 AWS 的合规证书/报告的自助门户 |
| **最容易混淆的对象** | AWS Audit Manager（持续收集**自己**系统的审计证据，而非下载 AWS 的证书） |
| **典型 AI 场景** | 团队计划把患者数据接入 Bedrock 做医疗 AI 应用，审计部门要求先提供 AWS 基础设施的合规证明 → 从 **AWS Artifact** 下载相关报告，并在 Artifact Agreements 中接受 BAA |

> **考试要点**：题目描述"需要向审计方证明底层 AWS 基础设施满足 SOC 2/ISO 合规要求" → **AWS Artifact**；题目描述"需要持续、自动化地收集自己 AI 系统的合规证据" → **AWS Audit Manager**，两者是 [[负责任的AI与安全]] 中 AI 合规性章节的高频对比题。
