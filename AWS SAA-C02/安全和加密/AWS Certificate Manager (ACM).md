# AWS Certificate Manager (ACM) - SSL/TLS 证书管理

> **AWS Certificate Manager (ACM)** 是集中管理 **SSL/TLS 证书**的托管服务，负责证书的申请、部署和**自动续期**，让 [[CloudFront]]、[[AWS Load Balance]]、[[Amazon API Gateway]] 等面向公网的服务无需手动管理证书生命周期即可启用 HTTPS 加密。
>
> 相关文档：[[CloudFront]] | [[AWS Load Balance]] | [[Amazon API Gateway]] | [[Route 53 DNS]] | [[KMS]] | [[VPC]] | [[IAM]]

---

## 核心概念

### 为什么需要 ACM

- **传统证书管理的痛点**：手动申请、安装、追踪到期时间、定期续期证书是繁琐且容易出错的运维工作，证书过期会直接导致服务中断和用户信任警告
- **ACM 的核心价值**：与 AWS **集成服务深度绑定**——证书申请后可直接绑定到 CloudFront/ALB/API Gateway 等资源，并在到期前**自动续期、自动替换**，全程无需人工干预，从根本上消除"证书过期导致中断"的风险

### 两种证书类型（考试高频）

| 类型 | 颁发方 | 费用 | 是否可导出私钥 | 典型场景 |
|------|--------|------|--------------|---------|
| **公有证书（Public Certificate）** | ACM 内置的公有证书颁发机构（CA） | **免费**颁发和续期 | 默认**不可导出**，2025 年起支持按需开启**可导出公有证书**（需额外付费，续期时也收费） | 面向公网的 HTTPS 服务，绑定到 CloudFront/ALB/API Gateway 等 |
| **私有证书（Private Certificate）** | AWS Private CA（客户自建的私有证书颁发机构） | 付费（私有 CA 本身 + 证书颁发均收费） | **可导出私钥**，用于企业内部应用、内部 mTLS 等场景 | 内部服务间通信、混合云环境、不面向公网的应用 |

> **考试陷阱**：**ACM 公有证书默认不可导出私钥，只能绑定到 ACM 集成的 AWS 服务使用**——题目描述"需要在自建 EC2 上手动安装 SSL 证书（而非通过 ALB/CloudFront 等集成服务）"，传统答案是**私有证书**或自行采购的第三方证书；2025 年起 ACM 也支持**可导出的公有证书**（额外收费），可用于任意计算工作负载（EC2、容器、本地服务器），但这是相对新的能力，需注意题目考的是"经典行为"还是"最新特性"。

## 证书验证方式

| 验证方式 | 说明 |
|---------|------|
| **DNS 验证（推荐）** | 在域名的 DNS 区域添加 ACM 指定的 CNAME 记录证明域名所有权，若使用 [[Route 53 DNS]] 管理域名，ACM 可**自动添加验证记录**，全程无需人工干预，也是**自动续期**得以实现的关键前提 |
| **邮件验证** | 向域名注册信息中的联系邮箱发送验证邮件，需要人工点击确认，**不支持自动续期**（每次续期都需要重新走邮件验证流程） |

> **考试要点**：**DNS 验证是实现"全自动续期"的必要条件**——题目强调"证书需要自动续期，无需人工干预" → 必须使用 **DNS 验证**（尤其是配合 Route 53 自动化），邮件验证方式的证书到期后仍需人工介入完成续期验证。

---

## 证书部署与集成服务

- ACM 证书**只能绑定到 ACM 集成的 AWS 服务**，包括 [[CloudFront]]、[[AWS Load Balance]]（ALB/NLB/CLB）、[[Amazon API Gateway]]、AWS CloudFormation 部署的资源等
- **区域限制（考试高频）**：为 **CloudFront** 使用的 ACM 证书**必须在 us-east-1（N. Virginia）区域申请**，无论 CloudFront 分发服务的用户实际分布在哪些地理区域，否则该证书不会出现在 CloudFront 的证书选择列表中；而绑定到 ALB/API Gateway 的证书需要与这些资源**所在的区域一致**

---

## 自动续期机制

- 由 DNS 验证签发的公有证书，ACM 会在到期前**自动尝试续期**
- 若证书已绑定到 **ACM 集成的服务**（如 CloudFront/ALB），续期后的新证书会**自动替换**旧证书，服务无感知、无需任何客户操作
- 若证书**未绑定**任何 ACM 集成服务（如导出后用于自建服务器），续期后需要客户**手动导出并重新部署**新证书
- 私有证书（AWS Private CA 签发）同样支持**托管续期（Managed Renewal）**：到期前约 60 天自动尝试续期，逻辑与公有证书一致

---

## 证书有效期（考试提示，行业规则变化）

- 遵循 **CA/Browser Forum** 行业规范，自 2026 年初起，ACM 新签发的**公有证书最长有效期收紧至 198 天**（较此前更短），这是行业范围内缩短证书有效期以提升安全性的趋势，而非 ACM 特有的限制
- 由于 ACM 的自动续期机制，这一变化对使用**集成服务自动续期**的客户基本无感知；但对导出证书手动部署的场景，意味着需要**更频繁的手动续期操作**

---

## AWS Private CA 与私有证书

- **AWS Private CA** 是独立的托管私有证书颁发机构服务，用于签发**企业内部信任**（而非公网信任）的证书
- 典型场景：内部微服务间的 **mTLS（双向 TLS）**认证、混合云环境中本地服务器与云端服务的加密通信、物联网设备身份认证
- 私有证书通过 ACM 签发后同样可绑定到 ACM 集成服务，也可**导出私钥**用于自建服务器、容器等任意工作负载

---

## 安全性

| 机制 | 说明 |
|------|------|
| **私钥保护** | 公有证书默认私钥不离开 ACM（除非显式启用导出），降低私钥泄露风险 |
| **IAM 策略** | 控制哪些身份可以申请、导出、删除证书 |
| **审计** | 证书的申请、续期、绑定等操作可通过 [[CloudTrail]] 审计 |
| **Security Hub 集成** | 可检测配置不当的证书（如即将过期未续期、使用了弱加密算法），统一汇总到安全态势看板 |

## 典型应用场景

| 场景 | 推荐配置 |
|------|---------|
| **CloudFront/ALB/API Gateway 启用 HTTPS** | ACM 公有证书（免费，DNS 验证，自动续期） |
| **CloudFront 证书申请** | 必须在 **us-east-1** 区域申请证书 |
| **域名由 Route 53 管理，希望零人工干预续期** | DNS 验证 + Route 53 自动添加验证记录 |
| **企业内部服务间的 mTLS 加密通信** | AWS Private CA + ACM 私有证书 |
| **需要在自建 EC2/容器/本地服务器上使用证书** | 可导出的公有证书（2025 年新特性，需额外付费）或私有证书 |
| **证书已导出用于非集成服务，到期需要人工介入** | 提前规划手动续期流程，DNS 验证方式续期相对简单 |
| **需要满足最新证书有效期合规要求** | 依赖 ACM 自动续期机制，无需手动跟踪 198 天有效期窗口 |

## 考试重点总结

### SAA-C02 高频考点

1. **核心定位**：集中管理 SSL/TLS 证书，负责申请、部署、自动续期，深度绑定 AWS 集成服务
2. **公有证书免费，私有证书付费**：公有证书面向公网服务，私有证书面向企业内部信任场景
3. **公有证书默认不可导出私钥**：只能绑定到 ACM 集成服务使用，2025 年起支持额外付费的可导出公有证书
4. **DNS 验证是自动续期的前提**：邮件验证方式的证书续期仍需人工介入
5. **CloudFront 证书必须在 us-east-1 申请**：区域限制是高频考点，与 ALB/API Gateway 证书需要与资源同区域的规则不同
6. **自动续期仅对绑定 ACM 集成服务的证书完全无感**：未绑定的证书续期后仍需手动导出部署
7. **私有证书依赖 AWS Private CA**：适合内部 mTLS、混合云、IoT 设备身份认证等场景
8. **2026 年起公有证书最长有效期缩短至 198 天**：行业规范变化，自动续期客户基本无感
9. **Route 53 托管域名可实现证书验证全自动化**：ACM 自动添加 DNS 验证记录，无需人工操作
10. **证书审计可结合 CloudTrail 和 Security Hub**：追踪证书操作并发现配置不当的证书

### 场景题解题思路

```
场景分析 → 判断使用 ACM 的哪种配置
├── "需要为 CloudFront/ALB/API Gateway 启用 HTTPS，且免费自动续期" → ACM 公有证书 + DNS 验证
├── "为 CloudFront 申请证书但证书列表中找不到" → 检查证书是否在 us-east-1 区域申请
├── "希望证书验证和续期全程零人工干预" → DNS 验证 + Route 53 自动管理域名
├── "企业内部服务间需要 mTLS 加密通信" → AWS Private CA + ACM 私有证书
├── "需要在自建 EC2/本地服务器上安装证书" → 可导出的公有证书或私有证书
├── "证书未绑定 ACM 集成服务，到期后服务受影响" → 需人工导出并重新部署续期后的证书
└── "需要满足证书有效期合规要求（198 天）" → 依赖 ACM 自动续期，无需手动跟踪
```

## 最佳实践

1. **优先使用 DNS 验证而非邮件验证**：这是实现全自动续期、避免人工介入的关键前提
2. **域名管理尽量使用 Route 53**：让 ACM 自动完成验证记录添加，进一步简化证书生命周期管理
3. **CloudFront 场景务必在 us-east-1 申请证书**：避免因区域错误导致证书在控制台找不到的常见问题
4. **证书尽量绑定 ACM 集成服务而非导出后自行部署**：最大化自动续期的价值，减少人工运维负担
5. **内部服务场景优先评估私有证书而非自签名证书**：获得集中管理、自动续期等托管能力，而非依赖脆弱的自签名证书流程
6. **确需导出证书的场景提前规划续期流程**：明确责任人和续期提醒机制，避免证书过期导致服务中断
7. **结合 CloudTrail 和 Security Hub 监控证书状态**：主动发现即将过期未续期或配置不当的证书
8. **多域名场景评估通配符证书或多域名 SAN 证书**：减少证书数量，简化管理复杂度
