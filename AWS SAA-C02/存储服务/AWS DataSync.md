# AWS DataSync - 自动化数据传输

> **AWS DataSync** 是全托管的**在线数据传输**服务，用于在本地存储系统与 AWS 存储服务之间，或 AWS 存储服务之间，自动化、加速地完成**持续/增量**数据同步，是"网络带宽充足"场景下 [[AWS Snowball]] 的替代方案。
>
> 相关文档：[[AWS Snowball]] | [[AWS Storage Gateway]] | [[S3 - Object Storage]] | [[文件储存 - AWS EFS]] | [[文件储存 - AWS FSx]] | [[虚拟私有云 - VPC]]

---

## 核心概念

### DataSync 定位（考试要点）

| 方案 | 迁移方式 | 是否持续同步 | 适用场景 |
|------|---------|------------|---------|
| **AWS DataSync** | 网络自动化传输 | **支持**，可按计划任务重复执行 | 有可用网络带宽，需要持续/增量同步本地与云端存储 |
| [[AWS Snowball]] | 物理设备运输 | 否，一次性迁移 | 数据量巨大、网络带宽不足或不可用 |
| [[AWS Storage Gateway]] | 混合云网关（持续在线） | 持续在线访问，非批量任务 | 长期、实时的本地应用直接读写云存储 |
| AWS DMS | 数据库复制 | 支持持续复制 | 数据库到数据库的迁移/同步，而非文件/对象存储 |

> **考试陷阱**：**DataSync 传输的是文件/对象数据**（本地文件系统 ↔ S3/EFS/FSx）；数据库迁移应使用 **AWS DMS**，两者不可混淆。

### 核心价值

- **自动化**：无需手写脚本或使用 `rsync`/`scp` 等工具手动管理传输任务，DataSync 自动处理重试、校验、加密
- **加速传输**：使用 AWS 专有的数据传输协议，能达到网络带宽上限的 **10 倍**（相比开源工具），充分利用可用带宽
- **增量同步**：任务重复执行时，只传输**发生变化的数据**（新增、修改、删除），大幅减少后续同步的时间和成本
- **自动校验**：传输过程中自动进行数据完整性校验，确保源和目标数据一致

## 工作机制

### DataSync Agent（代理）

- 若源端是**本地数据中心**，需要在本地网络部署一个 **DataSync Agent**（以虚拟机镜像形式提供：VMware/Hyper-V/KVM，或作为 EC2 实例部署）
- Agent 负责读取本地文件系统数据，通过网络将数据传输到 AWS
- 若源端和目标端**都在 AWS 内部**（如 EFS 到 S3、跨区域 S3 到 S3），则**无需部署 Agent**，DataSync 直接在 AWS 内部完成传输

### 支持的存储端点

| 类型 | 支持的位置 |
|------|-----------|
| **本地存储** | NFS、SMB 文件服务器、自建对象存储（Hadoop HDFS 等） |
| **AWS 存储** | [[S3 - Object Storage]]、[[文件储存 - AWS EFS]]、[[文件储存 - AWS FSx]]（Windows/Lustre/ONTAP/OpenZFS） |
| **其他云** | 支持跨云传输（如从其他公有云对象存储迁移到 AWS） |

### 传输任务（Task）

- 定义**源位置**和**目标位置**，可配置**传输计划（Schedule）**实现周期性自动同步（如每小时/每天）
- 支持**过滤规则**，只同步符合条件的文件/目录
- 传输带宽可**限速（Bandwidth Throttling）**，避免占满本地网络出口带宽影响其他业务

## 安全性

| 机制 | 说明 |
|------|------|
| **传输加密** | 数据在传输过程中使用 **TLS** 加密 |
| **静态加密** | 目标端数据落地后遵循目标存储服务自身的加密机制（如 S3 SSE、EFS 静态加密） |
| **VPC 私有连接** | 支持通过 [[虚拟私有云 - VPC]] Endpoint 私有连接，流量不经过公网 |
| **IAM 权限控制** | 通过 IAM 角色/策略控制 DataSync 任务对源和目标存储的访问权限 |

## 典型应用场景

| 场景 | 推荐配置 |
|------|---------|
| **本地文件服务器持续同步到云端** | DataSync Agent（本地）+ 定时任务同步到 S3/EFS/FSx |
| **数据中心迁移前的预热同步** | DataSync 先做批量增量同步，减少割接当天的数据量 |
| **EFS/FSx 之间或跨区域的存储间同步** | 无需 Agent，DataSync 直接在 AWS 内部传输 |
| **混合云架构下的定期备份** | DataSync 计划任务定期将本地数据备份到 S3 |
| **网络带宽充足但数据持续增长** | DataSync 增量同步，避免每次全量传输 |
| **数据量巨大或网络不可用** | 改用 [[AWS Snowball]]，而非 DataSync |

## 考试重点总结

### SAA-C02 高频考点

1. **核心定位**：网络自动化传输，适合有带宽、需要持续/增量同步的场景
2. **DataSync vs Snowball**：有可用网络带宽用 DataSync；网络不可用/成本过高/数据量巨大用 Snowball
3. **传输对象是文件/对象数据**：本地文件系统 ↔ S3/EFS/FSx；数据库迁移应使用 AWS DMS，而非 DataSync
4. **本地源需要部署 Agent**：以虚拟机镜像或 EC2 实例形式运行，AWS 内部传输（如 EFS→S3）无需 Agent
5. **增量同步是核心优势**：重复执行的任务只传输变化的数据，降低时间和成本
6. **传输速度可达开源工具的 10 倍**：得益于 AWS 专有传输协议对带宽的高效利用
7. **支持限速**：避免同步任务占满本地网络出口带宽，影响其他业务
8. **支持计划任务**：可配置周期性自动同步，无需人工触发
9. **自动数据完整性校验**：传输后自动比对源和目标，确保数据一致
10. **支持 VPC 私有连接**：敏感数据传输可避免经过公网

### 场景题解题思路

```
场景分析 → 选择传输方案
├── "本地文件服务器需要持续/定期同步到 S3 或 EFS" → AWS DataSync
├── "数据量巨大或网络带宽不足，一次性迁移" → AWS Snowball（而非 DataSync）
├── "需要迁移的是数据库而非文件/对象数据" → AWS DMS（而非 DataSync）
├── "EFS 与 S3 之间，或跨区域存储之间同步，均在 AWS 内部" → DataSync，无需部署 Agent
├── "希望减少重复同步时的传输量和时间" → DataSync 增量同步
├── "同步任务不能占满本地网络出口带宽" → 配置 DataSync 带宽限速
└── "需要长期、实时地让本地应用直接读写云存储（而非批量任务）" → [[AWS Storage Gateway]]（而非 DataSync）
```

## 最佳实践

1. **网络带宽充足时优先 DataSync**：比 Snowball 更快见效，且支持持续同步
2. **本地源部署 Agent 前评估资源**：Agent 需要一定的 CPU/内存/网络资源，建议独立部署而非与其他业务共用主机
3. **合理设置传输计划**：按数据变化频率配置 Schedule，避免过于频繁的空跑或数据陈旧
4. **迁移前先用 DataSync 预热同步**：大规模迁移前先同步大部分数据，减少最终割接窗口的数据量
5. **敏感数据传输走 VPC Endpoint**：避免流量经过公网
6. **合理设置限速**：与本地网络管理员协调带宽占用，避免影响生产网络
7. **数据库场景改用 AWS DMS**：不要用 DataSync 处理数据库层面的迁移或复制
