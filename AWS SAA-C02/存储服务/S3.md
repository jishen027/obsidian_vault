# S3 - Simple Storage Service

> **Amazon S3 (Simple Storage Service)** 是 AWS 提供的分布式对象存储服务，为任何规模的数据提供高持久性、高可用性的存储。是 AWS 架构中最基础和最常用的服务之一。
>
> 相关文档：[[Storage Service]] | [[S3 Glacier Archive]] | [[EBS]] | [[S3 Security]] | [[Amazon Athena]] | [[Redshift]] | [[AWS Glue]] | [[Disaster Recovery On AWS]] | [[AWS Outposts]] | [[AWS Amplify]]

---

## 核心概念

### 对象存储 vs 块存储

| 特性 | S3 (对象存储) | [[EBS]] (块存储) |
|------|--------------|-------------------------|
| 数据结构 | 扁平命名空间，对象由 Key 标识 | 将数据划分为块，由文件系统管理 |
| 访问方式 | REST API (HTTP/HTTPS) | 块设备挂载（如 `/dev/sdf`） |
| 适用场景 | 静态资源、备份归档、大数据分析 | 操作系统盘、数据库、企业级应用 |
| 一致性模型 | 强一致性（2020 年后） | 强一致性 |

### 基本组成

| 组件 | 描述 |
|------|------|
| **Bucket (存储桶)** | S3 的全局唯一命名容器，类似文件夹根目录 |
| **Object (对象)** | S3 中的基本存储单元，包含数据、元数据和 Key |
| **Key (键)** | 对象的唯一标识符，支持文件夹结构（`prefix/prefix/key`） |
| **Version (版本)** | 启用版本控制后，每个对象有多个版本 |

## 组织架构和规模

### Bucket 命名规则

- **全局唯一**：Bucket 名称在 AWS 全局范围内唯一
- 长度：3-63 个字符
- 只能包含小写字母、数字、点和连字符
- 不能是 IP 地址格式

### 容量限制

| 限制项 | 值 |
|--------|-----|
| 单个对象大小 | **5 GB - 5 TB**（大于 100 MB 建议使用分块上传） |
| Bucket 容量 | **无限** |
| 每个 Bucket 的对象数 | **无限** |
| 对象 Key 最大长度 | 1,024 个字符 |

### 分块上传 (Multipart Upload)

- **分块大小**：100 KB - 5 GB（推荐 50-100 MB）
- **最大块数**：10,000 个块
- **优势**：
  - 大文件上传的可靠性和性能
  - 中断后可从断点恢复
  - 并行上传提高效率

## 存储类别

### S3 存储类别对比（考试重点）

| 存储类别                        | 持久性   | 可用性    | 最小存储期限 | 检索时间     | 适用场景         |
| --------------------------- | ----- | ------ | ------ | -------- | ------------ |
| **S3 Standard**             | 11个9  | 99.99% | 无      | 即时       | 频繁访问的热数据     |
| **S3 Intelligent-Tiering**  | 11个9  | 99.99% | 无      | 即时       | 访问模式未知或变化的数据 |
| **S3 Standard-IA**          | 11个9  | 99.9%  | 30 天   | 即时       | 不频繁访问但需要快速检索 |
| **S3 One Zone-IA**          | 99.5% | 99.5%  | 30 天   | 即时       | 可重新创建的非关键数据  |
| **S3 Glacier Flexible**     | 11个9  | 99.99% | 90 天   | 分钟-小时    | 归档数据，定期访问    |
| **S3 Glacier Deep Archive** | 11个9  | 99.99% | 180 天  | 12-48 小时 | 长期合规归档       |

> **考试陷阱**：**S3 on [[AWS Outposts]] 不是上表中的某个存储类别，而是部署位置完全不同的独立产品**——它是运行在客户本地机房 Outposts 硬件上的固定容量对象存储，API 兼容标准 S3 但不具备完整的存储类别体系和默认跨区域复制能力，题目描述"数据必须留在本地机房，同时希望用 S3 API 管理" → S3 on Outposts，而非误以为选择某个标准 S3 存储类别即可满足数据本地化要求。

### S3 Intelligent-Tiering 详解（考试重点：不是单一类别，是自动分层的容器）

> **Intelligent-Tiering 本质是一个"自动分层"的容器**，内部包含多个访问层级（Access Tier），S3 会持续监测每个对象的访问模式，自动在层级之间迁移对象——**这个迁移过程免费、无检索费**，这是它和其他存储类别最本质的区别。

#### 内部访问层级

| 层级 | 触发条件（连续未访问天数） | 定价对标 | 检索延迟 | 是否默认启用 |
|------|---------------------------|---------|---------|-------------|
| **Frequent Access（频繁访问层）** | 默认层，新对象上传即进入 | 等同 S3 Standard | 即时 | ✅ 默认 |
| **Infrequent Access（不频繁访问层）** | 连续 30 天未访问 | 等同 S3 Standard-IA | 即时 | ✅ 默认 |
| **Archive Instant Access（归档即时访问层）** | 连续 90 天未访问 | 等同 S3 Glacier Instant Retrieval | **仍是即时**（毫秒级） | ✅ 默认 |
| **Archive Access（归档访问层）** | 可配置 90~730 天未访问 | 等同 S3 Glacier Flexible Retrieval | 分钟~小时（需发起 Restore） | ❌ 需手动开启 |
| **Deep Archive Access（深度归档访问层）** | 可配置 180~730 天未访问 | 等同 S3 Glacier Deep Archive | 数小时（需发起 Restore） | ❌ 需手动开启 |

- 一旦对象被重新访问，会**自动、免费**地移回 Frequent Access 层——不需要手动干预，也不产生检索费
- **Archive Access 和 Deep Archive Access 是可选层级**，默认不启用；只有当业务能接受偶尔的分钟/小时级检索延迟、且希望进一步压低长期不访问对象的存储成本时，才手动为存储桶配置这两层

#### 计费机制（考试易漏点）

| 费用项 | 说明 |
|--------|------|
| **存储费** | 按对象当前所在层级的单价计费，逐层递减（Frequent 最贵，Deep Archive 最便宜） |
| **检索费** | **完全没有**——这是 Intelligent-Tiering 相比 Standard-IA/One Zone-IA/Glacier 系列最大的优势，无论对象在哪个层级，读取都不额外收检索费 |
| **监控和自动化费（Monitoring and Automation Charge）** | 按对象数量、每月收取小额费用，**仅对大于 128 KB 的对象**收取——小于 128 KB 的对象太小、监控成本不划算，会一直留在 Frequent Access 层，不产生这笔费用，也不会被移动 |
| **最短存储期限** | **无**——这一点和 Standard 一样，与 Standard-IA/One Zone-IA 的 30 天限制不同 |

> **考试关键词识别**：题目出现**"访问模式未知/会随时间变化，希望自动优化成本，且不希望因为访问模式判断错误而被检索费"打脸""** 这类描述时，标准答案是 Intelligent-Tiering；如果题目额外强调**"数据几乎不会再被访问，愿意接受更长的检索延迟以换取更低成本"**，则应进一步为 Intelligent-Tiering **开启 Archive Access / Deep Archive Access 层**，而不是直接手动把对象转到独立的 Glacier 存储类别（两者最终存储单价相近，但 Intelligent-Tiering 的自动化和免检索费特性通常更省心）。
>
> **与 Standard-IA 的选型边界**（完整对比见下方"Standard-IA vs Intelligent-Tiering"）：如果题目已经明确告知一个**具体、稳定、可预测**的访问频率（如"每年访问两次"），说明访问模式已知，不需要为 Intelligent-Tiering 的监控自动化功能付费，应直接选 Standard-IA；只有访问模式**不确定或会变化**时，Intelligent-Tiering 的自动分层价值才能体现出来。

### 存储类别选择指南（考试场景题）

```
需要即时访问？
├── 是 → 频繁访问？
│         ├── 是 → S3 Standard
│         └── 否 → 访问模式可预测？
│                   ├── 是 → S3 Standard-IA
│                   └── 否 → S3 Intelligent-Tiering
└── 否 → 可接受延迟？
          ├── 分钟-小时 → S3 Glacier Flexible Retrieval
          └── 12-48 小时 → S3 Glacier Deep Archive
```

### 存储类别成本对比

| 存储类别 | 存储成本 | 检索成本 | 适合数据比例 |
|---------|---------|---------|------------|
| S3 Standard | 最高 | 无 | 100% 热数据 |
| S3 Standard-IA | 低 50% | 按检索量计费 | 冷数据 |
| S3 One Zone-IA | 低 60% | 按检索量计费 | 可重新创建的数据 |
| S3 Glacier | 低 95% | 按检索时间和时长计费 | 归档数据 |
| S3 Glacier Deep Archive | 低 96% | 按检索时间和时长计费 | 长期归档 |

### 生命周期转换的"瀑布模型"：哪些转换合法（考试高频，多选题常考）

> S3 存储类别之间的生命周期转换遵循单向的"瀑布"顺序，**不是任意两个类别之间都能互转**。记住下面这张图，比死记每一条规则更可靠。

```
S3 Standard ──┬──▶ S3 Intelligent-Tiering ──▶ S3 One Zone-IA
              ├──▶ S3 Standard-IA ──┬──▶ S3 Intelligent-Tiering
              │                     └──▶ S3 One Zone-IA
              ├──▶ S3 Glacier Instant Retrieval
              ├──▶ S3 Glacier Flexible Retrieval ──▶ S3 Glacier Deep Archive
              └──▶ S3 Glacier Deep Archive
```

| 转换方向 | 是否合法 |
|---------|---------|
| S3 Standard → 任意其他存储类别 | ✅ 合法（起点，可以去任何地方） |
| S3 Standard-IA → S3 Intelligent-Tiering 或 S3 One Zone-IA | ✅ 合法 |
| S3 Intelligent-Tiering → S3 One Zone-IA | ✅ 合法 |
| 任意存储类别 → S3 Glacier 系列 | ✅ 合法 |
| **任意存储类别 → S3 Standard** | ❌ **不合法**（S3 Standard 只能是起点，不能是转换目标） |
| **S3 Intelligent-Tiering → S3 Standard-IA** | ❌ **不合法**（Intelligent-Tiering 只能单向去 One Zone-IA，回不到 Standard-IA） |
| **S3 One Zone-IA → S3 Standard-IA 或 S3 Intelligent-Tiering** | ❌ **不合法**（One Zone-IA 是这条瀑布链的末端之一，不能"升级"回单可用区以上的类别） |

> **考试陷阱**：这类题目常问"以下哪些是**不合法**的转换"（反向提问），容易一时大意选反。记忆口诀：**瀑布只能往下流，不能往上游**——Standard 是唯一的源头（只出不进），One Zone-IA 和 Deep Archive 是末端（只进不出），Intelligent-Tiering 和 Standard-IA 之间可以互相到达对方，但都到不了比自己"更热"的类别。

### 短期/高频引用数据的存储类别陷阱：min duration + 检索费的组合（考试高频）

> 题目常见套路：数据"访问不频繁"看似该选 IA 类，但结合**最短存储期限**和**检索费**两个隐藏成本后，S3 Standard 反而是更省钱的答案。

- **最短存储期限（Minimum Storage Duration）**：Standard-IA 和 One Zone-IA 都要求至少存储 **30 天**，Glacier Flexible 是 90 天，Deep Archive 是 180 天——如果数据的实际生命周期**短于**这个最短期限（例如只保留 24 小时就会被删除），仍然要按最短期限计费，相当于变相支付了远超实际存储时长的费用
- **检索费（Retrieval Fee）**：IA 和 Glacier 系列都按检索量收费，Standard **不收检索费**——如果数据会被**频繁引用/检索**（哪怕只存在很短时间），检索费可能远超"更便宜"的存储单价带来的节省

> **考试关键词识别**：题目同时具备"**数据存活期很短（如 24 小时）**"和"**会被下游频繁引用/检索**"这两个特征时，即使听起来是"不常访问"的数据，正确答案往往还是 **S3 Standard**——因为 IA 类别的最短存储期限费用 + 检索费加总后，反而比 Standard 更贵。反过来，"访问频率低**且**生命周期足够长（≥30 天）**且**极少检索"的数据才真正适合 Standard-IA/One Zone-IA。

### Standard-IA vs Intelligent-Tiering：访问模式"已知稳定"还是"未知/多变"

> 两者的存储和检索定价结构几乎一样，唯一的区别是 **Intelligent-Tiering 每月收取少量的对象监控和自动化费用**，用于持续监测访问模式并自动切换层级。

| 场景 | 该选哪个 |
|------|---------|
| **访问频率已知且稳定**（如"一年只访问两次"这种可预测的固定模式） | **Standard-IA**——访问模式已经确定，不需要为"自动监测并切换"这个功能额外付费 |
| **访问模式未知，或会随时间变化、无法预测** | **Intelligent-Tiering**——让 AWS 自动监测并在不同层级间迁移，避免因访问模式突变而被高额检索费"打脸" |

> **考试陷阱**：题目描述一个**具体、已知的低频访问频率**（如"每年访问两次"）时，正确答案通常是 **Standard-IA**，而不是听起来更"智能"的 Intelligent-Tiering——既然访问模式已经明确告知，就不需要为 Intelligent-Tiering 的监控自动化功能支付额外费用。

## 持久性和可用性

### 数据保护机制

| 特性 | 说明 |
|------|------|
| **持久性** | **99.999999999% (11个9)**，设计为每年丢失 0.005% 以下的数据 |
| **可用性** | S3 Standard：99.99%（SLA） |
| **数据复制** | 自动在多个可用区 (AZ) 冗余存储（One Zone-IA 除外） |

### 版本控制

- 启用后，对对象的每次编辑都会生成新版本
- 可以恢复意外删除或覆盖的对象
- **不能暂停**，只能启用或禁用
- 适用于防止人为错误和合规要求

### 生命周期管理

- 自动将对象转换到更经济的存储类别
- 可配置规则：
  - 基于时间的转移（如 30 天后转移到 IA，90 天后转移到 Glacier）
  - 基于前缀或标签的转移
  - 过期后自动删除

#### 典型生命周期配置（考试常见场景）

```
创建 → S3 Standard (热数据)
        ↓ (30天后)
     S3 Standard-IA
        ↓ (90天后)
     S3 Glacier
        ↓ (180天后)
     S3 Glacier Deep Archive
        ↓ (7年后)
     自动删除
```

## 安全性

### 访问控制模型

| 机制 | 描述 |
|------|------|
| **IAM 策略** | 基于身份的权限策略，控制谁可以访问 S3 |
| **Bucket Policy** | 附加到 Bucket 的资源型策略 |
| **ACL (访问控制列表)** | 细粒度控制 Bucket 和对象的访问权限 |
| **S3 Access Points** | 为 S3 提供自定义入口，简化数据访问管理 |
| **Object Lambda** | 在访问对象时实时转换数据 |

### 加密

| 加密类型 | 服务 | 说明 |
|---------|------|------|
| **SSE-S3** | S3 管理密钥 | 默认加密，最简单 |
| **SSE-KMS** | AWS KMS | 密钥管理更精细，审计更强 |
| **SSE-C** | 客户管理密钥 | 客户负责密钥管理 |
| **客户端加密** | 客户端 | 上传前加密 |

### 访问日志和监控

- **S3 Access Logging**：记录访问 Bucket 的请求
- **S3 Inventory**：生成对象清单，用于合规和自动化
- **CloudTrail**：审计 S3 API 调用
- **CloudWatch Metrics**：监控存储量和请求数

## 网络访问

### S3 存储桶 URL 格式

| 类型 | 格式 | 示例 |
|------|------|------|
| **虚拟托管式** | `https://bucket-name.s3.region.amazonaws.com/key` | `https://mybucket.s3.us-east-1.amazonaws.com/photo.jpg` |
| **路径式** | `https://s3.region.amazonaws.com/bucket-name/key` | `https://s3.us-east-1.amazonaws.com/mybucket/photo.jpg` |
| **虚拟主机式 (DNS)** | `https://bucket-name.s3.amazonaws.com` | 用于 us-east-1 区域 |

### [[VPC Endpoints|VPC 终端节点]] (VPC Endpoint)

- **类型**：接口终端节点 (Interface Endpoint)
- **功能**：让 VPC 内的资源通过私有网络访问 S3，不经过公网
- **优势**：
  - 安全性：流量不暴露在公共互联网
  - 成本：无需 [[NAT Gateway|NAT 网关]]费用
  - 性能：更低延迟，更稳定
- **配合 Bucket Policy**：限制只有通过终端节点才能访问 Bucket

### S3 访问方式对比

| 方式 | 网络路径 | 费用 | 安全性 |
|------|---------|------|--------|
| 互联网 + [[Internet Gateway\|IGW]] | 通过公网 | 数据传输费 | 较低 |
| [[VPC Endpoints\|VPC Endpoint]] | 私有网络 | 无数据传输费 | 高 |
| CloudFront + Origin Access | CDN 缓存 | 低延迟 | 高 |
| [[AWS Storage Gateway]] | 混合云 | 额外费用 | 高 |

## 高级功能

### CloudFront 集成

- S3 可作为 CloudFront 的源站
- **Origin Access Control (OAC)**：保护私有 Bucket，只允许 CloudFront 访问
- CDN 缓存静态内容，降低延迟和 S3 请求成本

### 签名 URL (Signed URL)

- **用途**：临时授权访问私有对象
- **机制**：URL 包含签名认证字符串，在有效期内有效
- **特点**：
  - 过期后自动失效
  - 可指定访问权限（读/写）
  - 使用签名密钥完成身份验证
- **适用场景**：用户临时下载/上传私有文件

### 事件通知

- S3 可触发 **Lambda 函数**（如图片缩略图生成）
- 可发送消息到 **SQS** 或 **SNS**
- 适用于自动化数据处理流水线

### S3 Replication

| 类型 | 说明 |
|------|------|
| **CRR (跨区复制)** | 跨区域复制，满足合规要求 |
| **SRR (同区复制)** | 同区域内跨 Bucket 复制，自动版本复制 |

## 考试重点总结

### SAA-C02 高频考点

1. **存储类别选择**：根据访问频率、延迟要求、成本选择正确类别
2. **生命周期策略**：自动转换存储类别降低成本
3. **版本控制**：防止意外删除和覆盖
4. **加密**：SSE-S3、SSE-KMS、SSE-C 的区别和选择
5. **VPC Endpoint**：私有访问 S3，避免数据经过公网
6. **CloudFront + S3**：Origin Access 保护私有 Bucket
7. **事件驱动架构**：S3 事件触发 Lambda
8. **一致性模型**：S3 提供强一致性（读后写一致性）
9. **存储类别成本排序**：Standard > IA > One Zone-IA > Glacier > Deep Archive
10. **分块上传**：大于 100 MB 使用分块上传

### 常见场景题解题思路

```
场景题 → 提取关键词 → 匹配存储类别
├── "频繁访问" → S3 Standard
├── "不频繁但需即时" → S3 Standard-IA
├── "访问模式未知" → Intelligent-Tiering
├── "可重新创建" → One Zone-IA
├── "归档，分钟级检索" → Glacier Flexible
└── "归档，12-48小时" → Glacier Deep Archive
```

---

## 最佳实践

1. **选择正确的存储类别**：根据访问模式选择，使用 Intelligent-Tiering 自动化
2. **启用版本控制**：防止意外删除和覆盖
3. **配置生命周期策略**：自动转移冷数据降低成本
4. **启用加密**：默认使用 SSE-S3 或 SSE-KMS
5. **使用 VPC Endpoint**：VPC 内访问 S3 时保护数据安全
6. **CloudFront 缓存**：静态内容使用 CloudFront 加速
7. **设置 Bucket 日志**：审计和监控访问
8. **使用标签**：组织和管理对象
