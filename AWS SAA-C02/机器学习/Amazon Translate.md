# Amazon Translate - 神经网络机器翻译服务

> **Amazon Translate** 是全托管的**神经网络机器翻译（Neural Machine Translation, NMT）**服务，基于深度学习模型在文本的**语言对**之间提供快速、高质量的翻译，支持数十种语言、数千种语言对组合，无需自行训练或运维翻译模型。
>
> 相关文档：[[Amazon Transcribe]] | [[Amazon Polly]] | [[Amazon Rekognition]] | [[Amazon SageMaker]] | [[S3]] | [[AWS Lambda]] | [[Amazon API Gateway]] | [[IAM]] | [[KMS]]

---

## 核心概念

### 为什么需要 Translate

- **自建翻译模型的门槛**：高质量的机器翻译需要海量平行语料（双语对照文本）和专业的自然语言处理能力，且需要为每个语言对单独训练和维护模型
- **Translate 的核心价值**：提供**预训练**的神经网络翻译能力，通过 API 调用即可在数千种语言对之间实时翻译，并支持**自定义术语表**确保专有名词按业务要求翻译，无需从零训练模型
- **在 AWS AI 服务栈中的定位**：与 [[Amazon Transcribe]]、[[Amazon Polly]]、[[Amazon Rekognition]] 一样，Translate 是**开箱即用、面向特定任务（跨语言文本翻译）**的托管 AI 服务，区别于需要自行训练调优的通用机器学习平台（[[Amazon SageMaker]]）

### Translate 在 SAA-C02 考试中的定位（考试要点）

| 服务 | 处理对象 | 核心能力 | 典型场景 |
|------|---------|---------|---------|
| **Translate** | 文本（跨语言） | 将文本从一种语言翻译为另一种语言 | 多语言网站/应用内容本地化、跨语言客服、文档翻译 |
| [[Amazon Transcribe]] | 音频（同语言转文本） | 语音转文字（不跨语言） | 会议转写、字幕生成 |
| [[Amazon Polly]] | 文本（转语音） | 文字转语音（不跨语言） | 语音播报、有声内容生成 |

> **考试要点**：**Translate 专注于"跨语言"这一维度**，与 Transcribe（语音↔同语言文本）、Polly（同语言文本↔语音）是三个正交的能力——三者常组合使用，例如"外语语音 → Transcribe 转文本 → Translate 翻译成目标语言 → Polly 合成目标语言语音"，构成完整的**实时跨语言语音翻译管道**。

## 核心能力

| 能力 | 说明 |
|------|------|
| **自动语言检测（Automatic Language Detection）** | 无需预先指定源语言，Translate 可自动识别输入文本使用的语言 |
| **批量文档翻译（Batch Translation）** | 对存储在 [[S3]] 中的大批量文档做异步翻译，并保留原始文档格式（如 Word、PowerPoint、HTML 等） |
| **实时翻译（Real-Time Translation）** | 同步调用 API，适合单条短文本的即时翻译场景（如聊天消息、评论） |
| **自定义术语表（Custom Terminology）** | 定义特定品牌名、产品名、行业术语的固定翻译方式，避免机器翻译产生不符合业务要求的译法 |
| **主动自定义翻译（Active Custom Translation, ACT）** | 提供自有的平行语料（双语对照数据），让 Translate 针对特定领域语料微调翻译输出，无需训练完整的自定义模型 |
| **格式化控制** | 支持调整译文的**正式程度（Formality）**、**脏话过滤（Profanity Masking）**、**简洁度（Brevity）**等输出风格 |

> **考试要点**：题目描述**"翻译结果中的品牌名/产品名被错误翻译，需要保持固定译法"** → 使用**自定义术语表（Custom Terminology）**；题目描述**"希望结合自有的双语语料让翻译更贴合特定领域"** → 使用**主动自定义翻译（ACT）**，两者都无需从零训练完整的翻译模型。

---

## 同步 vs 异步翻译

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **实时翻译（同步）** | 直接调用 API 获取翻译结果，适合单条、短文本 | 聊天消息实时翻译、评论翻译、UI 界面动态翻译 |
| **批量翻译（异步）** | 提交 S3 中的文档，异步处理后将译文写回 S3，保留原始格式 | 大批量文档翻译、多语言内容本地化项目 |

## 架构与集成（考试高频）

| 集成方式 | 说明 |
|---------|------|
| **[[Amazon Transcribe]] + Translate + [[Amazon Polly]]** | 构成完整的**实时跨语言语音翻译管道**：外语语音 → Transcribe 转文本 → Translate 翻译 → Polly 合成目标语言语音 |
| **S3 触发批量翻译** | 文档上传到 [[S3]] 后，通过事件通知触发 [[AWS Lambda]] 调用批量翻译 API |
| **[[Amazon API Gateway]] + Lambda + Translate** | 构建面向应用的实时翻译 REST API，供聊天应用、客服系统等即时调用 |
| **多语言网站/应用本地化** | 结合 CMS 内容管道，批量翻译网站内容并按语言分发 |

> **考试要点**：题目描述**"呼叫中心需要支持多语言客户实时对话，坐席只懂一种语言"** → 组合使用 **Transcribe（转写客户语音）+ Translate（翻译成坐席语言）+ Polly（合成语音反馈给客户）**，这是 SAA-C02 场景题中"多语言语音客服"的标准三件套解法。

## 考试重点总结

### SAA-C02 高频考点

1. **核心定位**：预训练的神经网络机器翻译服务，专注"跨语言"文本翻译，与 Transcribe/Polly 是正交的三个能力
2. **判断依据**：题目强调"不同语言之间"的转换时选 Translate；同语言的语音↔文本转换分别对应 Transcribe/Polly
3. **自动语言检测**：无需预先指定源语言，Translate 自动识别输入语言
4. **实时翻译 vs 批量翻译**：短文本即时翻译用同步 API；大批量文档翻译用异步批量翻译并保留原始格式
5. **自定义术语表（Custom Terminology）**：固定品牌名/产品名/行业术语的翻译方式，避免机器翻译产生不当译法
6. **主动自定义翻译（ACT）**：提供自有平行语料微调翻译输出，无需训练完整自定义模型
7. **格式化控制**：可调整译文的正式程度、脏话过滤、简洁度等输出风格
8. **三件套组合构建语音翻译管道**：Transcribe（转写）+ Translate（翻译）+ Polly（合成），是多语言语音客服的标准架构
9. **批量翻译保留文档格式**：Word/PowerPoint/HTML 等格式在翻译后保持原有排版
10. **支持数千种语言对组合**：广泛的语言覆盖率，适合全球化应用的本地化需求

### 场景题解题思路

```
场景分析 → 判断是否用 Translate
├── "需要将文本从一种语言翻译为另一种语言" → Amazon Translate
├── "网站/应用需要支持多语言本地化" → Translate 批量翻译 + 自定义术语表
├── "聊天/评论内容需要实时翻译" → Translate 实时翻译 API
├── "翻译结果中品牌名/术语翻译不符合业务要求" → 自定义术语表（Custom Terminology）
├── "希望结合自有双语语料提升特定领域翻译质量" → 主动自定义翻译（ACT）
├── "呼叫中心需要支持多语言实时语音对话" → Transcribe + Translate + Polly 组合
├── "需要批量翻译大量文档且保留原始格式" → Translate 批量翻译（异步）
└── "需要将语音转文字或文字转语音（不涉及跨语言）" → 改用 Transcribe/Polly（而非 Translate）
```

## 最佳实践

1. **明确区分"跨语言"与"同语言转换"需求**：只有涉及不同语言之间的转换才需要 Translate，避免与 Transcribe/Polly 混淆
2. **品牌名/专有名词场景提前配置自定义术语表**：避免机器翻译产生不符合业务规范的译法
3. **特定领域翻译评估 ACT**：相比默认通用模型，结合自有语料能显著提升领域适应性
4. **短文本实时场景用同步 API，大批量文档用异步批量翻译**：按场景选择合适的调用模式，避免同步调用处理大文档导致超时
5. **多语言语音客服场景组合三大语言服务**：Transcribe + Translate + Polly 分工协作，而非试图用单一服务覆盖全流程
6. **批量翻译文档确保源格式受支持**：翻译前确认文档格式（Word/PPT/HTML 等）在支持范围内，以保留原始排版
7. **敏感内容翻译结果加密存储**：涉及隐私或商业机密的翻译文档应在 S3 中启用 KMS 加密
8. **利用自动语言检测简化前端逻辑**：无需要求用户或系统预先声明源语言，降低集成复杂度
