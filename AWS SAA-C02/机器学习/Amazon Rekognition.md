# Amazon Rekognition - 图像与视频分析服务

> **Amazon Rekognition** 是全托管的计算机视觉（Computer Vision）服务，基于深度学习模型，为应用添加**图像和视频分析**能力——包括物体/场景识别、人脸检测与分析、文本提取、内容审核等，通过简单的 API 调用即可实现，无需自行训练或运维机器学习模型。
>
> 相关文档：[[Amazon SageMaker]] | [[Amazon Transcribe]] | [[Amazon Kinesis]] | [[S3]] | [[AWS Lambda]] | [[Amazon API Gateway]] | [[IAM]] | [[KMS]]

---

## 核心概念

### 为什么需要 Rekognition

- **自建计算机视觉模型的门槛**：训练准确的图像/视频识别模型需要海量标注数据、专业的机器学习知识和持续的模型调优，对大多数应用团队而言成本过高
- **Rekognition 的核心价值**：提供**预训练（Pre-trained）**的计算机视觉能力，通过 API 直接调用即可获得物体识别、人脸分析、文本提取等结果；同时支持 **Custom Labels** 针对特定业务场景做轻量级模型定制，无需从零训练
- **在 AWS 机器学习服务栈中的定位**：Rekognition 是**开箱即用、面向特定任务（图像/视频）**的托管 AI 服务，区别于需要自行准备数据、选择算法、训练调优的通用机器学习平台（如 [[Amazon SageMaker]]）

### Rekognition 在 SAA-C02 考试中的定位（考试要点）

| 服务 | 类型 | 核心能力 | 典型场景 |
|------|------|---------|---------|
| **Rekognition** | 预训练计算机视觉 API | 图像/视频分析：物体识别、人脸分析、文本提取、内容审核 | 需要"开箱即用"的图像/视频智能分析，无需训练自定义模型 |
| [[Amazon SageMaker]] | 通用机器学习平台 | 自定义模型的训练、调优、部署全生命周期 | 需要针对特有业务数据训练专属模型，非标准视觉任务 |
| Amazon Textract | 文档分析 API | 从扫描文档中提取结构化文本、表格、表单字段 | 专注于文档（而非通用图像）的结构化数据提取 |

> **考试陷阱**：题目描述**"需要快速为应用添加图像识别/人脸检测/内容审核能力，且没有机器学习专业知识或训练数据"** → 答案是 **Rekognition**；若题目强调**"需要针对特有业务场景训练自定义机器学习模型，涉及模型选择、超参数调优"** → 应考虑 **[[Amazon SageMaker]]** 等通用机器学习平台，而非 Rekognition 这种预训练服务。

## 核心能力（图像分析）

| 能力 | 说明 |
|------|------|
| **物体与场景检测（Object & Scene Detection）** | 识别图像中的物体（如"汽车"、"狗"）和场景（如"海滩"、"办公室"），并返回置信度分数 |
| **人脸检测与分析（Face Detection & Analysis）** | 检测图像中的人脸，分析属性（年龄范围、情绪、是否戴眼镜等），**不涉及身份识别** |
| **人脸比对（Face Comparison）** | 比较两张图像中的人脸是否为同一人，返回相似度分数 |
| **文本检测（Text Detection）** | 从图像中提取文字（如路牌、产品标签上的文字） |
| **内容审核（Content Moderation）** | 自动识别图像中的不当内容（暴力、色情等），可自动过滤约 **95%** 的违规内容 |
| **名人识别（Celebrity Recognition）** | 识别图像中的知名公众人物 |
| **PPE 检测（Personal Protective Equipment）** | 检测人员是否正确佩戴安全帽、口罩、护目镜等防护装备，用于工作场所合规检查 |

> **考试要点**：Rekognition 的**人脸检测（Face Detection）**只分析人脸属性，**不识别人的身份**；若需要"判断图像中的人是谁"，需要使用**人脸搜索（Face Search）**功能，将检测到的人脸与预先建立的**人脸集合（Face Collection）**中的已知身份比对。

---

## 核心能力（视频分析）

- 支持对存储在 [[S3]] 中的视频文件做**异步分析**（Asynchronous Analysis），适用于批量处理已录制视频
- 可追踪物体/人物在视频帧间的**运动轨迹**，识别视频中的活动（Activity）
- 结合 [[Amazon Kinesis]] Video Streams 可对**实时视频流**做分析（安全摄像头、直播内容审核等场景）

> **考试提示**：**Rekognition 的实时流式视频分析（Streaming Video Analysis）功能自 2026 年 4 月起停止向新客户开放**（过去 12 个月内已使用该功能的现有客户不受影响），新工作负载若需要处理实时视频流，应评估当前该功能的可用状态；对存储视频文件的**异步批量分析**不受此变化影响，仍是标准能力。

---

## Rekognition Custom Labels

- 允许用户上传**少量标注图像**（相比从零训练模型所需的海量数据大幅减少），基于 Rekognition 的预训练模型做**迁移学习（Transfer Learning）**，训练出针对特定业务场景的自定义识别模型
- **典型场景**：识别特定品牌 Logo、特定生产线上的产品缺陷、特定设备型号等标准预训练模型无法覆盖的细分场景
- 相比使用 [[Amazon SageMaker]] 从零构建计算机视觉模型，Custom Labels 大幅降低了数据量和机器学习专业知识的门槛

---

## Face Liveness（活体检测）

- 用于**身份验证场景**，通过分析用户的实时自拍视频，判断当前操作者是**真人**还是照片/视频/面具等欺骗手段（Spoof）
- 常用于金融开户、身份核验等对身份真实性有强要求的场景，作为人脸比对的前置校验环节

## 架构与集成

| 集成方式 | 说明 |
|---------|------|
| **S3 触发分析** | 图像/视频上传到 [[S3]] 后，通过事件通知触发 [[AWS Lambda]] 调用 Rekognition API 做自动分析 |
| **[[Amazon Kinesis]] Video Streams** | 作为实时视频流的输入源，供 Rekognition 做流式分析 |
| **[[Amazon API Gateway]] + Lambda** | 构建面向应用的图像分析 REST API，前端上传图片后同步/异步返回分析结果 |
| **同步 vs 异步 API** | 图像分析通常是**同步**调用（实时返回结果）；视频分析通常是**异步**调用（提交任务后通过 SNS 通知获取结果） |

## 安全性

| 机制 | 说明 |
|------|------|
| **IAM 策略** | 控制哪些身份可以调用 Rekognition API、访问哪些人脸集合 |
| **静态加密** | 存储的人脸集合等元数据默认加密，也可使用客户管理的 [[KMS]] 密钥 |
| **传输加密** | API 调用默认通过 HTTPS/TLS |
| **VPC Endpoint** | 支持通过接口终端节点在 VPC 内私有调用 Rekognition API，无需经过公网 |

## 典型应用场景

| 场景 | 推荐配置 |
|------|---------|
| **用户上传内容的自动审核** | S3 上传触发 Lambda 调用 Rekognition 内容审核 API |
| **身份核验（金融开户、账户找回）** | Rekognition 人脸比对 + Face Liveness 活体检测 |
| **零售场景的商品/Logo 识别** | Rekognition Custom Labels 训练专属识别模型 |
| **工厂/工地安全合规检查** | Rekognition PPE 检测识别安全装备佩戴情况 |
| **媒体资产库的自动打标签** | 批量分析 S3 中的图像/视频，自动生成物体/场景标签便于检索 |
| **安全摄像头实时监控分析** | Kinesis Video Streams + Rekognition（需确认流式分析功能的当前可用性） |
| **需要针对特有业务训练完全自定义的复杂模型** | 改用 [[Amazon SageMaker]]，而非 Rekognition |

## 考试重点总结

### SAA-C02 高频考点

1. **核心定位**：预训练的计算机视觉 API 服务，开箱即用，无需自行训练模型即可获得图像/视频分析能力
2. **判断依据**：需要"快速集成、无需机器学习专业知识"选 Rekognition；需要"训练完全自定义模型"选 [[Amazon SageMaker]]
3. **人脸检测 ≠ 身份识别**：Face Detection 只分析人脸属性，识别"这是谁"需要 Face Search + 预建的人脸集合
4. **内容审核可自动过滤约 95% 违规内容**：常见于 UGC（用户生成内容）平台的自动化审核方案
5. **Custom Labels 用少量数据做迁移学习**：适合品牌 Logo、产品缺陷等标准模型无法覆盖的细分场景
6. **图像分析同步，视频分析异步**：图像 API 通常实时返回结果；视频分析提交任务后通过 SNS 通知获取结果
7. **视频分析两种模式**：对 S3 存储视频的批量异步分析（标准能力）vs 结合 Kinesis Video Streams 的实时流分析（新客户接入范围有变化）
8. **Face Liveness 用于活体检测**：身份核验场景中防止照片/视频等欺骗手段冒充真人
9. **PPE 检测面向工作场所合规**：识别安全帽、口罩等防护装备佩戴情况
10. **常与 S3/Lambda/Kinesis Video Streams 组合**：构成"存储触发分析"或"实时流分析"的标准架构模式

### 场景题解题思路

```
场景分析 → 判断是否用 Rekognition
├── "需要快速为应用添加图像/视频分析能力，无机器学习经验" → Amazon Rekognition
├── "需要判断图像中人脸的具体身份" → Rekognition Face Search + 人脸集合（而非仅 Face Detection）
├── "需要自动审核用户上传内容中的不当信息" → Rekognition 内容审核 API
├── "需要识别特定品牌 Logo/产品缺陷等细分场景" → Rekognition Custom Labels
├── "身份核验场景需要防止照片/视频冒充真人" → Rekognition Face Liveness
├── "需要针对特有业务训练完全自定义的复杂模型" → 改用 [[Amazon SageMaker]]（而非 Rekognition）
├── "需要从扫描文档提取结构化文本/表格" → 改用 Amazon Textract（而非 Rekognition）
└── "S3 中新上传的图片需要自动打标签" → S3 事件通知 + Lambda 调用 Rekognition API
```

## 最佳实践

1. **标准视觉任务优先使用 Rekognition，而非自建/训练模型**：物体识别、内容审核等常见任务复用预训练能力，降低开发成本
2. **需要身份识别时明确使用 Face Search 而非仅 Face Detection**：两者能力不同，避免混淆导致功能设计错误
3. **细分业务场景评估 Custom Labels 而非从零训练**：用少量标注数据即可获得针对性效果，无需 [[Amazon SageMaker]] 级别的机器学习投入
4. **身份核验场景叠加 Face Liveness**：仅靠人脸比对无法防御照片/视频欺骗，需结合活体检测
5. **图片分析走同步调用，视频分析走异步 + 通知机制**：按 API 类型合理设计前后端交互流程，避免视频分析场景下的同步阻塞
6. **实时视频流场景提前确认功能可用性**：流式视频分析已对新客户关闭接入，规划架构前应核实当前状态
7. **结合 S3 事件通知实现自动化分析管道**：避免应用层轮询，用事件驱动方式触发 Lambda 调用 Rekognition
8. **审核类场景仍需人工复核机制**：自动化内容审核准确率高但非 100%，关键业务场景应保留人工兜底流程
