# CIDR - 无类别域间路由

> **CIDR（Classless Inter-Domain Routing，无类别域间路由）**是用 `IP 地址/前缀长度`（如 `10.0.0.0/16`）表示一段连续 IP 地址范围的记法，是 [[VPC]]、[[Subnet]]、[[Route Table]]、[[Security Group]]、[[NACL]] 等几乎所有 AWS 网络服务进行地址规划和流量匹配的**共同语言**。看懂 CIDR 记法、算出可用地址数量、判断两个 CIDR 是否重叠，是解答几乎所有网络类场景题的前置计算能力。
>
> 相关文档：[[VPC]] | [[Subnet]] | [[Route Table]] | [[VPC Peering]] | [[Security Group]] | [[NACL]]

---

## 核心概念

### CIDR 记法结构

- 格式为 `网络地址/前缀长度`，例如 `10.0.0.0/16`——前缀长度（Prefix Length，即"掩码位数"）表示 IP 地址中**固定不变的网络位数**，剩余位数用于表示该网络内的**主机地址**
- **前缀长度越小 → 网络位越少 → 可用地址范围越大**；**前缀长度越大 → 网络位越多 → 可用地址范围越小**，这个"数字越大、范围越小"的反直觉关系是最容易搞混的地方

### 可用地址数量计算（考试高频）

- 公式：**可用地址数 = 2^(32 − 前缀长度)**（IPv4）
- 常见前缀长度对照表：

| 前缀长度 | 地址总数 | 常见用途 |
|---------|---------|---------|
| `/16` | 65,536 | VPC 允许的**最大**地址范围 |
| `/20` | 4,096 | 中等规模子网 |
| `/24` | 256 | 常见的标准子网大小 |
| `/28` | 16 | VPC/子网允许的**最小**地址范围 |
| `/32` | 1 | 单一主机地址（如安全组规则中指定单个 IP） |

> **考试要点**：题目给出"某子网需要容纳 N 台主机"时，先用公式反推所需的**最小前缀长度**，再叠加 [[Subnet]] 笔记中"每个子网 AWS 固定预留 5 个 IP"的损耗，才是该子网实际能容纳的主机数上限。

## VPC/子网的 CIDR 规则

- [[VPC]] 和 [[Subnet]] 支持的前缀长度范围一致：**`/16` 到 `/28`**（VPC 最大 65,536 个地址，最小 16 个）
- **子网 CIDR 必须是所属 VPC CIDR 的子集**，且**同一 VPC 内的子网之间不能重叠**
- 完整的子网划分规则、保留 IP、公私子网判定等详见 [[Subnet]] 独立笔记

### 二级 CIDR 块（Secondary CIDR Block，考试提示）

- VPC 创建时指定的**主 CIDR 不可修改**，但可以随时**追加二级 CIDR 块**为 VPC 扩容地址空间（常见于原有 CIDR 规划过小、后期需要扩容的场景）
- 新增的二级 CIDR **不能与已有的主 CIDR/其他二级 CIDR 重叠**
- 二级 CIDR **在其中没有资源占用地址时可以移除**，但主 CIDR 从创建起**永久不可删除**（除非删除整个 VPC）

> **考试要点**：题目描述"现有 VPC 的地址空间即将耗尽，但业务无法迁移到新 VPC" → 为该 VPC **追加二级 CIDR 块**，而非重建 VPC；这是"地址空间不足如何扩容"这类场景题的标准答案。

---

## CIDR 重叠规则（考试高频）

- **[[VPC Peering]] 明确不支持双方 CIDR 重叠**——一旦重叠，无法建立对等连接，只能重新规划其中一方的地址空间，完整限制说明见 [[VPC Peering]] 独立笔记
- **规划混合云/多 VPC 架构时应提前统一分配 CIDR**：避免不同 VPC、不同环境（开发/测试/生产）之间出现地址冲突，为未来可能的 Peering、[[Transit Gateway]] 或 VPN 互联预留兼容性
- 与本地数据中心通过 [[Virtual Private Gateway]] 建立 VPN 连接时，同样要求**双方网络的 CIDR 不重叠**，否则路由无法正确区分流量目的地

---

## 最长前缀匹配（Longest Prefix Match）

- 当一次请求的目标地址同时匹配路由表中的多条 CIDR 时，AWS **总是选择前缀长度最大（即范围最精确）**的那条路由——`/24` 比 `/16` 更精确，会被优先选中
- 这是 [[Route Table]] 路由选择的核心逻辑，而非按路由添加的先后顺序，完整机制见 [[Route Table]] 独立笔记

## 特殊 CIDR 记法（考试提示）

| CIDR | 含义 |
|------|------|
| `0.0.0.0/0` | **代表所有 IPv4 地址**，常用于默认路由（指向 IGW/NAT）或安全组规则中的"任意来源" |
| `::/0` | `0.0.0.0/0` 的 **IPv6 对应**，代表所有 IPv6 地址 |
| `x.x.x.x/32` | 仅表示**单一主机**地址，安全组/NACL 规则中限定"仅允许某一个特定 IP"时使用 |

> **考试陷阱**：**安全组/路由表中出现 `0.0.0.0/0` 不一定代表"不安全"**——它常合理地出现在**默认路由**（指向 IGW 或 NAT 网关的出口路由）中；但若出现在**安全组的入站规则**里（尤其是管理端口 22/3389），则通常是"允许任意来源访问"的**安全隐患**，需要结合上下文判断，而非看到 `0.0.0.0/0` 就一律判定为错误答案。

## 典型应用场景

| 场景 | 推荐做法 |
|------|---------|
| **规划 VPC 地址空间，预估未来子网数量** | 选择足够大的主 CIDR（如 `/16`），预留扩容空间 |
| **现有 VPC 地址空间不足** | 追加二级 CIDR 块，而非重建 VPC |
| **VPC Peering 建立失败** | 检查双方 VPC CIDR 是否存在重叠 |
| **子网需要容纳 N 台主机，如何选择掩码** | 按 `2^(32-前缀)-5` 反推最小可行前缀长度 |
| **安全组只允许单个管理员 IP 访问** | 使用 `/32` 精确指定该 IP |
| **默认路由/允许所有来源** | `0.0.0.0/0`（IPv4）或 `::/0`（IPv6） |
| **多条路由同时匹配同一目标地址** | 选择前缀长度最大（最精确）的一条 |

## 考试重点总结

### SAA-C02 高频考点

1. **前缀长度越大，可用地址范围越小**：`/28` 比 `/16` 地址数量少得多，容易被直觉误导
2. **可用地址数 = 2^(32-前缀长度)**：VPC/子网规划题的基础计算公式
3. **VPC 与子网 CIDR 范围均为 `/16` 到 `/28`**：这是 AWS 的硬性限制
4. **子网 CIDR 必须是 VPC CIDR 子集，且同 VPC 内子网不能重叠**：规划阶段需统一管理地址分配
5. **VPC 主 CIDR 不可修改，但可追加二级 CIDR 块扩容**：二级 CIDR 无资源占用时可删除，主 CIDR 不可删除
6. **VPC Peering 与 VPN 均要求双方 CIDR 不重叠**：这是最常见的连接失败排查点
7. **最长前缀匹配决定路由选择**：而非路由添加顺序，前缀越精确优先级越高
8. **`0.0.0.0/0` 代表所有 IPv4 地址，`::/0` 是其 IPv6 对应**：常见于默认路由，也可能是安全组的风险配置
9. **`/32` 表示单一主机地址**：常用于安全组白名单单个管理员 IP
10. **`0.0.0.0/0` 不能一概而论为"错误答案"**：需结合出现位置（路由表默认路由 vs 安全组入站规则）判断是否合理

### 场景题解题思路

```
场景分析 → CIDR 相关计算与判断
├── "子网需要容纳 N 台主机，选择哪个掩码" → 反推 2^(32-前缀)-5 ≥ N 的最小前缀
├── "VPC 地址空间即将耗尽" → 追加二级 CIDR 块
├── "VPC Peering/VPN 建立失败" → 检查双方 CIDR 是否重叠
├── "多条路由同时匹配目标地址，哪条生效" → 前缀长度最大（最精确）的一条
├── "安全组入站规则出现 0.0.0.0/0，是否有风险" → 结合端口判断（管理端口通常不应对所有来源开放）
├── "只允许单个管理员 IP 访问" → 使用 /32 CIDR
└── "规划多 VPC/混合云架构的地址分配" → 提前统一分配 CIDR，避免未来互联时冲突
```

## 最佳实践

1. **架构规划阶段统一分配 CIDR 地址空间**：为不同 VPC/环境预留互不重叠的地址段，避免未来 Peering/VPN 互联时被迫重新规划
2. **VPC 主 CIDR 选择时预留充足余量**：主 CIDR 创建后不可修改，规划过小会频繁依赖二级 CIDR 块打补丁
3. **子网划分时预留增长空间**：结合每子网 5 个保留 IP 的损耗提前计算，避免后期需要重建子网
4. **安全组/NACL 中避免不必要的 `0.0.0.0/0`**：管理端口应精确限定到 `/32` 的管理员 IP 或公司出口 CIDR
5. **混合云场景提前核对本地网络 CIDR**：与本地数据中心互联前确认双方地址空间不重叠，避免 VPN/[[Direct Connect]] 建立后路由错乱
6. **文档化 CIDR 分配方案**：多团队/多账户共享 VPC 架构时，集中记录各 VPC/子网的 CIDR 分配，减少沟通成本和误配置风险
